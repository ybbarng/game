# 고정 규칙 (사용자가 정한 것)

이 저장소에서 일하는 모든 세션과 서브에이전트가 **일을 시작하기 전에 읽는** 규칙이다. 사용자가 한 번 정한 것을 다시 말하게 하지 않으려고 한곳에 모은다.

- 새 규칙이 생기거나 지적을 받으면 **같은 커밋에서** 이 파일을 고친다. 규칙은 짧게, 근거(날짜·사용자 말)는 아래 「지적 기록」에 둔다.
- **여러 단계로 나눈 계획은 남은 단계를 `docs/map.json` 할 일로 적고, 보고마다 남은 단계를 짚는다.** 다른 요청에 밀려도 남은 단계가 보이는 곳에 있어야 잊히지 않는다(2026-11-10 앱 공식 연습).
- **지적을 받으면 같은 원인을 쓰는 모든 화면을 찾아 함께 고친다.** 지적받은 화면 하나만 고치면 같은 원인의 다른 화면에서 또 지적받는다(2026-11-10 「끌어 돌리면 되돌아감」이 세 번 되풀이됨).
- 저장소 `CLAUDE.md`가 이 파일을 `@docs/standing-rules.md`로 가져오므로 모든 세션과 일반 서브에이전트에게 저절로 들어간다. Explore·Plan 서브에이전트에는 secretary `subagent-rules` hook이 넣어 준다. 그래도 맡길 때 지시에 해당 절을 짚어 준다.
- 결과를 검토할 때 이 파일의 해당 절과 맞춰 본다. 기계로 잡을 수 있는 규칙은 시험으로 둔다(각 줄 끝 「점검」).

## 1. 학습 자료·튜토리얼·규칙 설명

- **처음 보는 말은 풀어 쓰거나 뜻을 먼저 알려 주고 쓴다.** 설명 없이 새 낱말을 갑자기 쓰지 않는다. 앞에서 설명한 말만 그냥 쓴다. 점검: 공통 틀 `apps/web/src/tutorial/term-order.ts`(용어마다 처음 쓴 곳 ≥ 뜻을 알린 곳, 게임 튜토리얼은 한 단계 안에서도 문장마다 `sentencePlaces`). 게임 튜토리얼은 `term-order-suite.ts`로 게임마다 `tutorial-terms.test.ts`, 큐브는 `glossary-333.test.ts`(3×3 초보자)와 `course-terms.test.ts`(중급 과정, 먼저 배우는 과정을 이어 읽음). 새 학습 자료를 만들면 같은 틀로 용어 목록을 둔다. JSX 본문도 글로 펼쳐 같은 틀로 본다: 보안 배우기 `components/learn/learn-terms.test.tsx`, 별 따기 보안 배우기 `stardraw/learn/learn-terms.test.tsx`, 큐브의 수학 `cube/math/math-terms.test.ts`, 큐브 기능 지도 `cube/nav/feature-map.test.ts`, 마이티 낱말 사전 `tutorial/glossary-terms.test.ts`. 틀에 넣지 못한 글(보안 설명, 게임 규칙 화면, 사이트 쓰는 법)은 독자 검토로 본다.
- **초보자용은 순서대로 따라만 하면 되게** 쓴다. 판단이 필요한 곳은 「이 모양이면 → 이렇게 쥐고 → 이 공식 n번」처럼 닫는다. 「될 때까지」, 「알아서」, 「잘 보고」처럼 판단을 넘기는 말을 쓰지 않는다. 점검: 큐브 초보자 `beginner-path.test.ts`(단원 규칙 자료만으로 섞기 50개를 맞춤), 2×2 두 과정 `beginner-path-222.test.ts`(같은 방식).
- **단원·단계 첫머리는 맥락부터**: 「지금까지 한 것 → 이번에 할 것 → 그래서 지금 상태」. 대뜸 「흰 십자가 맞은 큐브예요」로 시작하지 않는다.
- **서두에서 세운 개념과 어긋나게 설명하지 않는다.** 예: 큐브는 「색이 아니라 조각(블럭)을 제자리로 옮긴다」고 가르쳤으니, 색끼리 맞추는 말투(「옆 색이 옆 센터와 다를 수 있어요」)를 쓰지 않는다. 색은 조각을 알아보는 표시, 제자리를 알려 주는 센터 색으로만 쓴다.
- 전문 이름(퍼뮤, OLL 등)은 초보자 자료에서 하는 일로 부른다. 중급 자료에서 쓸 때도 처음 나올 때 뜻을 먼저 준다.
- 그 게임에 정한 낱말 문서가 있으면 먼저 읽고 따른다. 큐브: `docs/47-cube-design.md` 1절, 별 따기: `docs/41-stardraw-setting.md`.
- 글을 내보내기 전에 대화 맥락이 없는 독자(서브에이전트)에게 「처음 보는 사람」으로 읽혀, 설명 없이 처음 나온 말·어디서 이어지는지 모르겠는 곳·서두 개념과 어긋나는 곳을 뽑게 하고 고친다.

## 2. 큐브 낱말

- 조각은 **「센터 블럭」·「엣지 블럭」·「코너 블럭」**(표기 「블럭」). 조각 하나를 홀로 부르면 블럭을 붙인다(「이건 엣지 블럭이에요」, 「흰-초록 엣지 블럭」). 이어 붙는 꼴은 뺀다(「코너 방향」, 「첫 층 코너」, 「둘째 층 엣지」, 「옆 센터」). 상황·단계 이름은 꾸미는 말이 붙어도 조각 하나를 가리키므로 블럭을 붙인다(「자리에서 뒤집힌 엣지 블럭」). 자세한 것은 docs/47 1절 「(2026-11-05) 조각 이름」.
- 큰 큐브 자리 낱말은 하나에 뜻 하나: 「줄」은 두 옆면 사이 세로 엣지 자리, 줄 안의 날개 자리는 「위 자리·아래 자리」, 「칸」은 한 면의 센터 블럭 자리, 한 면 센터 블럭 둘씩은 「위 두 칸·아래 두 칸」, 날개가 붙은 덩이는 「엣지」(「한 줄로 붙어요」 아님). 큐브 낱말 전체는 docs/47 1-1 낱말표. 점검: `course-terms.test.ts` 「큰 큐브 줄·칸 낱말」.
- 여럿이 같은 섞기로 겨루는 것은 「대결」(「경주」 아님).
- 맞춘 면을 돌리는 것은 「위험한 회전」, 그 반대 면은 「안전한 회전」. 화면 글은 면 글자 대신 「맞춘 면」·「반대 면」.

## 2-1. 큐브 화면

- **끌어 돌린 보기 각도는 손을 떼도 남긴다. 처음 각도로는 단추·키로**(벗어났을 때만 뜨는 「처음 각도로」 단추, ↑ 키). 화면마다 켜지 않고 `CubeView` 기본으로 둔다. 점검: 화면 시험 `cube-keep-view`.
- **큐브를 펼친 그림(전개도)으로 보이지 않는다.** 전개도는 여섯 면을 십자(또는 펼친) 배치로 모두 보이는 그림이다. 뒤쪽은 거울 판·끌어 둘러보기로 보인다. 큐브 그림 하나를 크게 보이는 곳(모양 만들기 목표, 타이머 섞인 모습)은 내가 돌리는 큐브와 같은 3D 큐브·같은 거울 판으로 둔다. 비스듬한 큐브 그림 둘(`CubePoster`)은 3D를 못 그리는 기기와 그림이 여럿인 곳(고르는 카드·다시 보기·상대 작은 큐브)만. 점검: `cube/no-cube-net.test.ts`, 모양 만들기 목표는 화면 시험 `cube-shape.spec.ts` 「목표 그림: 거울 판을 단 3D 큐브」.
- **OLL·PLL 상황은 윗면 평면도를 함께 보인다**(윗면 + 옆면 윗줄, `AlgPicture`). 평면도는 전개도와 다른 것이고 있어야 하는 그림이다.
- **Cubie 투명 창에서 큐브는 제 실루엣을 따라 도는 테두리로 바탕과 가른다.** 큐브 크기와 맞지 않는 둥근 받침·판을 뒤에 깔지 않는다(따로 논다). 생김새를 견줄 때 바탕은 완전히 검은 #000·어두운 회색·흰색·사진 넷, 장면은 떠 있을 때·맞추는 중(거울 보임) 둘. 테두리는 흐린 빛 대신 흐림 없는 선으로 둔다(흐림은 엔진마다 진하기가 다르다). 거울 판 테두리도 큐브처럼 얇게(뒤 배경을 덜 가리게, 2026-11-12). docs/47 15-23. 점검: `cube/mini/backdrop.test.ts`, 거울 판 둘레는 `mirror.test.ts`·`CubeGeometryTests` 「판 테두리는 큐브처럼 얇다」, 화면 시험 `cube-mini.spec.ts` 「큐브 윤곽을 따라…」(받침 없음, `DESKS`에 #000).
- **Cubie 미니 화면의 생김새를 견주는 시안·README 그림은 앱과 같은 엔진 WebKit으로 찍는다**(Playwright `webkit`, 배율 2). 앱은 WKWebView라 Chromium 헤드리스로 찍은 그림만 보고 판단하면 앱에서 다르게 보일 수 있다. 점검: `apps/cubie/scripts/readme-shots.mjs`가 `webkit`으로 띄운다.
- **키 배치 「두 손」(2026-11-12)**: 글자 키는 csTimer 자리 그대로. **숫자 n = 다음 면 키 하나의 n번째 층**(남지 않음), **Shift = 같이 돌리기**(Shift + 면 키 = 바깥 두 층, 숫자 n 뒤 = 바깥 n층, 7×7 바깥 세 층 = 3 → Shift+I). T·B = M′·M, E·S는 2 + D·F 쪽 키. Alt·Ctrl은 큐브 키로 쓰지 않는다. 키를 글에 적을 때는 배치에서 읽는다(`keyTextFor`). docs/47 4-2, docs/53 10절. 점검: `keys/two-hand.test.ts`, `input/input.test.ts`.
- **수 표기와 키를 함께 적으면 한눈에 갈리게(2026-11-16)**: 수 표기는 고정폭 글자, 키는 키캡 상자(사이트 `KeyCaps`의 `<kbd>`), 한 수의 다른 키 사이는 →. 웹 화면과 Cubie 앱 말풍선(낱말 꼴 `move`·`key`) 모두. docs/47 4-4 「수 표기와 키」. 점검: `mini/key-spans.test.ts`·코어 `practice.rs` 같은 예, 화면 시험 `cube-mini.spec.ts` 공식 연습.
- **엠블럼 보석은 투명하게(뒤가 비쳐 보이게), 금속처럼 보이지 않게, 돌릴 때 끊기지 않게(2026-11-12).** 보석 안에서 나가는 빛 가운데 꿰뚫어 보는 빛은 뒤 배경을 읽는다(스튜디오 반사 지도만 읽으면 거울·금속처럼 보인다). 정면 겉 반사는 굴절률 그대로(에메랄드 약 5%, 사파이어·루비 7.7%, 다이아몬드 17%), 보석 스튜디오의 큰 빛판은 작게(면 전체를 고르게 밝히면 닦은 금속판). 몸 색은 지나온 길이만큼 흡수(큐브 전체 두께까지). 돌리는 동안 GPU가 한 장을 화면 주기 안에 못 끝내면 해상도를 낮췄다가 멈추면 제 해상도로 그린다. 셰이더는 주 스레드를 막지 않게 먼저 짓는다. 생김새는 밝은·어두운 바탕 둘, 정면·돌린 각에서 견준다. docs/47 14-7 「넷째 시안」. 점검: `emblem3d/gem.test.ts` 「겉 반사는 물리 그대로…」·「면을 정면으로 보면 빛 대부분이 뒤 배경에서 온다…」, `emblem3d/quality.test.ts`.
- **엠블럼 시안은 로컬에서 사용자 검토를 받은 뒤 push한다(2026-11-12).** 시안을 만들면 브랜치에 커밋만 하고, 사용자가 로컬 서버(HQ가 띄움)에서 보고 고른 뒤에 push·PR한다. 고를 수 있게 한 페이지에서 시안을 바꿔 볼 단추(시안 때만, 고르면 지운다. 개발용 미리보기 페이지는 2026-11-13 없앴으니 티어 화면에 시안 때만 둔다)와 비교 그림(WebKit·Chromium, 어두운·밝은 바탕, 정면·돌린 각)을 함께 준다.
- **엠블럼은 위 티어일수록 밝고 화려하게, 숫자로 확인한다(2026-11-13).** 3D 장을 어두운·밝은 바탕, 정면·돌린 각에서 재서 엠블럼 전체·큐브·장식(틀·날개·볏·왕관)의 밝기(L*)와 반짝임을 견준다. 장식은 에메랄드·다이아몬드·마스터가 한 단계(예전 그랜드마스터 틀 밝기), 그 위 그랜드마스터, 꼭대기 챌린저(사용자 지정). 큐브는 그랜드마스터 ≥ 마스터. 금속은 장식·전체 밝기가 아이언 < 브론즈 < 실버 < 골드 < 플래티넘 < 에메랄드(2026-11-16, 열 티어 모두 잰다). 값을 바꾸면 `ONLY=ladder node scripts/render-emblem-posters.mjs`로 다시 재고 표를 PR에 붙인다(사용자 지정 순서와 부딪치면 바꾸지 말고 보고). docs/47 14-7 「밝기 사다리」. 점검: `emblem3d/ladder.test.ts`(남긴 숫자가 지금 값으로 잰 것인지, 순서), 찍기 스크립트가 순서를 어기면 그림을 찍지 않고 실패.
- **티어 화면 진열(2026-11-13)**: 내 티어 엠블럼을 크게 3D로 천천히 좌우로 흔들고(끌면 따라 돌다가 놓으면 잠시 뒤 다시), 다음 티어와 줄일 시간, 열 티어 사다리(열 칸 모두 같은 중간 밝기, 위쪽 큰 칸에 보고 있는 칸만 제 밝기와 그 티어 색 3px 테두리·빛(바탕과 배경 판 둘 다 대비 3:1 이상, 위쪽 큰 칸에 뜬 티어는 언제나 이 칸, 기록이 없으면 아이언), 내 티어 칸은 구간 표의 내 줄과 같은 밝은 배경 판(가는 선 표시는 다른 빛에 묻힌다), 얻었는지로 밝기를 가르지 않는다). **동작은 누르기 하나**: 사다리 칸을 누르면(Enter·Space도) 위쪽 큰 칸이 그 티어로 바뀌고, 같은 칸·내 칸을 누르면 내 티어로. 마우스를 올리면 살짝 떠오르기만 한다. **3D는 늘 위쪽 큰 칸 하나**, 사다리 칸은 3D를 각도마다 미리 찍은 그림을 넘긴다. 사다리는 한 번에 한 칸씩 흔든다. **저절로 흔드는 동안은 해상도를 낮추지 않는다**(넘치면 그리는 횟수를 줄인다, 해상도는 사람이 끄는 동안만). 해상도·간격 단계는 무대마다 따로 두고 넉넉해지면 되돌린다. 동작 줄이기면 모두 멈추고, 화면 밖 3D는 그리지 않으며, 너무 느린 기기는 저절로 흔들기를 그만둔다. 개발용 미리보기 페이지는 두지 않는다(옛 주소는 티어 화면으로). **Cubie 앱 티어표 창도 같은 진열**(같은 글·차례·동작, 3D 대신 미리 찍은 각도별 그림을 넘긴다, 창이 안 보이면 멈춤)이고 메뉴 프로필 칸 엠블럼도 메뉴가 열린 동안 흔든다(docs/52 5-11). docs/47 14-7 「진열」. 점검: 화면 시험 `cube-emblem3d.spec.ts`(흔들기·화면 밖·동작 줄이기·누르기·마우스 올리기·3D 하나·「고른 티어의 3D는 미리 찍은 그림만큼 선명하다」 120Hz 예산 고정에서 배율 1)·`cube-tiers.spec.ts`(진열 배치·잠김·옛 주소), 단위 `quality.test.ts`(무대마다·되돌리기·흔들 때 횟수), `rank.test.ts` 「다음 티어」.

## 4. 시험과 맥 자원

- flaky 시험을 두지 않는다. 제한 시간은 `Clock` 주입(시험은 `ManualClock`), 기다리기는 조건으로.
- 화면 시험은 **nice 없이** 바꾼 spec 하나를 `--workers=1`로 돌린다(2026-11-09 사용자 결정, nice로 감싸면 자동 권한 판정에 막힌다). 전체 화면 시험은 CI가 맡는다.
- 단위 시험·빌드는 바꾼 것만(`pnpm test:changed`). 백그라운드 작업은 한 번에 하나씩.
- main 보호: PR 필수·CI 통과(`ci-ok`)·최신 main 반영 필수. main에서는 화면 시험을 다시 돌리지 않는다(main push는 빠른 검사만, 매일 한 번은 전부). docs/38 17절.
- **3D 재질에 반사 세기(`envMapIntensity`)를 따로 두지 않는다(2026-11-16).** 이 사이트의 3D 장면은 모두 장면 반사 지도(`scene.environment`)를 쓰고, 그러면 three(r169)는 재질 값 대신 장면의 `environmentIntensity`를 쓴다. 세기는 장면 값으로 바꾸고, 재질 하나만 다르게 하려면 그 재질에 `envMap`도 건다. docs/47 14-7 「반사 세기 정리」. 점검: `apps/web/src/lib/three-env-intensity.test.ts`.
- **새 CSS를 `globals.css`에 넣지 않는다.** 한 게임(또는 몇 화면)만 쓰는 규칙은 그 게임 layout이나 그 클래스를 쓰는 컴포넌트가 import하는 CSS 파일에 둔다. globals.css는 모든 화면이 쓰는 것만이고, 바뀌면 화면 시험이 전부 돈다. 큐브 화면 코드는 `cube/learn` 묶음(index) 대신 필요한 모듈을 바로 부른다. docs/38 17절. 점검: `scripts/affected-e2e.test.mjs` 「게임별 CSS」.
## 5. 기능 범위와 사이트 목적

- 기능은 따로 말하지 않아도 모든 게임에 넣는다. 새 게임은 PC·휴대폰, 여러 단계 컴퓨터가 기본(`docs/21-new-game-checklist.md`).
