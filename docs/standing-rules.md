# 고정 규칙 (사용자가 정한 것)

이 저장소에서 일하는 모든 세션과 서브에이전트가 **일을 시작하기 전에 읽는** 규칙이다. 사용자가 한 번 정한 것을 다시 말하게 하지 않으려고 한곳에 모은다.

- 새 규칙이 생기거나 지적을 받으면 **같은 커밋에서** 이 파일을 고친다. 규칙은 짧게, 근거(날짜·사용자 말)는 아래 「지적 기록」에 둔다.
- **지적을 받으면 같은 원인을 쓰는 모든 화면을 찾아 함께 고친다.** 지적받은 화면 하나만 고치면 같은 원인의 다른 화면에서 또 지적받는다(2026-11-10 「끌어 돌리면 되돌아감」이 세 번 되풀이됨).
- 저장소 `CLAUDE.md`가 이 파일을 `@docs/standing-rules.md`로 가져오므로 모든 세션과 일반 서브에이전트에게 저절로 들어간다. Explore·Plan 서브에이전트에는 secretary `subagent-rules` hook이 넣어 준다. 그래도 맡길 때 지시에 해당 절을 짚어 준다.
- 결과를 검토할 때 이 파일의 해당 절과 맞춰 본다. 기계로 잡을 수 있는 규칙은 시험으로 둔다(각 줄 끝 「점검」).

## 1. 학습 자료·튜토리얼·규칙 설명

- **처음 보는 말은 풀어 쓰거나 뜻을 먼저 알려 주고 쓴다.** 설명 없이 새 낱말을 갑자기 쓰지 않는다. 앞에서 설명한 말만 그냥 쓴다. 점검: 큐브 3×3 초보자 `glossary-333.test.ts`(용어마다 처음 쓴 곳 ≥ 뜻을 알린 곳). 다른 자료로 넓히는 중.
- **초보자용은 순서대로 따라만 하면 되게** 쓴다. 판단이 필요한 곳은 「이 모양이면 → 이렇게 쥐고 → 이 공식 n번」처럼 닫는다. 「될 때까지」, 「알아서」, 「잘 보고」처럼 판단을 넘기는 말을 쓰지 않는다. 점검: 큐브 초보자 `beginner-path.test.ts`(단원 규칙 자료만으로 섞기 50개를 맞춤).
- **단원·단계 첫머리는 맥락부터**: 「지금까지 한 것 → 이번에 할 것 → 그래서 지금 상태」. 대뜸 「흰 십자가 맞은 큐브예요」로 시작하지 않는다.
- **서두에서 세운 개념과 어긋나게 설명하지 않는다.** 예: 큐브는 「색이 아니라 조각(블럭)을 제자리로 옮긴다」고 가르쳤으니, 색끼리 맞추는 말투(「옆 색이 옆 센터와 다를 수 있어요」)를 쓰지 않는다. 색은 조각을 알아보는 표시, 제자리를 알려 주는 센터 색으로만 쓴다.
- 전문 이름(퍼뮤, OLL 등)은 초보자 자료에서 하는 일로 부른다. 중급 자료에서 쓸 때도 처음 나올 때 뜻을 먼저 준다.
- 그 게임에 정한 낱말 문서가 있으면 먼저 읽고 따른다. 큐브: `docs/47-cube-design.md` 1절, 별 따기: `docs/41-stardraw-setting.md`.
- 글을 내보내기 전에 대화 맥락이 없는 독자(서브에이전트)에게 「처음 보는 사람」으로 읽혀, 설명 없이 처음 나온 말·어디서 이어지는지 모르겠는 곳·서두 개념과 어긋나는 곳을 뽑게 하고 고친다.

## 2. 큐브 낱말

- 조각은 **「센터 블럭」·「엣지 블럭」·「코너 블럭」**(표기 「블럭」). 조각 하나를 홀로 부르면 블럭을 붙인다(「이건 엣지 블럭이에요」, 「흰-초록 엣지 블럭」). 이어 붙는 꼴은 뺀다(「코너 방향」, 「첫 층 코너」, 「둘째 층 엣지」, 「옆 센터」). 자세한 것은 docs/47 1절 「(2026-11-05) 조각 이름」.
- 여럿이 같은 섞기로 겨루는 것은 「대결」(「경주」 아님).
- 맞춘 면을 돌리는 것은 「위험한 회전」, 그 반대 면은 「안전한 회전」. 화면 글은 면 글자 대신 「맞춘 면」·「반대 면」.

## 2-1. 큐브 화면

- **끌어 돌린 보기 각도는 손을 떼도 남긴다. 처음 각도로는 단추·키로**(벗어났을 때만 뜨는 「처음 각도로」 단추, ↑ 키). 화면마다 켜지 않고 `CubeView` 기본으로 둔다. 점검: 화면 시험 `cube-keep-view`.
- **큐브를 펼친 그림(전개도)으로 보이지 않는다.** 전개도는 여섯 면을 십자(또는 펼친) 배치로 모두 보이는 그림이다. 뒤쪽은 거울 판·끌어 둘러보기, 섞인 모습·목표는 비스듬한 큐브 그림 둘(`CubePoster`)로 보인다. 점검: `cube/no-cube-net.test.ts`.
- **OLL·PLL 상황은 윗면 평면도를 함께 보인다**(윗면 + 옆면 윗줄, `AlgPicture`). 평면도는 전개도와 다른 것이고 있어야 하는 그림이다.

## 3. 화면 글

- 쉬운 한국어. 영어 음역·무거운 한자어를 피한다. 개발 표준어는 억지로 바꾸지 않는다.
- 동작 힌트·덧붙임 문구를 넣지 않는다(생김새로 알게 한다).
- 안내·감사·설명 문장은 마침표로 끝낸다. 제목·단추 이름은 예외.
- 화면 갈무리는 「스크린샷」(「스크린숏」 아님).
- 연출은 무슨 일인지 알아볼 만큼 천천히, 문구 읽을 시간을 두고, 여러 개를 동시에 움직이지 않는다.

## 4. 시험과 맥 자원

- flaky 시험을 두지 않는다. 제한 시간은 `Clock` 주입(시험은 `ManualClock`), 기다리기는 조건으로.
- 화면 시험은 **nice 없이** 바꾼 spec 하나를 `--workers=1`로 돌린다(2026-11-09 사용자 결정, nice로 감싸면 자동 권한 판정에 막힌다). 전체 화면 시험은 CI가 맡는다.
- 단위 시험·빌드는 바꾼 것만(`pnpm test:changed`). 백그라운드 작업은 한 번에 하나씩.

## 5. 기능 범위와 사이트 목적

- 기능은 따로 말하지 않아도 모든 게임에 넣는다. 새 게임은 PC·휴대폰, 여러 단계 컴퓨터가 기본(`docs/21-new-game-checklist.md`).
- 사이트 머리글은 「누구든 공정하게」. 겨루는 곳은 같은 섞기·같은 문제, 기록으로 다시 계산해 확인한다. 명예에 맡기기를 기본 답으로 내지 않는다. 서버 자원은 최소로.
- 큐브: 맥 앱 Cubie는 간단한 혼자 하기 전용(나중에 랭킹 고려), 웹은 혼자·같이 하기 모두(2026-11-10).
- 시킨 일을 「시범 + 확인」 단계로 줄이지 않는다. 찾은 빈틈·되돌리기 쉬운 선택은 바로 하고 사후에 한 줄로 알린다.

## 6. 파일 형식

- `docs/map.json`은 starship-map/1 형식을 따른다. 형식 원본은 `~/personal/projects/starship/src/protocol/map.ts`. 갈림길(`fork`) status는 `open`·`decided`만(끝났으면 `decided`와 `decided`에 정한 내용).
- 책상(`~/.local/state/secretary/desk/*.json`) 형식 원본은 `~/personal/projects/starship/docs/desk.md`.
