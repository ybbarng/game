# 42. 원카드의 "원카드!" 외치기 판정 조사 (2026-11-03)

대상: 원카드(한국식, 트럼프 52장 + 조커). docs/31(실시간 "누가 먼저인가" 판정)을 원카드에 맞춰 더 깊이 본 조사다. 코드는 바꾸지 않았다.
docs/31의 방법 번호(방법 1~10)는 그대로 가리킨다. 31을 읽었다고 보고 되풀이하지 않는다.

---

## 0. 한 줄 결론

**원카드의 실시간 다툼은 "본인 외침 대 남의 잡기" 하나뿐이고, 이것은 규칙 모양을 조금 바꾸면 속도 겨루기 없이 판정할 수 있다.**
본인 외침은 자기 차례에 카드를 낼 때 같이 누르게 하고(남은 두 장일 때 미리 누르기), 잊었을 때만 **본인 시간 P(예 1초) → 잡기 창 T(예 3초)** 를 겹치지 않게 차례로 연다.
잡는 사람이 누구든 벌칙은 같아서(외치지 않은 사람이 먹는다) 잡는 사람끼리의 순서는 판정에 쓰이지 않는다.
그래서 docs/31의 반응 시간 판정(방법 3·4·5)은 원카드 첫판에 필요 없고, 창 경계를 재는 것과 "모두가 증인"(방법 6) 정도면 된다. 반응 시간 판정은 "벨 치기"·"끼어 내기" 같은 집 규칙을 넣을 때로 미룬다.
판 도중 덱에서 여러 장 뽑기는 지금 fair-play로 된다. **덱이 바닥났을 때 버린 더미를 다시 섞는 것**은 새 섞기 사슬 하나로 할 수 있지만 지금 코드로는 바로 안 된다(한 판에 여러 번, 서로 다른 덱 조각을 잇는 판 끝 검증, 조커 두 장 번호가 새로 필요하다).

### docs/31과 같은 점·다른 점

| | docs/31 | 이 문서(원카드) |
|---|---|---|
| 판정의 바탕 | 반응 시간(자극 프레임 → `event.timeStamp`) | 같은 도구를 쓰되 **창 경계를 재는 데만** 쓴다 |
| 원카드 추천 | 본인 우선 시간 1.5초 + 그 뒤 반응 시간 경쟁, 동점은 본인 편 | 본인 시간 P와 잡기 창 T를 **겹치지 않게** 나눠 경쟁 자체를 없앤다. 본인 외침은 카드 내기와 한 동작 |
| 누가 겨루나 | 모두가 모두와 | 본인 대 "잡는 사람 아무나". 잡는 사람끼리는 겨루지 않는다 |
| 자극 | 한 장이 된 장면 | 같다. 다만 본인은 자극을 미리 알고(자기가 낸다), 남들도 "두 장 남은 사람 차례"를 보고 미리 준비한다. 순수 반응 시간 겨루기가 아니다 |
| 방장 이점 | 반응 시간으로 지운다 | 창(초 단위)이 지연(수십~수백 ms)보다 훨씬 커서 거의 사라진다. 창 끝 부근만 남는다 |
| 함께 정하는 난수 | 동점 가르기에 필요 | 원카드 첫판에는 필요 없다(동점이 판정에 영향 없음) |
| 덱 | 다루지 않음 | 판 도중 뽑기·다시 섞기를 따로 본다(4-2) |

## 1. 저장소 사실

### 1-1. docs/31 1단계가 얼마나 구현됐나 (2026-11-03, grep으로 확인)

`apps`·`packages`·`docs`에서 `resolveClaims|checkClaimBound|DelayedNetwork|MonotonicClock|stimulusId|useStimulusShown|latency.ts|jointRandom|tieRandom|rttMin`을 찾으면 docs/31 한 파일만 나온다.

| 31의 1단계 항목 | 상태 | 근거 |
|---|---|---|
| 지연 측정 `net/latency.ts`(쌍별 핑, `RTT_min`, 흔들림) | **없음** | 파일 없음. `rtc-diag.ts` `summarize`가 연결될 때 `currentRoundTripTime`을 한 번 진단으로 보낼 뿐 |
| `diag("rtt", …)` 측정 기록 | **없음** | 진단 통로(`net/diag.ts`)는 있다 |
| 반응 시간 청구(`stimulusId`, 그린 프레임 시각, `event.timeStamp`) | **없음** | 게임 화면 어디에도 `event.timeStamp`를 쓰지 않는다 |
| 승자 계산 `resolveClaims`, 경계 확인 `checkClaimBound` | **없음** | |
| 단조 시계(`MonotonicClock`) | **없음** | `fair-play/src/clock.ts`의 `realClock.now`는 아직 `Date.now()` |
| 시험용 지연 망 `DelayedNetwork` | **없음** | `net/transport.ts` `MemoryNetwork`는 `queueMicrotask`로 바로 전달 |
| 약속 뒤 공개 | **게임 시작 시드에만** | `net/fairness.ts` `commit`·`deriveSeed`(일반방 시드, `HostRoom.start`). 판 도중 사건마다 쓰는 일반 도구는 없다 |
| 함께 정하는 난수(동점용) | **없음** | 위 시드 말고는 없다 |
| 모두가 증인(청구를 모두에게 직접) | **장치는 없음, 통로는 있음** | `Transport.send(message, to?)`는 대상 없이 모두에게 보낼 수 있다. 멘탈 포커 열쇠 넘기기(`handover`)는 이미 받는 기기에게 직접 간다 |
| "아무 때나 낼 수 있는 결정" | **일부 있음** | `GameKit.offTurn`(내 차례가 아니어도 보낼 수 있는 행동, 체스 무승부 제안), `GameKit.timing`(나이롱뽕 응답 창: `callClock`, `timeout` 기록, `stamp`로 쓴 시간 싣기) |
| 중립 순서 서버 | **없음** | |
| 측정 화면(`/lab/reaction`) | **없음** | `apps/web/src/app`에 없다 |

정리: **31의 판정 장치는 아직 하나도 없다.** 원카드가 기댈 수 있는 것은 나이롱뽕이 만든 "응답 창"(`GameKit.timing` + `LocalMatch`가 재는 시간 + 기록에 남는 `timeout`)과 `offTurn`이다. 이 문서의 추천안(B)은 이 둘로 거의 만들 수 있다.

### 1-2. 나이롱뽕 응답 창에서 가져올 것 (docs/30 2절)

- 시간은 대국을 돌리는 기기(혼자 하기는 내 기기, 온라인은 방장)의 `LocalMatch`가 `Clock`으로 잰다. 다 되면 `{type:"timeout", spent}`를 기록에 남기고, 참가자는 `timeout`을 보낼 수 없다(`guestMayAct`).
- 응답에는 쓴 시간을 싣는다(`stamp`). 기록에 남으니 다시 하기·복기·판 끝 검증이 그대로 된다.
- **창이 열리는 것 자체가 정보를 흘리면 모두에게 늘 같은 창을 연다**(`everyDiscard`, 온라인 3초). 원카드는 손패 장수가 원래 공개라 이 걱정이 작다(4-1).
- 화면은 받은 `left`(그 순간 남은 시간)에서 받은 뒤 지난 시간을 빼 초읽기를 보인다. 참가자는 편도 지연만큼 짧게 본다(docs/24와 같은 한계).

### 1-3. fair-play로 판 도중 덱 다루기

| 할 일 | 지금 되나 | 어디 |
|---|---|---|
| 판 시작에 섞고 자리별로 나눠 주기 | 된다 | `FairDevice.start(deal, devices, cards)`, `assign` |
| 더미에서 한 장을 한 사람만 보게 가져오기 | 된다(나이롱뽕) | `hwatu-table.ts`의 `deck` 요청(`to: 그 기기`) → 그 기기를 뺀 모두가 열쇠 공개 |

## 2. 원카드 규칙과 "실시간이 필요한 곳"

### 2-1. 흔한 규칙(나무위키 기준)과 실시간 여부

| 규칙 | 흔한 모양 | 집마다 다른 것 | 실시간? |
|---|---|---|---|
| 내기 | 같은 무늬 또는 같은 숫자·글자 | 같은 숫자 여러 장 한꺼번에, 같은 무늬 이어지는 숫자(계단) | 아니오(자기 차례) |
| 공격 | 2 = 2장, A = 3장, ♠A = 10장(5장 변형), 흑백 조커 5~10장, 컬러 조커 7~13장. 공격끼리 더한다 | 장 수, 무엇으로 막나(같은 무늬 A, 다른 무늬 2, 조커) | 아니오(받은 사람 차례에 막거나 먹는다) |
| 7 | 무늬 바꾸기 | 7 뒤에 한 장 더 | 아니오 |
| J | 다음 사람 건너뛰기 | 2인이면 다시 나 | 아니오 |
| Q | 방향 바꾸기 | 앞 차례로 되돌리기, 2인이면 K처럼 | 아니오 |
| K | 한 장 더 | 두 사람 건너뛰기, 한 장 공격, 방향 바꿔 건너뛰기 | 아니오 |
| 마지막 한 장 | 남은 한 장이 되는 차례에 "원카드" | 공격·방어 카드로 끝낼 수 없음(기본) | — |
| **남이 먼저 외치면** | 한 장 남은 사람이 **한 장** 먹는다 | UNO는 2장 | **예** |
| **본인이 외치면** | 나무위키: 다른 사람들이 뭉치에서 **한 장씩** 먹는다 | 본인이 외쳐도 아무도 안 먹기 | **예**(위와 한 짝) |
| 외칠 수 있는 때 | 문서에 시간 제한이 없다 | 마지막 카드를 낼 때 외치기, 두 장 이상 한꺼번에 내 끝내면 생략, 외치기 없음 | **예** |
| 덱이 바닥나면 | 버린 더미 맨 위만 남기고 섞어 새 뭉치 | — | 아니오(그러나 멘탈 포커에서는 시간이 든다, 4-2) |
| 파산 | 손패 15·20·21·24장 이상 | 기준 | 아니오 |
| **벨 변형** | 뭉치 옆에 벨을 두고 민첩하게 친다(나무위키 "원카드" 문서에 언급) | 무엇에 치는지 문서에 자세하지 않다 | **예**(순수 반응 속도) |

### 2-2. 실시간 판정이 필요한 지점 전부

1. **본인 외침 대 남의 잡기**(핵심). 한 장이 된 사람이 먼저 외치면 안전(변형에 따라 남들이 먹음), 남이 먼저 외치면 본인이 먹는다.
2. **잡기 대 다음 사람의 진행.** "다음 사람이 내기 전까지"만 잡을 수 있다면 잡는 사람과 다음 사람(카드를 내는 사람)이 겨룬다. 다음 사람이 일부러 빨리 내서 친구를 살려 주는 일도 생긴다. → 고정 창으로 바꾸면 사라진다.
3. **벨 치기 변형.** 할리갈리와 같은 순수 반응 속도. docs/31 방법 3+4+5가 다 필요하다.
4. **끼어 내기(jump-in).** UNO 집 규칙: 맨 위 카드와 색·숫자가 똑같은 카드를 차례가 아닌데 낸다. UNO는 같은 카드가 두 장씩 있어 성립한다. 한국 원카드(덱 한 벌)는 똑같은 카드가 없어 "같은 숫자 끼어 내기" 같은 모양이어야 하는데, **한국 원카드에서 이런 변형을 쓴다는 출처는 찾지 못했다.** 넣는다면 여러 사람이 동시에 낼 수 있어 진짜 순서 판정이 필요하다(docs/31 C).
5. 잡는 사람끼리의 순서: **판정에 쓰이지 않는다.** 흔한 규칙에서 벌칙은 외치지 않은 사람이 먹고, 잡은 사람은 아무것도 얻지 않는다. 그래서 같은 순간 두 사람이 잡아도 결과가 같다. 잡은 사람에게 상을 주는 변형은 찾지 못했다.

### 2-3. UNO 공식 규칙과 비교

- Mattel 설명서(UNO NFL·Disney 100판): "카드가 한 장만 남은 **순간** UNO를 외쳐야 한다. 누가 먼저 외치면, **다음 사람이 차례를 시작하기 전에**, 2장을 먹는다."
- UNO Flash(전자판) 설명서는 "**끝에서 두 번째 카드를 낼 때** UNO를 외친다. 외치지 않았고 다음 사람이 차례를 시작하기 전에 들키면 2장"으로 적는다. **카드 내기와 외침을 한 순간으로 보는 표현**이라 이 문서의 A·B안(카드 낼 때 같이 외치기)과 맞는다.
- UNO Flash에는 따로 **SLAP 카드**가 있다: 내면 모두가 자기 단추를 빨리 누르고 **가장 늦은 사람**이 2장을 먹는다. 기계 한 대가 순서를 재는 "같은 방" 판정(D안과 같은 모양)이다.
- 끼어 내기는 기본 규칙에 없다. "Speed Play"라는 Mattel 판 변형이 있다는 검색 요약이 있었지만 설명서 원문은 확인하지 못했다.
- 다른 점: 원카드 기본 벌칙은 1장, UNO는 2장. 원카드 나무위키 변형에는 "본인이 외치면 남들이 한 장씩"이 있는데 UNO에는 없다. 이 변형이 있으면 본인 외침이 공격이 되어 **본인도 서두를 까닭이 생긴다**(카드 내기와 한 동작이면 상관없다).

## 3. 다른 구현은 어떻게 하나

| 사례 | 구조 | 외치기 | 잡기 | 시간 | 확인 정도 |
|---|---|---|---|---|---|

## 4. 원카드만의 기술 문제

### 4-1. 멘탈 포커와 "한 장 남음"

- **손패 장수는 공개 정보다.** 실제 놀이에서도 보이고, 화투 세 게임의 `viewOf`도 남의 손패는 장수만 보낸다. 멘탈 포커로도 장수는 공개 사건(나눠 준 자리 수, 낸 카드 열기, 더미 요청 자리 수)에서 누구나 계산한다. 방장이 장수를 속이면 판 끝 다시 계산에서 드러난다.
- 그래서 "한 장이 된 순간"은 **모두에게 같은 자극**이다. 본인은 낼 카드를 고를 때 이미 알고, 남들은 그 사람이 낸 카드가 열리는 순간 안다. 자극 시각은 기기마다 편도 지연만큼 다르다.
- 더 중요한 점: **남들도 미리 안다.** "두 장 남은 사람 차례"면 한 장이 될 것을 예상하고 손가락을 올려 둔다. 순수 반응 시간(200~300ms)보다 훨씬 짧은 반응이 정직하게 나온다. 31의 "120ms 미만 무효" 같은 사람 한계 거르기가 원카드 잡기에는 맞지 않을 수 있다(정직한 사람을 잘못 거른다). 이것도 반응 시간 경쟁을 피할 까닭이다.
- 낸 카드가 공격 카드면 끝낼 수 없다는 규칙(마지막 카드 제한)은 낼 때 카드가 열리므로 엔진이 바로 확인한다.
- "낼 수 있으면 꼭 내야 한다"를 규칙으로 두면, 멘탈 포커에서는 방장이 그 자리에서 확인하지 못한다(남의 손패를 모른다). 판 끝에 진짜 패로 다시 돌려 잡는다(하트 `renege.ts`와 같은 생각). 나무위키에 이 규칙이 분명하지 않아 "먹고 싶으면 먹어도 된다"로 두면 문제가 없다.

### 4-2. 판 도중 뽑기와 다시 섞기

**뽑기(벌칙 n장 포함)는 지금 된다.** 나이롱뽕 가져오기와 같은 `deck` 요청에 자리를 n개 실으면 된다. 한 번 주고받기라 몇 ms + 왕복 한 번이다.

**다시 섞기에 필요한 것.** 덱이 바닥나면 버린 더미(맨 위 한 장 빼고)를 섞어 새 더미로 쓴다. 이 카드들은 이미 모두가 본 카드다.
- 함께 정한 난수로 섞으면 **안 된다.** 순서를 모두 알게 되어 누가 무엇을 뽑는지 다 보인다. 반드시 섞기 사슬(각자 섞고 잠그기)을 거쳐 순서를 숨겨야 한다.
- 가장 쉬운 길: 다시 섞을 때마다 **새 기기 판 번호로 사슬을 하나 더 연다**(`start(dealId', devices, 그 카드 목록)`). 카드 목록은 모두가 아는 공개 정보라 서로 맞춰 볼 수 있다. 화투가 판 시작에 쓰는 `hwatuDealId` 방식을 판 도중으로 넓힌 것이다.
- 지금 코드에 없는 것:
  1. 한 판이 여러 기기 판(처음 덱 + 다시 섞은 덱 k개)에 걸치는 자리 표와, 판 끝 검증이 그것들을 이어 진짜 패로 다시 돌리는 일(`checkHwatuReplay`는 판마다 덱 하나를 가정)
  2. 이미 있는 `reshuffle(pool)`은 숨은 자리를 다시 섞는 6·7마용이고 한 번뿐이라 맞지 않는다
  3. 조커 두 장 번호(1-3절)와 원카드용 표(`HwatuFairSpec`처럼 게임 모양을 받는 것)
  4. "다시 섞는 중"을 모두에게 보이고, 그동안 뽑아야 하는 사람만 기다리게 하는 화면
- **걸리는 시간(추정).** 계산은 작다. ristretto255 잠그기 한 번이 이 맥에서 0.088ms(docs/13)라 40장을 섞고 다시 잠가도 기기 하나에 수 ms~십수 ms, 휴대폰이 3~5배 느려도 수십 ms다. 시간을 정하는 것은 **차례로 건네는 횟수**다. 섞기와 다시 잠그기 두 단계가 기기 수만큼 차례로 돌아 4명이면 8번 건넌다. 편도 20~75ms면 0.2~0.6초, 그 뒤 뽑을 카드 열쇠 공개에 왕복 한 번. 중계(TURN)면 몇 초가 될 수 있다. 참고로 화투 48장 섞고 나누기는 여러 탭 시험에서 0.35~0.86초였다(docs/27 3-6). **폰으로 재지 않았다.**
- **섞기 증명은 기다리지 않는다.** 섞은 결과를 이미 공개한 뒤라 증명은 뒤에서 오간다. 카드가 이미 열려 있는 경우는 바로 만든다(docs/15 "보내는 때"). 한 사람 몫 증명이 이 맥에서 1초 안팎이라 폰은 몇 초 걸릴 수 있지만 게임은 멈추지 않는다.
- **멈추는가**: 다시 섞는 동안 뽑아야 하는 사람만 기다린다(1초 안팎, 추정). 미리 섞어 두면(더미가 몇 장 안 남았을 때 그때까지의 버린 더미를 섞어 남은 더미 밑에 붙임) 기다림이 없어지지만, 그 뒤 버린 카드가 다음 섞기까지 빠져 실제 규칙과 아주 조금 달라진다. 첫판은 "바닥나면 섞기"로 두고 시간을 잰 뒤 정한다.
- 공격이 쌓이면(♠A 10장 + 조커 등) 한 번에 수십 장을 먹다가 중간에 덱이 바닥날 수 있다. 엔진은 "몇 장 먹고 → 다시 섞기 → 나머지 먹기"를 한 걸음 안에서 나눠 처리해야 한다. 버린 더미도 모자라면(카드가 거의 다 손에 있음) 먹을 수 있는 만큼만 먹는 기본값이 필요하다.

### 4-3. 본인 외침을 카드 내기와 한 동작으로

- 화면: "원카드!" 단추는 **판 내내 늘 같은 모습으로** 있다(5-B "늘 있는 단추"). 내 차례에 손패가 두 장일 때 누르면 켜진 상태가 되고, 그다음 카드를 내면 **낸 행동에 외침이 함께 실린다**(`{type:"play", card, call: true}`). letsuno의 "두 장일 때 미리 외치기"와 같다. 세 장 이상을 한꺼번에 내 한 장이 되는 변형도 같은 방식이다.
- **두 장이 됐다고 단추를 띄우거나 반짝이게 하면 안 된다.** 단추가 "지금 외칠 때"를 알려 주면 아무도 잊지 않고, 원카드의 재미("깜빡하기·알아채기")가 사라진다(2026-11-03 사용자 지적).
- 그러면 본인 쪽은 **실시간이 아니다.** 자기 차례 행동이라 순서가 이미 정해져 있다. 방장 이점·지연·시계 차이가 끼어들 틈이 없다.
- 단추를 미리 눌러야 하므로 잊을 수 있다. 원카드의 재미("깜빡한 사람 잡기")는 그대로 남는다.
- 자동 누르기 프로그램이 할 수 있는 일은 "단추를 늘 누르기"뿐이고, 이건 정직한 사람도 손 하나로 하는 일이다. 즉 **부정할 거리가 사라진다.**
- 남는 것: (1) 잊은 사람이 바로 알아차리고 늦게 외치는 것을 받아 줄지(본인 시간 P), (2) 남이 잡을 수 있는 시간(잡기 창 T). 둘을 겹치지 않게 두면 경쟁이 없다(B안).

## 5. 선택지

### A. 규칙을 바꿔 실시간을 없애기

- **A1. 함께 외치기 + 잊으면 자동 벌칙.** 카드를 낼 때 외치지 않고 한 장이 되면, 다음 사람 차례가 시작될 때 엔진이 바로 벌칙(1장)을 준다. 잡는 사람이 없다. 전자 UNO 기계 중에 "연출이 끝날 때까지 UNO 단추를 안 누르면 4장"인 것이 있다는 검색 요약이 있었지만 설명서 원문은 확인하지 못했다.
- **A2. 자동 외치기.** 한 장이 되면 엔진이 대신 외친다. 외침 규칙이 사라진 것과 같다(나무위키 "외치지 않기" 변형, letsuno "조용한 UNO").
- **A3. 외치기 없음.** A2와 같고 "원카드" 소리·연출만 남기거나 뺀다.

### B. 늘 있는 단추 + 겹치지 않는 시간 (추천, 2026-11-03 고침)

**원칙: 화면이 판 상태를 대신 알아채 주지 않는다.** 처음 초안은 "두 장이면 원카드 단추가 뜨고, 외치지 않은 사람 자리에 잡기 표시가 뜬다(Mattel163처럼)"였다. 그러면 단추가 켜지는 것 자체가 신호라 모두 바로 누르고, 잊는 사람도 알아채는 사람도 없어진다(사용자 지적). 그래서 아래처럼 바꾼다.

1. **단추는 하나, 늘 같은 모습.** 판 내내 모두에게 "원카드!" 단추 하나가 보이고, 누가 몇 장이든 모양·위치·눌림 가능 여부가 바뀌지 않는다. 오프라인에서 누구나 언제든 "원카드!"를 외칠 수 있는 것과 같다.
2. **누른 뜻은 엔진이 가린다.** 누르면 `{type:"shout", seen: 판 번호}`를 보낸다. `seen`은 누른 사람 화면에 그려져 있던 판의 번호다.
   - 내 차례이고 내 손패가 두 장 → 미리 외침(다음에 내는 카드에 실림, 4-3)
   - 내가 한 장이고 아직 안 외침 → 본인 외침(본인 시간 P 안이면 안전)
   - `seen` 판에서 외치지 않은 한 장짜리 남이 있고 잡을 수 있는 때 → 잡기
   - 그 밖 → **헛외침, 벌칙 1장**
3. **헛외침 벌칙이 마구 누르기를 막는다.** 이것이 없으면 "늘 있는 단추"도 연타 한 번으로 무너진다. 판정을 `seen` 판 기준으로 하므로, 지연 때문에 한 판 늦게 보고 정직하게 누른 사람은 헛외침이 되지 않는다(쏜 사람 기준 판정, 31 방법 3의 생각을 판 번호로).
4. **본인 시간 P**(예 1초): 외치지 않고 한 장이 되면 P 동안은 본인 외침이 이긴다. P 안에 온 남의 누름은 헛외침도 잡기도 아니다(본인이 P 안에 외치면 그냥 지나가고, 끝내 안 외치면 P가 끝나는 순간 잡기로 처리). 남들은 알아챈 즉시 눌러도 손해가 없고, 본인은 깜빡해도 1초 안에 정신 차리면 산다.
5. **잡을 수 있는 때**: P가 끝난 뒤 잡기 창 T 동안(갈림길 3). 그 사람 손패가 바뀌면(먹거나 마지막 카드를 냄) 일찍 닫힌다.
6. **외침이 보이는 방식**: 외치면 소리와 말풍선이 잠깐(예 1.5초) 뜨고 사라진다. 오프라인에서 외침을 "듣는" 것과 같다. **"외치지 않음" 표시나 "한 장 남음" 강조는 두지 않는다.** 손패 장수는 평소처럼 카드 뒷면으로만 보인다. 누가 한 장인데 안 외쳤는지는 사람이 보고 기억해야 한다.
7. 시간은 방장 `LocalMatch`가 `Clock`으로 잰다(나이롱뽕 응답 창과 같다). 창 끝 부근 참가자를 위해 여유 시간(예 0.3초)을 둔다. 잡기·외침 청구는 모두에게 직접 보낸다(31 방법 6).
8. 컴퓨터는 단계별 확률과 지연으로 외치고 잡는다(letsuno 값 참고: 중수 50%·1~3초, 고수 90%·0.5~2초). 입문 컴퓨터는 가끔 헛외침도 한다.

B는 본인과 잡는 사람의 시간이 겹치지 않아 **판정이 "어느 시간 안에, 어느 판을 보고 눌렀나"만 본다.** 잡는 사람끼리는 결과가 같아 겨루지 않는다. 31이 원카드에 추천한 "본인 우선 시간 + 경쟁"에서 경쟁 부분을 뺐고, 잡는 재미는 단추가 아니라 사람의 알아챔에 남긴다.

### C. docs/31 방식 반응 시간 경쟁

본인 우선 시간 P 뒤에도 본인 외침을 받고, 본인 외침과 잡기가 둘 다 오면 각 기기가 잰 반응 시간으로 가른다. 동점(창 X 안)은 본인 편. 31 1단계(지연 측정, 반응 시간 청구, `resolveClaims`, 경계 확인, 모두가 증인)가 모두 필요하다. 원카드에서는 남들이 미리 준비하므로(4-1) 사람 한계 기준을 다시 정해야 한다.

### D. 방장 도착 순서 그대로

방장 엔진이 받은 순서로 처리한다. 같은 와이파이에서 모여 할 때는 왕복 수 ms라 거의 공정하다. 다른 망이면 참가자가 RTT만큼 손해. 화면에 "방장 판정"이라고 밝힌다. 벨 변형을 같은 방에서만 시험할 때 쓸 수 있다.

### E. 중립 순서 서버

신호 서버에 방별 순서 매기기를 더한다(31 방법 8). 원카드 첫판에는 지킬 것이 "창 경계" 정도라 서버를 둘 이득이 작다. 막힌 망 대체 통로가 필요해질 때 함께 본다.

## 8. 추천과 단계

### 1단계: 처음 만들 것

1. **원카드 엔진**: 행동 기록 + `viewOf`(남의 손패는 장수만). 낸 행동에 `call` 싣기, 본인 시간 P·잡기 창 T 상태와 `timeout`, 잡기 행동(`offTurn`으로 차례가 아니어도 보냄), 잡기·외침 판정은 순수 함수. 덱이 바닥나면 다시 섞기 사건, 먹는 도중 바닥나면 나눠 처리.
2. **B안**: 시간은 `GameKit.timing`(나이롱뽕처럼)으로 방장 `LocalMatch`가 잰다. 잡기 청구는 모두에게 직접 보내고, 방장 발표와 다르면 표시한다(31 방법 6의 최소판).
3. **암호화방**: 원카드용 카드 표(조커 두 장 번호 추가, 52+2장), 판 도중 뽑기(`deck` 요청에 자리 n개), **다시 섞기 = 새 기기 판 번호로 사슬 하나 더**, 판 끝 검증이 여러 덱 조각을 잇게. 일반방(방장 시드)은 이것 없이 먼저 낼 수 있다.
4. **컴퓨터**: 외침 확률·잡기 확률·잡기 지연을 단계별로(letsuno 값을 출발점으로).
5. 시험: 엔진·판정 순수 함수 표 시험, `ManualClock`으로 P·T 경계(창 끝 직전·직후, 여유 안·밖), 다시 섞기 온라인 방 하나.

### 2단계: 측정할 것

- 실제 폰 3~5대로 **다시 섞기 시간**(직접 연결·중계) → 미리 섞기를 할지 정한다.
- 잡기 창 T와 본인 시간 P의 체감(너무 길어 김빠지나, 너무 짧아 억울한가). 판마다 "잊음 → 잡힘/무사" 비율을 내 기록에 남겨 본다.
- 참가자가 본 남은 창과 방장 창의 차이(왕복 시간). `diag`로 모은다. 31 9절 측정 계획의 망 측정 부분을 여기서 같이 시작할 수 있다.

### 3단계: 나중에

- 벨 치기·끼어 내기 변형은 31 1단계(반응 시간 판정)를 만든 뒤 옵션으로.
- 잡기 청구 경과 시간에 31 방법 4 경계 확인 더하기(창 끝 다툼이 실제로 생기면).
- 중립 순서 서버는 막힌 망 대체 통로가 필요해질 때.

## 10. 불확실한 점

- 한국 원카드의 "외칠 수 있는 때"와 "본인 외침 보상"은 나무위키 한 출처에 기대고 있다. 다른 한국어 출처(블로그·앱 도움말)를 찾지 못했다.
- 한게임·큐플레이·넷마블 원카드가 외치기를 어떻게 처리하는지 확인하지 못했다.
- Mattel163 UNO! 앱의 잡기 창 길이, 잡기를 누가 먼저 했는지 가르는 방식은 공개 자료에서 찾지 못했다.
- letsuno에서 "다음 사람이 내면 더는 못 잡는다"를 다른 곳에서 막는지 확인하지 못했다(살펴본 엔진 함수에는 없었다).
- 전자 UNO 기계의 "연출 끝까지 안 누르면 4장" 규칙, Mattel "Speed Play" 끼어 내기 변형은 검색 요약만 보고 설명서 원문은 확인하지 못했다.
- 다시 섞기 시간(4-2)은 이 맥 계산값과 화투 여러 탭 시험에서 짐작한 것이다. 폰·중계에서 재지 않았다.
- 미리 준비한 사람의 잡기 반응 시간 분포는 모른다(C안을 고를 때만 중요).
