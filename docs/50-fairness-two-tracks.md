# 50. 공정성의 두 결: 증명하는 판정과 고르게 하는 통신 (2026-11-04, 가이드)

게임 센터의 공정성 장치를 두 결로 나눈다. 사용자 제안(2026-11-04)을 onecard 세션이 정리했다. game 세션 리뷰 전 초안이다.

- **1결: 증명한다.** 결과를 누가 봐도 다시 계산해 확인할 수 있고, 방장·서버도 속이지 못한다. 대신 느려도 된다.
- **2결: 고르게 한다.** 서버 자원을 거의 쓰지 않고, 정직한 사람끼리 누구도 일방적으로 빠르지 않게, 끊기지 않게 한다. 증명은 하지 않는다.
- **빠른 실시간 판정은 2결에 둔다.** 1결로 끌어오려는 시도(반응 시간 증명)는 하지 않는다. 까닭은 2절.
- **결은 게임이 아니라 판정 하나하나에 붙인다.** 한 게임 안에 두 결이 함께 있을 수 있다(원카드: 패는 1결, 누가 빨랐나는 2결).

---

## 1. 두 결

| | 1결: 증명한다 | 2결: 고르게 한다 |
|---|---|---|
| 약속 | 방장·서버·다른 사람 누구도 결과를 몰래 바꾸지 못한다. 판 끝에 모두가 다시 계산한다 | 정직한 사람끼리는 망·기기 차이 때문에 누가 일방적으로 이기지 않는다. 끊겨도 이어진다 |
| 믿는 것 | 수학(암호, 해시, 서명)과 모두의 다시 계산 | 각 기기가 정직하게 잰다는 것. 속임은 막지 않고 이득을 묶는다 |
| 속도 | 느려도 된다(섞기 증명 몇 초, drand 회차 기다리기) | 빨라야 한다(수십~수백 ms) |
| 속였을 때 | 드러난다(판 끝 다시 계산이 어긋남 → 사건) | 드러나지 않을 수 있다. 이득에 상한이 있다 |
| 서버 | 쓰더라도 믿지 않는다(장부는 공개, 결과는 drand 등 바깥 난수) | 거의 쓰지 않는다(연결 신호, 직접 연결이 안 될 때 TURN 중계) |
| 지금 장치 | 멘탈 포커(docs/13), 섞기 증명(15), 약속 후 공개, 해시 사슬, 함께 뽑기(joint-random), drand·공개 장부(36), 본 판 번호 판정(43 1층) | 각 기기 반응 시간(43 2층), 도착 하한 깎기, 보정 상한 C, 사람 하한 동점 구역, 개인 시간·대신 두기 시계, 재연결 |

### 1-1. 왜 빠른 판정은 증명할 수 없나

남이 잴 수 있는 것은 "내 청구가 늦게 도착했다"뿐이고, "내가 빨리 반응했다"는 내 기기만 안다. 앱을 고친 사람은 **망이 느린 척**(핑 답만 늦추기)을 할 수 있는데, 이것은 진짜로 느린 망과 구별되지 않는다. 반대로 빠른 척은 못 한다(남이 잰 왕복이 실제보다 짧을 수 없다).

그래서 손잡이는 하나다. 망 지연을 보정해 주면 느린 척이 이득을 보고, 보정하지 않으면 정직하게 느린 사람이 진다. 서버를 두어도 같다. 서버도 사람 몸의 반응 시각은 모른다. 큰 게임들도 같은 손잡이를 쓴다(총 쏘는 게임의 되감기 상한, 격투 게임 되감기 넷코드의 창). 증명 대신 **상한으로 묶고, 걸리면 기록**한다.

## 2. 규칙: 판정마다 결을 정한다

새 게임이나 새 판정을 만들 때 판정마다 하나씩 적는다.

1. 이 판정이 틀리면 누가 무엇을 잃나(패가 새어 나감, 점수, 한 판 벌칙 1장)
2. 판정에 쓰는 값을 남이 다시 계산할 수 있나(있으면 1결)
3. 사람의 반응 시각이나 기기 시계에 기대나(그러면 2결)
4. 2결이면 속인 사람의 이득 상한은 얼마이고, 그 상한이 판정을 뒤집을 만큼 큰가(docs/43 1-3)

섞지 않는다: 1결 판정에 2결 값을 넣으면(예: 반응 시간으로 패를 나눔) 1결 약속이 2결 수준으로 떨어진다. 반대로 2결 판정에 1결 장치를 억지로 끼우지 않는다(예: 반응 시각을 증명하려는 시도). 비용만 들고 약속은 그대로다.

## 3. 지금 게임의 판정별 결

| 게임 | 1결 판정 | 2결 판정 |
|---|---|---|
| 마이티·하트·고스톱·민화투·나이롱뽕 | 패·섞기(멘탈 포커), 판 끝 다시 계산 | 차례 제한 시간·대신 두기(방장 시계) |
| 오목·장기·체스·바둑 | 수(숨은 정보 없음, 모두 같은 기록을 다시 계산) | 개인 시간·초읽기(docs/24, 방장 시계) |
| 숫자야구 | 정답(약속 후 공개) | 맞힐 차례 개인 시간 |
| 윷놀이 | 던지기(해시 사슬) | 던지기·움직이기 개인 시간 |
| 은하 한 바퀴 | 주사위·공문(해시 사슬), 봉인 입찰(약속 후 공개) | 결정마다 20초 |
| 큐브 맞추기 대결 | 섞기(약속 후 공개, 모두 같은 섞기) | 걸린 시간(각 기기에서 잼, 도착 하한, docs/46 3-2) |
| 원카드 | 패·섞기·판 도중 다시 섞기 사슬, 누른 사람이 본 판 번호(1층) | 누가 더 빨랐나(2층: 각 기기 반응 시간, 하한 깎기, 상한 C, 100ms 아래 동점·본인 우선) |
| 하늘의 별 따기 | 추첨(drand, 공개 장부) | 해당 없음 |
| 행사용 게임(docs/49, 설계) | 결과(봉인 → drand), 판 지문 | 봉인 전에 들어왔나(각 휴대폰이 증인) |

드러난 것: **시간 제한은 거의 모든 게임에 있는 2결 판정이다.** 지금은 방장 시계로 재므로 방장이 남의 시간을 일찍 끊을 수 있다. 피해는 한 수 대신 두기 정도라 작지만, 2결 약속(정직하면 고르게)에 맞는지 4절 기준으로 다시 본다.

## 4. 2결이 할 일

목표는 "속임 막기"가 아니라 **정직한 사람끼리 고르고, 끊기지 않게**다.

1. **방장 이점 없애기.** 방장 기기는 자기와의 지연이 0이다. 먼저 도착한 순서로 가르는 판정은 모두 방장에게 기운다. 반응 시간은 각 기기에서 잰다(원카드 2층).
2. **지연 고르게 하기.** 모두가 같은 판을 비슷한 순간에 보게 한다. 남은 일: 방장 화면에 판을 보여 주는 때를 손님 편도만큼 늦출지(정직한 방장이 일방적으로 먼저 보지 않게) 검토.
3. **끊김 견디기.** 재연결(지금 있음), 방장이 나가면 다른 사람이 이어받기(아직 없음, docs/06), 직접 연결이 안 되는 망을 위한 TURN 중계(지금 있음, `net/turn.ts`, 못 받으면 TURN 없이 잇는다). TURN은 서버 자원이 드는 유일한 길이라, 직접 연결이 될 때는 쓰지 않는다는 지금 방식을 2결의 기준으로 적어 둔다.
4. **속임 대책은 지금 만큼에서 멈춘다.** 도착 하한 깎기, 보정 상한 C(150ms), 사람 하한 100ms 동점 구역, 동점은 본인 우선. 싸고 이미 만든 것이라 남겨 두고, 더 파고들지 않는다. 남는 빈틈(방장이 특정 사람에게 판을 늦게 보내기, C 안에서 느린 척, 기기 터치 지연 차이)은 문서와 보안 설명 화면에 밝힌다.
5. **판정 값은 방 안에서 정한다.** 서버·진단 기록(/diag)으로 보내지 않고, getStats는 증거로 쓰지 않는다(docs/43 0-1).

## 5. 사람에게 말하는 법

- 규칙·보안 설명 화면에서 판정마다 어느 결인지 적는다. 1결은 "누구도 몰래 바꿀 수 없어요, 판 끝에 모두의 기기가 다시 계산해요", 2결은 "정직하게 하면 망이 느려도 손해 보지 않아요. 앱을 고쳐 속이면 조금(최대 ○ms) 이득을 볼 수 있어요".
- 대국 화면에 한계를 덧붙이는 글은 넣지 않는다(저장소 규칙). 방 띠(FairLine)는 지금처럼 1결 장치(암호화방·일반방)를 말한다.

## 6. 새 게임 체크리스트에 더할 것(docs/21, 리뷰 뒤)

- 기획 단계에 "판정별 결" 표(3절 모양)를 쓴다.
- 2결 판정은 속인 사람의 이득 상한과, 그 상한이 판정을 뒤집는지 적는다.

## 7. 리뷰에서 정할 것

1. 두 결로 나누는 것 자체, 그리고 "판정마다 붙인다"는 규칙
2. 2결에서 속임 대책을 지금 만큼에서 멈추는 것(더 할 것, 뺄 것)
3. 시간 제한(방장 시계)을 2결로 보고 그대로 둘지, 손님 시계 확인을 더할지
4. 4절 2·3번(방장 화면 늦추기, 방장 이어받기)의 순서
5. 행사용 게임(docs/49)의 중계 서버가 2결의 "서버 거의 안 씀"과 맞는지(1:n 게시판은 1결 쪽 장치로 보는 것이 맞는지)
