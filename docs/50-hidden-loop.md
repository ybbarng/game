# 50-틀. 숨은 편 게임을 다듬는 틀: 대국 → 흠 → 고침 → 다시 대국 (2026-11-04)

[docs/50-hidden-ideas.md](./50-hidden-ideas.md)의 상위 10개를 서브에이전트끼리 실제로 두게 했더니, 기획 점수(86~94)와 달리 대국 평균은 57~72점이었다. 다섯 판은 기획한 길이의 절반도 못 가서 끝났다. 사용자 말:

> 「게임이 2바퀴 만에 끝난 거면 완성도가 낮은 게임이야. 개선점을 합리적으로 적용하고 다시 게임을 돌려줘.」
> 「지금 계속 게임을 수정하는 메타데이터를 잘 모아서, 궁극적으로 완성도 높은 게임을 다양하게 만들 수 있는 틀을 만들자.」

이 문서가 그 틀이다. 재미 기준(무엇을 노리나, 점수표, 설계 점검표, 대국에서 잴 값)은 [docs/50-fun-criteria.md](./50-fun-criteria.md)에 따로 있다. 3판부터는 그 점검표를 먼저 채우고 고친다. 이 문서는 네 부분으로 되어 있다.

1. **흐름**: 기획 → 빈칸 점검 → 대국 → 보고서 → 흠 나누기 → 고친 판 → 다시 대국 → 관문(2절)
2. **기록 형식**: 대국마다 보고서 하나 + `log.jsonl` 한 줄, 고친 판마다 기획 문서의 「n판」 단락(3절)
3. **흠 목록**: 여러 게임에서 되풀이되는 설계 흠과 표준 고침(4절). 새 게임 기획 때 체크리스트로 쓴다
4. **진행자 지시 틀**: 대국을 돌리는 서브에이전트에게 주는 글(5절)

---

## 1. 흐름

```
기획(docs/50-hidden-ideas.md 4절)
  → 빈칸 점검(4절 흠 목록을 체크리스트로: 특히 H1·H2·H5·H7·H14)
  → 대국 n판(진행자 1 + 플레이어 따로, 5절 지시 틀)
  → 보고서(docs/50-playtests/playtest-<번호><판>-<게임>.md) + log.jsonl 한 줄
  → 흠 나누기(4절 번호를 붙인다. 새 흠이면 목록에 더한다)
  → 고친 판((n+1)판 단락을 기획 문서 해당 절 끝에. 고친 것마다 흠 번호를 단다)
  → 다시 대국 …
  → 관문(2절)을 넘으면 「완성 후보」 → 사람 시험 → 구현
```

- **한 번에 고치는 양**: 흠마다 표준 고침(4절)을 먼저 쓴다. 한 판에 고침 2~7개. 너무 많이 바꾸면 무엇이 효과였는지 모른다.
- **판 수**: 같은 규칙판을 시드만 바꿔 여러 판 두면 우연을 걸러 낸다. 관문 G7(균형)은 3판 이상이 있어야 본다.
- **진행자가 혼자 둔 판은 관문에 세지 않는다**(G1). 흠 찾기에는 쓴다.

## 2. 관문: 완성 후보가 되려면

| 관문 | 기준 | 까닭 |
|---|---|---|
| G1 따로 둔 판 | 플레이어를 모두 따로 띄운 판만 센다 | 숨은 정보가 실제로 숨었을 때만 의미가 있다 |
| G2 판 길이 | 실제 차례 ≥ 예정의 60%, 결판 전에 드러나는 순간 2번 이상 | 2바퀴 만에 끝나면 미완성이다(사용자) |
| G3 핵심 장치 | 기획서가 「재미의 중심」으로 든 행동이 한 판에 인원 수 이상 쓰이고, 그 가운데 하나 이상이 결과를 바꾼다 | 1차에서 종 치기·탈 바꾸기·흥정이 0번이었다 |
| G4 모든 자리 | 모든 역할이 판 동안 자기만의 결정을 2번 이상 한다 | 밀정·어둑시니·무당 손녀·먼 자리가 구경꾼이 됐다 |
| G5 점수 | 평균 75점 이상, 진 편 평균 65점 이상 | 진 사람도 재밌어야 다시 한다 |
| G6 열린 흠 | 4절의 「심함」 흠이 남아 있지 않다 | |
| G7 균형 | 따로 둔 판 3판 이상에서 한 편이 모두 이기지 않는다 | 시작 배치가 결과를 정하는 흠(H8)을 거른다 |

- AI 대국 점수는 사람 재미를 대신하지 못한다. 그래서 관문은 점수(G5) 하나가 아니라 **판의 모양**(G2·G3·G4)을 먼저 본다. 이것은 AI 판에서도 믿을 만하다.

## 3. 기록 형식

### 3-1. 보고서(사람이 읽는 것)

`docs/50-playtests/playtest-<게임 번호><판 글자>-<게임 영문>.md`. 판 글자는 1판 대국이 a(옛 파일은 글자 없이), 2판이 b, …

맨 위에 띄운 방식·결과·바퀴·차례·호출 수, 그다음 판 요약, 판정 기록, 플레이어 평가(재밌었던 점·개선점·총점), 진행자 평가, 앞 판 대비, 개선 제안, 평균 점수.

### 3-2. `docs/50-playtests/log.jsonl`(기계가 읽는 것)

대국 한 판에 한 줄. 판이 끝나면 정리하는 세션이 더한다.

```json
{"id":"01a","game":"paru","name":"파루 종","rules":1,"players":6,"spawned":6,
 "date":"2026-11-04","winner":"도적 편","end":"차례 상한","rounds":4,"turns":24,"plannedTurns":24,
 "avg":62.7,"loserAvg":null,"coreUse":{"종 치기 합":3},"flaws":["H1","H2"],"report":"playtest-01-paru.md"}
```

| 칸 | 뜻 |
|---|---|
| `id` | 게임 번호 + 판 글자(01a, 01b …). 한 규칙판에서 여러 판을 두면 01b1, 01b2 |
| `rules` | 규칙판 번호. 기획 문서 해당 절의 「n판」 단락과 같다 |
| `spawned` | 따로 띄운 플레이어 수. `players`보다 작으면 G1에서 뺀다 |
| `end` | 판이 끝난 까닭(선언, 상한, 목표 도달 …) |
| `turns`·`plannedTurns` | G2 판 길이 |
| `coreUse` | 핵심 장치가 몇 번 쓰였나(G3) |
| `loserAvg` | 진 편 평균(G5). 보고서에 없으면 null |
| `flaws` | 이 판에서 드러난 흠 번호(4절) |

### 3-3. 고친 판(규칙의 이력)

기획 문서의 게임 절 끝에 「**n판(대국 m차 뒤 고침, 날짜)**」 단락을 더한다. 앞 판의 결과 한 줄, 드러난 흠, 고친 규칙을 적는다. 앞 판 글은 지우지 않는다(무엇이 왜 바뀌었는지 남긴다). 진행자는 「가장 마지막 n판 단락이 앞 규칙보다 앞선다」로 읽는다.

## 4. 흠 목록과 표준 고침

1차 대국 여덟 판에서 나온 흠을 게임과 상관없는 모양으로 묶었다. 새 게임을 기획할 때 이 목록을 하나씩 짚어 보면 대국 전에 많은 흠을 막을 수 있다.

| 번호 | 흠 | 증상(어느 판에서) | 표준 고침 | 심함 |
|---|---|---|---|---|
| H1 | **쥔 사람이 내줄 것을 고른다** | 숨은 물건이 쥔 사람 뜻으로만 움직여 빼앗을 수 없다(파루 종 인장, 구미호 구슬) | 가져가는 쪽이 엎은 채 무작위로 뽑는다. 본 장이 있으면 지목한다 | 심함 |
| H2 | **기다리는 편이 이긴다** | 시간이 다 되면 이기는 편은 끝을 당길 까닭이 없다(파루 종: 아무도 종을 안 침). 맞히는 쪽은 끝까지 미루는 게 늘 낫다(발자국) | 시간 끝 승자를 「끝을 미루고 싶은 편」의 반대로. 기다리는 편에게 상대의 시계(곳간 장물 같은 목표)를 준다 | 심함 |
| H3 | **행동 자체가 고백** | 한 편만 득을 보는 행동을 하면 바로 들킨다(아홉 꼬리: 굿을 청한 사람이 구미호, 발자국: 「도적 무늬를 지웠다」 기록) | 그 행동을 정해진 때 저절로 일어나게. 행동한 사람을 숨기거나, 양편 모두 쓸 까닭을 준다 | 심함 |
| H4 | **확정 정보 카드** | 역할을 바로 보여 주는 카드가 추리를 대신한다(발자국 등불 11번) | 표본 정보(주머니 하나, 「있음/없음」), 장 수·횟수 줄이기 | 중간 |
| H5 | **늘 안전한 선택** | 위험 없는 선택이 있으면 정보가 나오지 않는다(탈 바꾸기 「받고 시늉」, 구슬 「빈 손만 주기」) | 받는 쪽의 선택을 없앤다. 안전한 선택에 값을 매긴다 | 심함 |
| H6 | **모름이 사라지는 엿보기** | 엿본 뒤 남는 모름이 없어 핵심 장치가 꺼진다(늦은 항로) | 지연을 늘려 엿봐도 한 장은 모르게. 엿보기 값을 공개로 치르게 | 심함 |
| H7 | **문턱이 너무 낮거나 닿을 수 없다** | 이기는 문턱이 한두 수로 채워지거나(항로 두 번 멈춤), 손 크기로는 닿지 않는다(꼬리 목표 7, 손 3장) | 문턱을 손 크기·행동 수·바퀴 수로 계산해 「가장 빠른 승리 ≥ 예정의 절반」인지 확인 | 심함 |
| H8 | **시작 배치가 결과를 정한다** | 숨긴 카드·거리·주머니 운이 승패를 정한다(탈 바꾸기 3:2, 항로 거리, 발자국 주머니) | 판 도중 배치를 바꿀 수단(장터 뒤 탈). 대칭 배치. 작은 편 보정 | 중간 |
| H9 | **결말을 운이 정한다** | 마지막 수보다 무작위 값이 크다(야간 당직 별 바람) | 셀 수 있는 운(정해진 덱), 마지막 운은 미리 공개 | 중간 |
| H10 | **몰려서 막기** | 앞선 편이 한 곳에 몰려 막기만 하면 된다(야간 당직 기관실) | 둘이면 합산, 셋부터 막힘, 정원 | 중간 |
| H11 | **할 일 없는 자리** | 혼자 노는 역할·먼 자리가 구경꾼이 된다(밀정, 어둑시니, 무당 손녀, 파루 종의 먼 자리) | 역할마다 고유 수단 하나. 손 닿는 거리를 늘리는 카드 | 중간 |
| H12 | **죽은 행동·자원** | 한 번도 쓰이지 않는 행동·카드(흥정, 엽전, 증명 없는 보여 주기) | 쓸 까닭을 주거나 뺀다. 「보여 주기」는 우리 기술로 증명되게(지정 확인자) | 중간 |
| H13 | **공짜 기본 승리** | 아무것도 안 해도 이기는 조건(나침반 「진로 0」) | 조건을 더한다(물자 2장 이상) | 중간 |
| H14 | **규칙 빈칸** | 진행자가 그 자리에서 정해야 했다(선언 인원, 손 크기, 맞바꾸기 세부) | 진행자 판정 기록을 다음 판 규칙으로 올린다. 기획 때 「누가·언제·몇 장·몇 번·공개 여부」를 행동마다 채운다 | 가벼움 |
| H15 | **진행자 난수 고정** | 진행자가 「차례 번호가 짝수면 첫 장」 같은 고정 규칙으로 뽑았다(파루 종, 아홉 꼬리) | 진행자 지시에 「고정 규칙 금지, 매번 예측할 수 없게」(5절). 흠이 게임이 아니라 시험 방법에 있다 | 가벼움 |
| H16 | **AI는 결정적 증거 하나로 바로 몰아간다** | 증거가 하나 서면 모두가 같은 결론에 닿아 판이 끝난다(아홉 꼬리 4표 몰림) | 결정적 증거가 나오기까지 「반쯤 맞는 증거」를 여러 개 겹치게. 사람 판도 같은지는 사람 시험에서 본다 | 관찰 |

| H17 | **숨긴 것이 공개 수치로 샌다** | 익명 행동을 해도 손 장수·점수 같은 공개 수치가 바뀌어 누가 했는지 드러난다(도깨비감투: 감투 쓴 사람이 4바퀴 모두 드러남) | 숨은 행동은 공개 수치를 바꾸지 않게(옮기기·맞바꾸기). 바꿔야 하면 그 수치도 숨긴다 | 심함 |

| H18 | **증거가 한쪽으로만 확정된다** | 「이 행동을 했다 = 그 편이 아니다」만 확실하고 반대는 누구나 흉내 낼 수 있어, 비슷한 두 편을 끝내 가를 수 없다(메밀묵 금기: 도깨비와 구미호) | 흉내 낼 수 없는 「그 편만 할 수 있는 행동」을 하나 둔다(판 끝 확인). 지도자에게 판에 한 번 가르는 수단 | 중간 |

- 흠 번호는 바꾸지 않는다. 새 흠은 끝에 더한다.
- 새 게임 기획의 빈칸 점검: 행동마다 「H1·H3·H5에 걸리나」, 끝 조건마다 「H2·H7·H13에 걸리나」, 역할마다 「H11에 걸리나」를 적는다.

## 5. 진행자 지시 틀

대국을 돌리는 서브에이전트(general-purpose)에게 주는 글. `{}`만 바꾼다.

```text
너는 숨은 편 카드 게임 「{이름}」 {n}판 규칙의 진행자다. 서브에이전트 플레이어 {인원}명으로 실제 대국 한 판을 돌리고 평가를 모아 보고한다. 모든 글은 한국어.
하지 말 것: 빌드·시험·셸 명령(grep 포함) 금지, 파일은 Read로만, 저장소 수정 금지. 파일 쓰기는 보고서 하나만: {보고서 경로}

플레이어: Agent로 {인원}명을 따로 띄워 SendMessage로 이어 간다. 상한(20)에 걸리면 대신 두지 말고 판 준비를 하며 다시 시도, 30번 실패하면 「중단」. 남의 비밀은 주지 않는다. 답 형식은 짧게.
판이 끝나면: 비밀 공개 → 플레이어마다 따로 ① 재밌었던 점 ② 개선점 ③ 총점(docs/50-fun-criteria.md 2절 점수표) → 진행자 평가 + 판정 기록, 실제 길이, 앞 판 대비, 그리고 docs/50-fun-criteria.md 4절의 값(결판 바퀴, 첫 확정 차례, 핵심 장치 사용, 안전한 수 비율, 거짓말 시도/들킴, 자리별 얽힘, 진 편 평균).
보고서: 3-1 형식. 마지막 답은 요약 30줄과 파일 경로.
```

- **동시 실행**: 서브에이전트는 한 번에 20개까지 돈다. 진행자 1 + 플레이어 5~7이니 **게임 두세 개씩** 띄운다. 1차 때 열 판을 한꺼번에 띄웠다가 넋 깃든 물건은 플레이어를 하나도 못 띄웠다.
