# 47. 큐브 맞추기 설계 (2026-11-03)

docs/46(인프라 적합성 검토)을 바탕으로, 사용자가 정한 범위(2026-11-03)를 한 게임으로 묶는 설계다. 구현은 이 문서의 단계(12절) 순서로 작은 PR을 이어 올린다.

## 0. 사용자가 정한 것(2026-11-03)

- 진행한다. docs/46 갈림길 K1~K8은 **추천대로**(같은 섞기 대결, 진행 막대+순위, 고정 여유 cap, 기기 표시, 3×3·2×2 먼저, 이름 「큐브 맞추기」, three.js, 실시간 판정 장치보다 먼저).
- **색 배치**: 대회 표준 색(위 흰색·앞 초록·오른쪽 빨강, 맞은편은 노랑·파랑·주황). 설정에서 바꿀 수 있게.
- **배우기**: 초보자 해법을 처음부터 끝까지 순서대로 따라 할 수 있게. 고급 해법(프리드리히, CFOP)도 소개하고 훈련. 훈련 때 필요한 부분 말고는 **까맣게 가리기 / 보통 큐브** 중에 고를 수 있게. 2×2·4×4·5×5도 마찬가지.
- **핑거 트릭**: 실물 큐브를 들고 하는 훈련으로 따로.
- **타이머 모드**: 실물 큐브 시간 재기. 섞는 공식은 대회 규칙에 맞게 만들고, 15초 살펴보기 시간.
- **블라인드**: 보고 외운 뒤 안 보고 맞추기.
- **여럿이 하기**를 알맞게 구성.
- **조작은 키보드만**(마우스와는 상대가 안 된다). 회전 종류가 크기마다 크게 달라지는 것을 넓힐 수 있게. 양손 키보드 대 한 손 마우스는 적당한 안을 제시(4절). **모든 조작을 설정에서 바꿀 수 있게.**
- **그래픽은 실물에 가깝게**, 회전은 부드럽게.
- 나중: 표면에 그림을 넣어 가운데 방향까지 맞추기(그림 큐브), 아주 나중: 큐브가 아닌 퍼즐(스퀘어-1, 피라밍크스 등).
- 분리할 수 있는 것은 서브에이전트로 나눠 만들고, game에 잘 인계한다.
- **(2026-11-04) 낱말**: 여럿이 같은 섞기로 겨루는 것은 「경주」가 아니라 **「대결」**(경주는 서로 달리는 것). 코드 식별자(`race`)는 그대로 둔다.
- **(2026-11-04) 앱 아이콘**: 위층을 띄운 틈이 가운데 굵은 검은 선으로 보여 큐브 같지 않았다. 틈 없는 섞인 큐브로.
- **(2026-11-04) 첫 화면**: 위 그림은 펼친 그림 대신 3D 큐브가 무작위로 섞이고 해법대로 맞춰지는 연출(초보자 해법과 프리드리히를 번갈아). 고를 것이 많아 무엇부터 볼지 헷갈리지 않게 메뉴를 묶어 줄인다.
  - 메뉴는 묶음 다섯(맞추기·대결·배우기·연습·실물 큐브)의 2열 격자, 항목은 아이콘과 이름만. 「처음이라면」이 배우기 첫 칸. 배우기는 처음이라면·해법 배우기·키 익히기·큐브의 수학, 연습은 공식 훈련·십자 훈련·내 공식·패턴 만들기(2026-11-04).
  - 연출은 장식이라 입력을 받지 않고, 안 보이거나 탭이 숨으면 멈추고, 움직임 줄이기·WebGL 없음이면 펼친 그림. 순서는 `apps/web/src/cube/hero/loop.ts`(시계로 도는 상태 기계), 풀이는 워커(`hero` 일).
  - 설정 「첫 화면 큐브」에서 크기(2×2~5×5)와 해법(「번갈아」 또는 하나)을 고른다. 해법 목록은 `apps/web/src/cube/hero/methods.ts`의 `HERO_METHODS` 한 표에만 두고, 줄을 더하면 설정과 연출에 저절로 나온다. 못 푼 판(축소법이 막힘 등)은 건너뛰고 다시 섞는다.
  - **(2026-11-04) 잘 보이게 돌려 쥐기**: 카메라(위-앞-오른쪽)에서 안 보이는 자리를 줄인다. 해법이 낸 수는 그대로 두고(컴퓨터 대결 계획·배우기가 같은 해법을 쓴다) 연출의 보여 주기 변환(`hero/present.ts`, 순수 함수)이 큐브 돌리기를 끼우고 뒤 수를 켤레로 바꾼다. 초보자 해법은 배우기에서 가르치는 방식(`@game/cube-ai`의 `{ taught: true }`, 연출 전용)으로 흰 십자와 첫 층 꼭짓점(`R' D' R D`, 칸은 UFR)을 흰 면 위에서 맞추고 z2로 내린다. 프리드리히·큰 큐브의 3×3 단계는 십자를 위에서 보인 뒤 z2로 내리고, F2L 짝·둘째 층 모서리·2×2 첫 층은 넣을 칸을 앞-오른쪽(DFR·FR)으로 y 돌려 쥔다. 마지막으로 돌려 쥔 단계 끝에 해법의 방향으로 돌아와 마지막 층 공식은 그대로 보인다. 초보자 마지막 층도 배우기와 같은 순서(노란 십자 `F R U R' U' F'` → 옆면 맞추기 `R U R' U R U2 R' U` → 꼭짓점 자리 `U R U' L' U R' U' L` → 꼭짓점 방향 `R' D' R D`, 쥐는 법·횟수도 8-2 표대로, `taught.ts`)이고 단계 꼬리표도 레슨 이름이다. 4×4·5×5 축소법(초보자)의 3×3 단계도 같고(PLL 패리티는 옆면 맞추기 앞), 2×2 초보자는 꼭짓점 자리·방향만(제자리가 꼭 하나인 U 자리, 대각이면 0인 자리에서 한 번). 꼭짓점 방향은 돌려 쥐지 않아 아래 두 층이 흐트러졌다 돌아오는 모습이 보인다. 컴퓨터 대결(`botPlan`)은 옛 순서 그대로다. 루 첫 블록·ZZ 왼쪽 블록은 y2로 돌려 오른쪽에 보이고 되돌린다. 큐브 돌리기는 보통 수의 1.5배 시간.
- **(2026-11-04) 조각부터**: 큐브 입문에서 가장 중요한 것은 「색을 옮기는 것」이 아니라 「조각을 옮기는 것」을 이해하는 것이다. 공식보다 먼저 세 종류의 조각과 그 움직임·특징을 직접 해 보며 익힌다. 3×3 초보자 과정 맨 앞에 「큐브의 조각」, 2×2·4×4·5×5 과정 맨 앞에 짧은 조각 단원, 처음 안내 맨 앞에 「조각」 단계(8-4).
- **(2026-11-04) 조각을 자유롭게**: 조각 단원은 경직된 「R을 돌렸어요. 어디 있나요?」 대신 직접 만지는 상호작용으로 한다. 누른 조각 전체를 3D·펼친 그림에서 밝히고(맞음 초록·틀림 빨강), 여러 개는 눌러 세며(「3 / 6」, 다시 누르면 풀림), 보고 싶은 조각만 색을 넣은 큐브를 모든 키로 돌려 보는 놀이판을 둔다(8-4).
- **(2026-11-04) 처음 흐름**: 3×3 초보자 과정 맨 앞은 준비 단원 둘. 「큐브와 만나기」(환영 → 스티커가 아니라 조각 → 가운데 세기 → 가상 분해·조립 → 26개)와 「조각의 움직임」(놀이판 → 따라가기 확인 → 「한 면을 맞춘 상태는?」 평가 → 제자리·방향 → 해 보기). 차례는 준비 둘 → 표기 → 전체 흐름 → 흰 십자. 「처음이라면」(`/cube/intro`)은 조각이 아니라 **우리 화면 쓰는 법**(표기·공식·단축키, 면 이름의 뜻, 방향, x·y·z, M·E·S, 넓게·큰 큐브, 화면 읽기, 키 배치 고르기, 단축키, 보는 법, 어디로).
- **(2026-11-04) 시연은 한 번에 하나**: 시연 단계는 「① 보기 → ② 해 보기」. 보기에서는 키 안내를 빼고 치라는 문장을 흐리게, 해 보기에서만 키캡과 「쳐 보세요」(8-1).
- **(2026-11-04) 키 배치**: 「두 손」은 csTimer와 같은 자리이고 실물 핑거 트릭을 옮긴 배치로 소개한다. csTimer에 없는 자리에만 Shift = 넓게를 덧붙이고 Alt는 쓰지 않는다. 처음 안내에서 「빠른 두 손 / 외우기 쉬운 표기」를 고른다(기본 두 손). 키 그림은 면 색으로 칠한다(4-5).
- **(2026-11-04) 3×3을 아는 사람의 2×2**: 2×2는 3×3의 꼭짓점만 남긴 큐브라 3×3을 떠올려 맞출 수 있다는 것을 소개하는 과정을 2×2 초보자 다음에 둔다(8-2).
- **(2026-11-04) 큐브의 수학**(`/cube/math`): 재미로 읽는 이야기 카드 일곱 장, 카드마다 직접 해 보기 하나. 중심은 ① 2×2~5×5 경우의 수를 묻고 맞히며 쌓기 ② 뽑아서 다시 끼우면 12개 중 1개만 풀리는 까닭(12 = 2·3·2, 조각을 뒤집고·비틀고·바꿔 끼워 엔진 판정) ③ 방향·짝 계기(가운데 방향 포함, 그림 큐브 4⁶÷2) ④ 크기별 날개 고리와 패리티(4×4~7×7). 뒤에 신의 수·차수·교환자. 숫자·판정은 모두 엔진·BigInt로 계산하고 `apps/web/src/cube/math/*.test.ts`가 본다. 메뉴는 배우기 묶음에 「패턴 만들기」와 나란히 둔다(여섯 칸, 2열).
- **(2026-11-04) 패턴 만들기**: 맞춘 큐브에 공식 하나로 만드는 예쁜 무늬를 소개한다(`/cube/patterns`). 크기별 카드 → 시연 → 내 키로 직접 만들어 보기(색 배치가 같으면 통과, 큐브 전체 방향 차이는 허용). 공식은 널리 알려진 것만 엔진으로 결과를 확인해 넣는다: 성질로 쓸 수 있는 것은 단위 시험(`apps/web/src/cube/patterns/data.test.ts`), 나머지는 펼친 그림 스냅숏과 스크린샷을 눈으로 본다. 4×4의 칸마다 엇갈리는 체커보드는 반 바퀴 6수 안에 없어 넣지 않았다. 내 패턴은 이 기기(`cube.patterns.v1`)에 둔다.
- **(2026-11-04) 초보자 마지막 층은 한국에서 많이 쓰는 순서로**: 노란 십자(모서리 방향) → 옆면 맞추기(모서리 자리) → 꼭짓점 자리 → 꼭짓점 방향. 단계마다 같은 공식을 모양을 보며 여러 번 쓰는 것을 가르친다. 첫 층 꼭짓점도 흰 면을 위에 둔 채 `R' D' R D`로 넣고 끝나면 뒤집는다(마지막 층 꼭짓점 방향과 같은 공식). 사용자가 말한 차례는 코너 방향 → 코너 위치였지만 자료 두 곳(아래 8-2)이 모두 위치를 먼저 하므로 위치 → 방향으로 두고, 방향을 먼저 하는 방식(A퍼뮤)은 고르기 문제로 소개만 한다.
- **(2026-11-04) 단계 지도**: 해법 과정마다 시작(준비 단원 뒤)에 「전체 흐름」 단원을 두어 몇 단계로 맞추는지 띠로 보이고, 단원 머리에는 「n단계 중 k단계」 띠를 둔다(8-6). 3×3 초보자는 준비(조각·표기) 뒤 일곱 단계.
- **(2026-11-04) 십자 훈련**: 프리드리히의 첫 십자를 여러 조건에서 살펴본 뒤 몇 수 안에 만드는 훈련을 따로 둔다(`/cube/train/cross`, 8-1절 끝). 조건은 색(흰색·흰·노랑·모든 색)·어려움(최적 4수 이하~8수·무작위)·수 제한(최적~+2·없음)·살펴보기(15초·8초·무제한)·방식(보면서·계획 후 가리고, 「아래에서」 함께).

## 1. 화면과 모드

주소 `/cube`. 첫 화면(GameHome 틀)에서 고른다.

| 모드 | 하는 일 | 큐브 |
|---|---|---|
| **혼자 맞추기** | 가상 큐브를 섞어 맞추고 시간을 잰다. 15초 살펴보기(끄기 가능). 기록·평균 | 3D 가상 |
| **타이머** | 실물 큐브용. 대회 규칙 섞는 공식 + 섞인 모습 그림, 스페이스바 길게 눌렀다 떼서 시작·아무 키로 멈춤, 15초 살펴보기(+2·DNF), 평균(5번·12번·100번) | 실물(화면은 그림) |
| **블라인드** | 외우는 동안 보고, 「시작」 뒤 스티커가 모두 가려진 채 키보드로 맞춘다. 외우기 시간 + 맞추기 시간. 실물 블라인드용 타이머(외우기·맞추기 나눠 재기)도 | 3D 가상 / 실물 |
| **배우기** | 초보자 해법(크기별) 단원을 순서대로. 단원마다 설명·시연·직접 해보기 | 3D 가상 |
| **큐브의 수학** | 경우의 수, 불가능한 큐브(뽑아서 다시 끼우기), 방향과 짝, 크기와 패리티, 신의 수, 차수, 교환자를 카드로 넘기며 직접 해 본다(`/cube/math`) | 3D 가상 |
| **훈련** | 프리드리히(CFOP)의 십자·F2L·OLL·PLL, 2×2·큰 큐브 공식. 상황을 내고 맞게 풀었는지·시간 기록. 가리기/보통 | 3D 가상 |
| **핑거 트릭** | 실물 큐브를 들고: 공식을 손가락 표기와 함께 보여 주고 반복 횟수·초당 수 기록 | 실물 |
| **온라인 대결** | 2~8명, 같은 섞기, 진행 막대·순위 | 3D 가상 |
| **컴퓨터와 대결** | 단계별 컴퓨터(입문~초고수)와 같은 섞기로 | 3D 가상 |
| **패턴 만들기** | 체커보드·여섯 점·큐브 속 큐브·슈퍼플립 등 크기별 패턴(`/cube/patterns`). 카드마다 시연·직접 만들어 보기·되풀이 횟수·되돌리는 공식. 내 패턴 저장 | 3D 가상 |

크기: 2×2, 3×3, 4×4, 5×5부터(엔진은 n×n 일반, 6×6·7×7은 화면·조작만 확인하면 열림).

## 2. 패키지 구성과 넓힐 자리

```
packages/puzzle-core     퍼즐 공통 계약(조각·스티커·수·상태). 큐브가 아닌 퍼즐도 이 계약을 따른다
packages/cube-engine     n×n 큐브: 상태, 표기 읽기·쓰기, 수 적용, 맞춤 판정, 무작위 상태, 가리기, 상황 만들기
packages/cube-solver     2×2 최적 해, 3×3 2단계 해(섞기·초고수), 사람 흉내 해법(층별·CFOP·축소법)

apps/web/src/cube/       화면: 3D 그리기(view), 조작(input), 모드별 화면, 배우기·훈련 자료, 온라인
```

### 2-1. 퍼즐 공통 계약(`puzzle-core`)

큐브가 아닌 퍼즐까지 받으려고, **"스티커 자리의 순열 + 스티커 방향"** 을 공통 상태로 둔다.

```ts
interface PuzzleDef<Move> {
  id: string;                     // "cube3", "cube4", 나중에 "pyraminx", "sq1"
  stickerCount: number;
  faces: FaceDef[];               // 면 이름·기본 색 자리
  solved(): PuzzleState;
  parse(text: string): Move[];    // 표기 → 수
  format(moves: Move[]): string;
  apply(state: PuzzleState, move: Move): PuzzleState;   // 둘 수 없는 수(스퀘어-1 모양)면 오류
  canApply?(state: PuzzleState, move: Move): boolean;
  isSolved(state: PuzzleState, opts?: { orientCenters?: boolean }): boolean;
  geometry: PuzzleGeometry;       // 그리기용: 조각 모양, 스티커 위치, 수마다 회전축·각도·움직이는 조각
}
interface PuzzleState { perm: Uint16Array; twist: Uint8Array }  // 자리 i에 있는 스티커 번호, 그 스티커의 돌아간 정도
```

- **수 = 순열 + 회전 정보.** 수마다 "어느 스티커가 어디로 가나"와 "어느 축으로 몇 도, 어떤 조각이 움직이나"를 함께 둔다. 엔진은 앞의 것만, 3D는 뒤의 것만 쓴다. 피라밍크스(꼭짓점 축 120°)·메가밍크스(72°)도 같은 모양이다.
- **스티커 방향(`twist`)** 을 처음부터 들고 다닌다. 보통 큐브에서는 판정에 안 쓰지만, 그림 큐브(가운데 방향까지 맞추기)에서 `orientCenters`로 쓴다. 나중에 상태 모양을 바꾸지 않아도 된다.
- 스퀘어-1처럼 모양이 바뀌어 둘 수 없는 수가 생기는 퍼즐은 `canApply`로 막는다.
- 표기는 퍼즐마다 다르므로 `parse`·`format`이 퍼즐 안에 있다.

### 2-2. n×n 큐브의 수 모델(`cube-engine`)

크기마다 회전 종류가 크게 달라지는 것을 **하나의 일반 수**로 표현하고, 표기는 그 위의 이름일 뿐으로 둔다.

```ts
interface CubeMove {
  axis: "x" | "y" | "z";          // 회전축
  from: number; to: number;       // 축을 따라 몇 번째 층부터 몇 번째 층까지(1부터 n까지)
  turns: 1 | 2 | 3;               // 시계 방향 90°의 몇 배
}
```

- `R` = x축 바깥 1층, `Rw`·`r` = 바깥 1~2층, `3Rw` = 1~3층, `2R` = 2층만, `3R` = 3층만, `M`(3×3) = 가운데 층, `x` = 1~n층 전체(큐브 돌리기), 큰 큐브 가운데 층(`M`은 홀수 크기의 정가운데, 짝수는 정의 없음).
- 표기 읽기는 WCA 표기(`R U2 F' Rw 3Rw2 x`)와 흔히 쓰는 소문자(`r u`)·가운데 층(`M E S`)을 받는다. 쓰기는 WCA 표기로.
- 새 회전(예: 6×6의 `3Rw`)이 필요해도 수 모델은 그대로고, 조작키 배치에 "동작"만 하나 더하면 된다(4절).

### 2-3. 무작위 상태·가리기·상황 만들기

- **무작위 상태**: 조각별(꼭짓점·모서리·가운데·큰 큐브의 날개 모서리·가운데 조각)로 섞고 맞출 수 있는 조건(홀짝, 방향 합)만 맞춘다. 해법기가 필요 없다.
- **일부만 섞기**: "F2L은 맞고 윗층만 무작위", "십자만 맞음" 같은 상황을 조각 묶음 단위로 만든다(맞아 있어야 할 조각은 고정, 나머지만 무작위). 훈련의 "보통 큐브" 모드가 이것을 쓴다.
- **가리기(마스크)**: 스티커마다 「보임 / 까맣게 / 회색」. 단계마다 정해 둔 마스크(십자만, F2L만, OLL은 윗면 색만, PLL은 윗층 옆면만 등)를 훈련의 "가리기" 모드가 쓴다. 블라인드는 모두 까맣게.
- **공식으로 상황 만들기**: 공식의 거꾸로를 맞춘 큐브에 적용 + 무작위 윗면 돌리기(AUF)로 OLL·PLL 상황을 만든다.

## 3. 대회 규칙 섞기(`cube-scramble`)

WCA 규정과 공식 섞기 프로그램(TNoodle) 방식을 따른다.

| 종목 | 방식 | 필요한 것 |
|---|---|---|
| 2×2 | 무작위 상태, 최적 해가 4수 미만이면 다시(4b3b). 섞기 글은 TNoodle처럼 U·R·F만으로 **딱 11수** | 2×2 최적 해(상태 367만, 표) |
| 3×3(블라인드 포함) | 무작위 상태 → 2단계 해법으로 푼 해의 거꾸로를 섞는 공식으로(21수 이하). 1수 이하로 풀리는 상태만 다시(4b3: 2수 이상 필요한 상태) | 3×3 2단계 해법(Kociemba류, 웹 워커) |
| 4×4 | 공식은 무작위 상태(3단계 해법). **1차는 무작위 수 40수**로 하고 화면에 "대회 공식과 다름"을 밝힌 뒤 나중에 바꾼다 | (나중) 4×4 해법 |
| 5×5 | 무작위 수 60수(4b3e, 대회 방식과 같음) | 이어지는 같은 축 묶음 안에서 같은 면·두께는 한 번만(TNoodle `isRedundant`를 줄여 옮김) |
| 6×6·7×7 | 무작위 수 80·100수 | 같음 |

- 섞기는 씨앗에서 결정적으로 나온다(온라인 대결·컴퓨터·복기에서 같은 섞기를 다시 만든다).
- 블라인드 3×3(4b3a): 섞기 뒤 무작위 방향 돌리기를 붙인다. 첫 수 {없음, Rw, Rw2, Rw', Fw, Fw'} × 둘째 수 {없음, Uw, Uw2, Uw'}, 24가지 같은 확률. 섞기 마지막 수는 방향 돌리기 첫 수의 축과 같지 않게 해를 찾는다(TNoodle `firstAxisRestriction`).
- 2단계 해법은 표를 처음 만드는 시간이 든다. 웹 워커에서 만들고, 그동안 화면은 "섞기 준비 중"을 보인다. 크기·시간은 CI에서 잰다(로컬 성능 측정은 하지 않는다, 2026-11-03 사용자).

## 4. 조작: 키보드

### 4-1. 동작과 키를 나눈다

- **동작(action)** 은 "무엇을 하는가": `move(R)`, `move(R')`, `move(Rw)`, `move(2R)`, `rotate(x)`, `layer+1`, `undo`, `reset`, `inspectionSkip` 등. 크기마다 쓸 수 있는 동작 목록이 다르다(`M`은 홀수만, 깊이 고르기는 4×4 이상).
- **키 배치(keymap)** 는 "어느 키가 어느 동작인가". 배치는 이름 있는 묶음(「두 손」「표기」「사용자」)이고, 설정 화면에서 아무 동작이나 아무 키(Shift·Alt 조합 포함)로 바꾼다. 겹치는 키는 저장 전에 알린다. `event.code`(자판 위치) 기준이라 한글 입력 상태에서도 같은 자리로 동작한다.
- 저장은 기기 `localStorage`(내 설정), 내보내기·가져오기(JSON).

### 4-2. 양손 키보드 대 한 손 + 마우스 — 제안

| 안 | 장점 | 단점 |
|---|---|---|
| **A. 양손 키보드(큐브 돌리기 x·y·z도 키)** | 가장 빠르다. 손이 홈 줄을 떠나지 않는다. 시뮬레이션 큐브에서 오래 써 온 방식이라 옮겨 오는 사람이 많다. 온라인 대결에서 모두 같은 조건 | 처음엔 외울 것이 많다 |
| B. 왼손 키보드 + 오른손 마우스(끌어서 x·y·z) | 큐브를 "손으로 돌려 보는" 느낌, 외울 키가 적다 | 마우스로 90° 맞춰 돌리기는 키 한 번보다 느리고 손이 오간다. 오른손 담당 면(R 등)을 왼손으로 쳐야 해 공식 손맛이 실물과 달라진다. 대결에서 A보다 늘 느리다 |

**제안: A를 기본으로 하고, 배우기용으로 「표기 배치」를 함께 둔다. B는 "보기 돌리기"로만 연다.**

- **「두 손 배치」(기본, 빠르기)**: 실물 큐브에서 그 면을 돌리는 손이 같은 손으로 치도록 둔다. 오른손 = R·U(오른 검지)·F, 왼손 = L·U′(왼 검지)·D, 그리고 같은 면의 시계·반시계는 대칭 자리. 큐브 돌리기 x·y·z는 가운데 줄(T·Y·G·H 근처, 두 검지가 닿는 곳)과 ;·A 등 새끼손가락. 정확한 표는 구현 때 기존 웹 큐브 프로그램과 최대한 같은 자리로 맞춰 옮겨 오는 사람이 편하게 한다.
- **「표기 배치」(처음, 직관)**: R·L·U·D·F·B 키 = 그 면 시계, Shift = 반대, M·E·S, X·Y·Z = 큐브 돌리기, 숫자 2~7 = 다음 수의 층 깊이, Alt = 넓게(w). 튜토리얼 공식을 글자 그대로 친다.
- **마우스(선택)**: 끌면 **보기만** 돈다(카메라, 수로 세지 않음, 놓으면 제자리로 천천히 돌아옴). 큐브 돌리기(x·y·z)를 마우스로 하는 설정은 「사용자 배치」에서 켤 수 있게 열어 두되 기본은 끔. 대결에서 B를 고른 사람은 결과에 표시한다.
- **큰 큐브**: 「표기 배치」는 숫자로 깊이, 「두 손 배치」는 넓게 돌리기(`Rw` `Lw` `Uw` `Dw` `Fw` `Bw`)와 안쪽 한 층(`2R` 등)을 몇 키 더 둔다. 5×5 넘어가면 "층 고르기 키 + 면 키".
- 키 그림(지금 배치)을 큐브 아래에 늘 보이게(접기 가능). 키를 누르면 그 키가 잠깐 빛난다.
- 휴대폰은 1차로 **혼자 하기·배우기·타이머**만(밀어서 돌리기 + 표기 단추 줄). 가운데 줄을 밀면 M·E·S가 되고, 단추 줄에도 홀수 크기는 M을 둔다(3D를 못 그리는 기기와 루 LSE, `input/actions.ts`의 `buttonMoves`). 온라인 대결은 키보드 기기만 들어오게 하고 나중에 다시 본다(사용자: 키보드만).

#### 4-2 결정(2026-11-04): csTimer와 같은 「두 손」, 핑거 트릭으로 소개

- **cube-controls 갈림길을 정했다**: 양손 키보드 기본(x·y·z도 키), 마우스는 보기만(사용자 배치에서 마우스 돌리기를 켤 수 있음). 배치는 바꾸지 않고 소개 틀을 바꾼다.
- **csTimer가 정한 키는 csTimer와 똑같이**(github cs0x7f/cstimer `src/js/twisty/twistynnn.js` `generateCubeKeyMapping`, 391~413행 숫자 키). 사용자 판단: 「우리만의 배치가 오히려 혼란을 일으킨다」. 면·x·y·z·넓게(U = Rw, M = Rw', V = Lw, R = Lw', `,` = Uw, C = Uw', Z = Dw, / = Dw')·M(5·6 / X·.)은 원래 같았고, 숫자를 더했다: **1 = S', 2 = E, 9 = E', 0 = S**, 큰 큐브 **층 수** 3·4 = 왼손 층 수 −1·+1, 7·8 = 오른손 층 수 +1·−1. 왼손 층 수는 L·Lw 키, 오른손 층 수는 R·Rw 키가 함께 돌리는 바깥 층 수다(R 키 = 바깥 k층, Rw 키 = k+1층, `input/interpreter.ts` `withLayers`). 층 수는 유지되고 키 그림 위에 「층 수 왼손 k · 오른손 k」로 보인다. 예전의 깊이 키(2~4 → 면 키)는 지웠다. **(2026-11-04 고침) 가운데 줄 키 5·6·X·.는 csTimer처럼 「잡은 층 바로 안쪽 한 층」**(csTimer `[oSr+1, oSr+1, R]`): 3×3은 M·M'(예전과 같음), 4×4는 . = 2R·6 = 2R'·5 = 2L·X = 2L', 층 수를 올리면 한 층씩 안쪽(6×6에서 7 → . = 3R). 그래서 5×5의 M은 7 → 6이다(csTimer와 같음, 예전에는 6 하나로 가운데 층이었다). 안쪽 한 층이 키 하나가 되어 배우기 키캡의 「Rw R'」(두 수라 해 보기 중 잠깐 「다른 모양」이 떴다)는 없앴다.
- **csTimer에 없는 자리에만 덧붙임**: Shift + 면 키 = 넓게(Shift+I = Rw, Shift+J = Uw …, 큰 큐브는 층 수 + 1층). Shift는 「강한」 느낌이라 넓게로 알아보기 쉽고(사용자), csTimer는 Shift를 무시해 익숙한 사람의 손 기억과 부딪치지 않는다. **Alt는 쓰지 않는다**: 윈도 크롬의 Alt+D(주소창)·Alt+F(메뉴)처럼 브라우저가 가로챌 수 있다. 「표기」 배치는 그 규칙(Shift = 반대, Alt = 넓게) 그대로다. 처리한 키는 `preventDefault`를 부르지만(`input/keyboard.ts`), 윈도 크롬에서 Alt+D가 막히는지는 이 맥에서 확인하지 못했다(남은 확인).
- **csTimer와 다른 곳: Space**. csTimer는 층 수를 1로 되돌리는 키, 우리는 살펴보기·블라인드 시작이다. 우리 쪽을 지키고, 층 수는 섞기·맞춘 상태로·크기 바꾸기 때 1로 돌아간다. 처음 안내·키 익히기·단축키 표에 한 줄로 적었다.
- **기록·공식은 가장 짧은 이름**: 받은 수는 `canonicalNotation`(`input/actions.ts`)으로 적는다. 3×3의 2R = M'·2U = E', 3R = L', 넓게 n층 = x·y·z, 4×4의 3R = 2L', 5×5의 3U = E'. 모든 크기·면·층·방향에서 같은 돌리기인지 `canonical.test.ts`가 엔진으로 본다.
- **핑거 트릭으로 소개**: 「실물에서 돌리는 손가락으로 치고, 손이 움직이는 쪽(위·아래)으로 줄을 골라요.」 대응표 `keys/two-hand.ts`(R = 오른 손목 아래→위 I, R' = K, U = 오른 검지 J, U' = 왼 검지 F, D = 왼 약지 S, D' = 오른 약지 L, F·F' = 검지 한 칸 안쪽 H·G, M = 약지로 밀어 올리기 숫자 줄, M' = 오른 약지로 당겨 내리기 . 등)를 `two-hand.test.ts`가 실제 배치·손(`handOf`)·줄로 확인한다. M도 핑거 트릭으로 설명되어 예외가 아니고, **예외는 B·B'**(사람마다 손가락이 달라 「편한 손가락으로 바꾸려면 설정의 사용자 배치에서」).
- **처음 안내에서 고른다**: 「빠른 두 손」(꼬리표 「한 수에 키 하나」 「실물 핑거 트릭과 같은 손가락」) / 「외우기 쉬운 표기」(「외울 것 적음」 「반대 방향은 Shift + 키」). 기본은 두 손, 고르면 설정에 저장한다. 근거: 반대 방향(')이 공식의 절반 가까이라 Shift 방식은 치는 횟수가 늘고 Shift를 늦게 떼는 실수가 잦다.

### 4-3. 빠른 입력과 부드러운 회전

- 키를 누른 순간 엔진 상태가 바뀐다(시간·판정 기준). 화면은 애니메이션 줄을 따라간다.
- 다음 키가 오면 지금 돌던 회전을 즉시 끝내고 다음으로. 줄이 길면 회전 시간을 줄인다(기본 한 수 90ms, 설정 0~200ms).
- 키 반복(autorepeat)은 무시한다.

### 4-4. 키 익히기·단축키 표(2026-11-04)

사용자 요청(「키가 익숙해질 수 있도록 조작 훈련이나 튜토리얼」, 「키보드 레이아웃에 단축키 표」)으로 `/cube/keys` 세 화면을 두었다(첫 화면 「키 익히기」, 처음 오셨나요·설정 키 배치·혼자 맞추기 아래에서 이어짐). **단축키 표**(`/cube/keys`)는 지금 배치를 실제 키보드 비례(숫자 줄·QWERTY 세 줄·스페이스·화살표)로 그려 키마다 그냥·Shift·Alt(·Alt+Shift) 층 동작을 적고, 면 돌리기는 큐브 표준 색(R 빨강·L 주황·U 흰·D 노랑·F 초록·B 파랑), 넓게·안쪽·가운데 층·큐브 돌리기·명령은 따로 색, 왼손·오른손 영역은 옅게 나눈다. 크기 2~7을 고르면 없는 동작은 흐리게, 인쇄는 흰 바탕, 휴대폰은 칸이 줄어 가로로 넘치지 않는다. 아래 동작 → 키 표는 `R'`·`Ri`·`Shift+I`·「되돌리기」로 찾는다. **키 익히기**(`/cube/keys/learn`)는 쉬운 것에서 어려운 것으로 13단계다(아래 2026-11-04 결정). 칠 키가 그림에서 빛나고 3D 큐브가 친 대로 돌며 틀리면 친 키의 동작을 알린다. 문구의 키는 배치에서 읽어(「두 손」·「표기」·「사용자」 같은 단계) 배치에 없는 수는 건너뛰고 알린다. **조작 훈련**(`/cube/keys/drill`)은 수 보고 치기(30초 또는 30수, 단계 면만 → 반대 → 큐브 돌리기 → 넓게·가운데 → 4×4 이상 안쪽 층, 큐브 숨기기), 키 보고 맞히기(빛나는 키의 동작을 보기 넷에서), 공식 따라 치기(핑거 트릭 공식, 반복마다 초당 수). `R2`는 같은 층을 두 번, `2R`은 깊이 키 뒤 면 키로 친 것도 맞다. 키(동작)별 맞힘률·평균 반응 시간과 튜토리얼 진도를 이 기기에 남기고, 틀린 비율·느린 만큼 무게를 더해 약한 키를 더 자주 낸다. 로직은 `apps/web/src/cube/keys/`(화면 모름, 시계·난수 주입).

**키 익히기 차례를 단계적으로 다시 짰다(2026-11-04, 사용자 「처음은 큐브 돌려보기, 다음은 한쪽 면씩 돌리기」).** 예전에는 첫 단계부터 면 셋(R·R'·U)을 묶고 큐브 전체 돌리기가 다섯째였다. 지금 차례: ① 손 자리(F·J) → ② **큐브 둘러보기**(x·y·z를 한 번씩 친 뒤 「초록 면을 위로」 → 「빨강 면을 위로」 → 「흰 위·초록 앞」 목표 모양 만들기. 섞이지 않고 보는 쪽만 바뀐다는 것을 먼저 손에 익힌다. 면을 돌리면 「큐브 전체를 돌려요」라고 알린다) → ③ 오른쪽 면 R·R' → ④ **되돌리기·맞춘 상태로**(R → 되돌리기 → 섞기 → 맞춘 상태로. 실수해도 괜찮다는 것을 한 면을 배운 바로 뒤에 가르친다) → ⑤~⑨ 왼쪽·윗면·앞면·아랫면·뒷면(면마다 한 단계, 「돌리고 → 되돌려 맞추기」 `F F' F' F`로 시계·반시계 짝을 익힌다. 단계 머리에 치는 손(「오른손」·「왼손」·「두 손」)과 그 배치의 키캡을 보인다) → ⑩ **섞고 풀기**(R U → U' R'을 따라 친 뒤 F R로 섞고 혼자 풀기, 조각 단원의 「나중 것부터 거꾸로」와 이어진다. 맞춘 상태로·섞기는 풀기로 치지 않는다) → ⑪ 반 바퀴(R2·U2·F2 = 같은 키 두 번) → ⑫ 넓게·가운데 층 → ⑬ 짧은 공식(섹시 무브·수네) → 조작 훈련으로. 단계를 열면 큐브를 맞춘 상태로 두고, `StepRun`이 맞춘 상태에서 수·명령을 따라가 목표 모양·혼자 풀기를 판정한다. 색 이름은 대회 표준 색으로 쓰고 칸은 사용자 색으로 칠한다. 옛 진도(`right`·`left`·`fdb` 등)는 `migrateLearnDone`이 옮긴다: 옛 8단계를 모두 마친 사람은 모두 마침, `right` → 오른쪽 면, `left` → 왼쪽 면(둘 다면 윗면도), `fdb` → 앞·아래·뒷면, 모르는 id는 버린다.

**배우기·튜토리얼은 사용자 키 배치를 그대로 보여 준다(2026-11-04, 사용자 요청 「튜토리얼, 학습 자료도 같은 키들을 써야 자연스럽게 인터페이스에 익숙해지지 않겠어?」).** 해 보기는 원래 설정 배치로 돌았지만 화면에는 표기(R)만 있어 「두 손」 사용자는 R을 I로 머릿속에서 바꿔야 했다. 이제 수 표기 옆에 그 사람의 키를 작은 키캡으로 붙인다(`R` `I`): 해 보기 모범 답 힌트(연 마지막 수), 시연 수 목록, 따라 하기의 칠 수, 훈련의 쓰는 공식, 공식 모음 시연, 레슨 본문 속 수(「L을 쳐 보세요」). 힌트·따라 하기 중에는 큐브 아래 키 그림(접기 가능)에서 칠 키가 하늘색으로 빛나고, Shift·Alt가 필요하면 칸에 ⇧·Alt를 붙인다. 처음 안내(`/cube/intro`)의 키 단계는 지금 배치로 R·R'·U·U'을 직접 쳐 보고, 두 배치 그림은 「두 배치 견주어 보기」로 접었다. 휴대폰(키보드 없을 기기, `useNoKeyboard`)은 키캡을 숨기고 표기만 보인다. 핑거 트릭(실물)은 키캡을 붙이지 않는다.
- 변환은 `keys/move-keys.ts`의 `keysForMove(keymap, n, notation, layers)` 하나다(2026-11-04 다시 짬). 키마다 해석기와 같은 계산(`keys/reach.ts` `playedMove`)으로 실제로 도는 수를 흉내 내어 고르므로 동작 이름이 달라도(3×3의 . = `2R` = M') 같은 돌리기면 맞는 키다. 차례: 키 하나 → `R2`는 같은 층 키 두 번(시계 먼저) → 깊이 키 + 면 키(「표기」의 2 → R), 같은 무리 안에서는 공식과 같은 글자의 키·조합 키 적은 것·배치 차례. 층 수 키가 있는 배치는 지금 손이 잡은 층 수(`keys/hand-layers.ts`, `CubePlay`가 알림)에서 시작해 층 수 키를 앞에 붙인다(5×5 `3Rw` = 7 → U, 그 뒤 `R` = 8 → I). 키 차례는 늘 수 하나만 일으킨다. 조작 훈련·키 익히기는 층 수를 바꾸지 않는 `pressesFor`(층 수 1·1). 소문자 넓게(`r`)는 `Rw`, `R2'`는 `R2`로 읽는다. 크기에 없거나 배치에 키가 없는 수는 「키 없음」(「두 손」 5×5의 `3Uw`처럼 csTimer에도 없는 것)(버튼 밖에서는 설정 링크). 핑거 트릭 화면도 수마다 「두 손」 키캡을 붙인다(사용자 배치와 상관없이 두 손).
- **손 표시(2026-11-04)**: 큰 큐브 「두 손」은 큐브 위에 왼손(하늘색)·오른손(주황)이 잡은 층 경계를 선과 세모로 보인다(csTimer `updateHandMarks`, `CubeView.setHandMarks`). 큐브 아래 키 그림은 「층 수 왼손 k · 오른손 k」와 함께 R·L 쪽 칸 글을 지금 치면 도는 수로 바꾼다(층 수 2면 I = Rw).
- **키 익히기 「배치 규칙」(2026-11-04)**: 둘러보기 다음 단계. 「두 손」은 실물 핑거 트릭을 옮긴 배치(csTimer와 같음)와 규칙 한 문장을 알리고, R(I)을 보인 뒤 L'·L·U'·F'은 키 그림 글을 가리고 대응표(`keys/two-hand.ts`)의 손가락 실마리로 맞혀 친다. 「표기」는 Shift 규칙을 맞힌다.
- 본문 속 수는 그리는 쪽(`MoveText`)이 `splitMoveText`로 찾는다. 레슨 자료는 그대로다. 앞뒤에 영문·숫자·프라임·`~`가 붙은 것(OLL·F2L·EO·CMLL·Ua·A~D)과 뒤에 「키」·「자」·「퍼뮤」·「모양」이 오는 것은 수로 보지 않는다. 스티커를 글자로 부르는 블라인드 단원은 덧붙임('·2·w·깊이)이 있거나 빈칸으로 이어진 공식만 바꾼다(「버퍼 B와 D」는 그대로).

### 4-5. 키 그림의 면 색(2026-11-04)

사용자 요청(「키보드에 면 색을 표시하고 시계·반시계를 구별하면 아래 가상 키보드를 보면서 키를 익히기 좋다」). 큐브 아래 키 그림(`KeyGuide`)과 단축키 표·키 익히기·조작 훈련(`KeyboardMap`)에 같은 칠하기(`components/KeyPaint.tsx`, 판정 `keys/key-colors.ts`)를 쓴다. 설정 「키 그림에 면 색」(기본 켬)을 끄면 단색.
- **면 돌리기·넓게·안쪽 층**: 그 면의 색으로 꽉 채운다. 사용자 색 설정을 따른다. 반대 방향(')은 같은 색을 연하게 + **빗금**(연하기만이면 색약에서 구별이 어렵다). 글자색은 바탕 밝기로 고른다(흰·노랑 위는 검정).
- **색의 기준은 들고 있는 방향**: 처음 방향(흰 위·초록 앞)에서 큐브 전체 돌리기를 따라간 방향. 홀수 큐브는 가운데 칸으로 읽고, 짝수 큐브는 받은 수를 따라간다(절반 넘는 층을 함께 돌리는 넓게도 큐브 전체 돌리기로 친다, `orientAfter`). y를 치면 R 키가 파랑이 된다.
- **x·y·z·M·E·S**: 회색 바탕에 「보내는 면 색 ▸ 받는 면 색」 두 색 띠. 앞(또는 위) 줄이 어디로 가는지다: x 앞 → 위, y 앞 → 왼쪽, z 위 → 오른쪽, M 앞 → 아래, E 앞 → 오른쪽, S 위 → 오른쪽(엔진으로 시험). 반대 방향은 색 차례를 거꾸로 하고 빗금.
- Shift를 누르고 있는 동안 키 그림의 굵은 글이 Shift 층(넓게) 이름으로 바뀐다. 명령 키는 그대로.
- **짝 잇기·손가락 자리(2026-11-04)**: 같은 면의 시계·반시계 두 키(I·K, J·F …)를 면 색 선으로 잇는다. 선은 키 글을 가리지 않게 줄 사이 틈으로 돌고, 같은 틈의 선은 번갈아 비킨다(`keys/key-pairs.ts` `pairPath`). 가운데 줄 손가락 자리(F·J 검지 …)를 손 색으로 옅게 겹친다. 설정 「키 그림에서 같은 면의 두 키 잇기」·「키 그림에 손가락 자리」로 끈다. 키 보고 맞히기(동작 글 숨김)에서는 짝 선을 끈다.

## 5. 그래픽

three.js(이미 의존성, 큐브 화면에서만 늦게 불러오기).

- **조각**: 모서리가 둥근 상자(검은 플라스틱, 약간 거친 반사). 스티커는 조금 들어간 둥근 사각형, 매끈한 광택(clearcoat). 「스티커 없는(stickerless)」 모양을 고를 수 있게.
- **빛**: 실내 반사맵(three.js가 코드로 만드는 방 환경, 파일 없음) + 부드러운 그림자 한 장(바닥 접촉 그림자). 과하면 휴대폰은 낮은 품질로.
- **회전**: 부드러운 가감속(끝에 아주 살짝 넘쳤다 돌아오기는 설정). 움직이는 동안만 그리고 멈추면 그리기를 멈춘다(배터리).
- **색**: 표준(흰·노랑·초록·파랑·빨강·주황), 설정에서 면마다 바꾸기와 색 묶음(높은 대비, 색약 친화). 가린 스티커는 검정(또는 회색).
- **그림 큐브(나중)**: 스티커에 그림 조각을 붙이고 `twist`로 방향을 그린다. 상태 모양은 이미 준비(2-1).
- **보기**: 기본은 앞·위·오른쪽이 보이는 각도. 뒤·아래 살짝 보기(키 하나로 잠깐), 펼친 그림(전개도) 작은 창.
- 그리기 품질 단계(높음/보통/낮음)를 설정에 둔다. 성능 숫자는 실기기·CI에서 잰다.

## 6. 타이머 모드(실물)

- 종목 고르기(2×2~7×7, 3×3 블라인드). 대회 규칙 섞는 공식 + 섞인 모습 펼친 그림.
- 시작: 스페이스바를 0.3초 넘게 누르고 있으면 준비(초록), 떼면 시작, 아무 키로 멈춤. 휴대폰은 화면 누르기로 같게.
- **살펴보기 15초**(WCA A3a1·A3b3·A3b4·A4d): 켜면 섞기 뒤 첫 누름으로 살펴보기 시작, 8초·12초 알림 소리, 딱 15.00초부터 +2, 딱 17.00초부터 DNF(A4d1+·A4d2+). 끌 수 있다. 블라인드는 살펴보기가 없다(B1a).
- 기록: 종목·세션별 목록, 5번 평균(가장 좋은·나쁜 것 빼고 셋 평균), 12번 평균(관례), 최고 기록, +2·DNF 고치기, 메모. 내 기록(`/profile`)에 묶는다. 이 기기 저장 + 내보내기.
- 버림·반올림(9f1·9f2): 한 번 기록은 원래 값을 1/100초로 버린 뒤 +2를 더하고, 10분 이상이면 초로 버린다. 평균은 그 기록으로 낸 뒤 1/100초(10분 이상은 초)로 반올림.
- 블라인드: 외우기 끝 표시(키 한 번)로 외우기·맞추기 시간 나눔. 3×3 블라인드는 5번 중 최고(9b3a)와 따로 인정하는 5번 평균(9b3b)을 보인다(4×4·5×5 블라인드는 3번 중 최고·세 번 평균, 9b6).

## 7. 블라인드(가상)

- 섞기 → 외우기(보이는 상태, 큐브 돌리기 x·y·z와 보기 돌리기만 허용, 면 돌리기 막음) → 「시작」 키 → 모든 스티커 까맣게, 맞추기 → 「끝」 → 공개. 맞았으면 시간, 아니면 DNF와 틀린 조각 표시.
- 배우기에 블라인드 해법(올드 포흐만: 모서리·꼭짓점 하나씩 바꾸기 공식, 글자 붙이기)을 단원으로 둔다(3단계 뒤).

## 8. 배우기와 훈련

### 8-1. 공통 틀

- **단원(lesson)**: 설명 글 → 시연(엔진이 공식을 천천히 돌림, 한 수씩 앞뒤) → 직접 해보기(정해진 상황에서 목표 모양을 만들면 통과). 목표는 "이 조각들이 맞아 있음"으로 확인(일부 칸만 보는 판정).
- **훈련(drill)**: 상황 묶음(예: PLL 21개)에서 무작위로 내고, 맞춘 시간·실수·쓴 공식 기록. 약한 것 다시 내기. 고른 상황만 연습.
- **가리기/보통**: 단원·훈련마다 마스크(2-3)를 정해 두고, 사용자가 「가리기」(필요한 스티커만 색, 나머지 검정)와 「보통 큐브」(나머지도 무작위로 섞인 실제 모양) 중 고른다.
- **시연은 「① 보기 → ② 해 보기」(2026-11-04)**: 보기는 재생·한 수씩만(키캡 없음, 본문의 치라는 문장은 흐리게, `demoBodyParts`), 재생을 끝까지 보면 「해 보기」가 눈에 띄고, 해 보기에서만 키캡과 「쳐 보세요」. 같은 공식의 해 보기가 단원에 따로 있으면 「해 보기는 다음 단계에서」.
- **수 표기 옆에 사용자 키 배치의 키를 함께 보인다(2026-11-04)**: 시연·해 보기 힌트·따라 하기·훈련·본문 속 수 모두. 자세한 것은 4-4절 끝.
- 공식은 여러 개를 허용하고 **결과 모양으로 채점**한다(사람마다 쓰는 공식이 다르다). 대표 공식과 대안을 보여 준다.
- 자료는 데이터 파일(`apps/web/src/cube/learn/*.ts`)로 둔다. 상황 이름, 마스크, 만드는 공식, 대표 공식, 손가락 표기.
- **내 공식(2026-11-04, `/cube/algs`, `apps/web/src/cube/algs/`)**: 상황마다 내 공식을 여러 개 넣고 하나를 「쓰는 공식」으로 고른다(기본은 대표 공식, 이 기기 `cube.algs.v1`, JSON 내보내기·가져오기). 넣을 때·가져올 때 모두 검사기 `checkAlg`를 거친다: 훈련 「가리기」와 같은 상황(흰 면 아래로 쥔 맞춘 큐브 + 대표 공식의 거꾸로)에 새 공식을 해 보고 묶음의 목표가 되는지 본다(OLL 윗면 노랑·F2L 지킴, PLL 윗면 돌리기 하나 남음까지, F2L 십자·다른 칸 지키고 짝 넣기, 2단계·오르테가는 훈련 목표, 4×4 패리티는 「3×3처럼 풀 수 있음」(OLL 뒤집힘 짝수, PLL 꼭짓점·모서리 자리 바꿈 홀짝이 같음), 5×5는 모서리 묶기, 블라인드는 다 맞춤). 앞 윗면 돌리기는 봐주고 필요하면 붙여 저장한다. 판정은 가운데 색 기준이라 x·y·z·넓게·가운데 층이 섞여도 된다. 아니면 깨진 곳을 상태로 짧게(「F2L이 깨짐」, 「모서리 둘이 남음」) 알리고, 같은 묶음의 다른 상황을 풀면 그 이름을 준다. 거울(좌우·앞뒤·위아래)·거꾸로·y로 돌려 쥐기·큐브 돌리기 빼기는 엔진 수에 공간 변환 행렬을 걸어 만든다(좌우 거울은 Ua↔Ub, Ja↔Jb 등 자료의 쌍으로 시험). 훈련·배우기 힌트는 쓰는 공식을 보여 주되 채점은 그대로 결과 모양이다. 공식 하나는 `?case=&alg=` 링크로, 묶음 전체는 줄 목록 글로 복사한다.
- **십자 훈련(2026-11-04, `/cube/train/cross`, `apps/web/src/cube/cross/`)**: 섞기 → 살펴보기(남은 초, 큐브 돌리기 x·y·z만) → 첫 면 돌리기로 시간·수 세기 → 고른 색 가운데 어느 색이든 십자가 되면 끝.
  - **최적 풀이**(`solver.ts`): 십자 색 모서리 넷의 "그 색 스티커 자리"(24곳)만 보는 상태(190,080가지)를 24^4칸 표(색마다 324KB, 너비 우선으로 약 22ms)에 둔다. 반 바퀴 한 수(HTM), 최대 8수. 같은 길이 해를 여러 개 찾아 손이 편한 것(뒤·아래 면이 적은 것)부터 낸다. 가운데 색 기준으로 읽어 큐브를 돌려 쥐어도 맞다.
  - **어려움**(`scramble.ts`, 워커 `cross` 일): 「무작위」는 대회 섞기 그대로. 수를 고르면 대회 섞기 방식(무작위 상태 → 해법기의 거꾸로)이되, 무작위 상태를 뽑을 때 한 색의 십자를 그 거리 상태로 놓고 나머지를 무작위로 둔 뒤, 고른 색들의 가장 짧은 십자가 그 수인 것만 쓴다. 모든 색 8수는 거의 없어 고를 수 없다. 여러 색이면 결과에 색마다 최적 수와 가장 짧은 색을 보인다.
  - **수 세기·판정**(`session.ts`, `Clock`): 같은 면을 잇달아 돌리면 합친다(U U = 한 수, 되돌리기도 합친다). 가운데 층은 두 수. 제한을 넘는 순간 실패. 살펴보기는 혼자 맞추기 규칙을 고른 시간 L에 맞춰 L초 넘겨 시작 +2, L+2초 DNF. 「계획 후 가리고」는 첫 면 돌리기부터 모두 까맣게 가리고(`all-hidden`), 십자가 되면 바로 성공, 「끝」(Space)에 십자가 없으면 실패. 「아래에서」는 섞은 뒤 첫 색을 아래로 쥐고(흰색이면 z2) 최적 해도 그 방향으로 적는다. 「십자만 보기」는 고른 색들의 `cross` 마스크를 합쳐 쓴다.
  - **결과**: 내 수·최적 수·제한·시간·살펴본 시간, 최적 해 두 개(수 칩 + 키캡, 「시연」은 `DemoCube`). 「같은 섞기 다시」(Esc), 「다음 판」(Enter)은 치는 동안 미리 만들어 둔 판을 바로 꺼낸다.
  - **기록**: 이 기기 `cube.cross.v1`(모든 조건 합쳐 300개, 조건 열쇠를 붙임, 모양이 틀린 줄은 읽을 때 버림). 조건별 성공률·평균 (내 수 − 최적 수)·평균 살펴보기 시간·최근 목록을 읽을 때 낸다. 고른 조건은 `cube.cross.conditions.v1`.
  - 남은 것: X십자(십자 + F2L 짝 하나) 최적 계산.
- **내 공식 일람표·후보·버릇 훈련·상황 알림(2026-11-04, 사용자 요청 「상황에 따라 내가 버릇을 들이고자 하는 공식을 훈련」)**:
  - 「내 공식」을 배우기와 따로 서는 **「내 공식 일람표」**(`/cube/algs`)로 다듬었다. 묶음별 카드에 상황 그림·쓰는 공식(수 칩과 사용자 키캡)·버릇 상태·「배우기와 다름」(쓰는 공식 ≠ 대표 공식)을 보이고, 「전체·안 정함·버릇 들이는 중·익숙함」으로 걸러 본다. 설명 글은 늘리지 않고 이름·꼬리표만 둔다.
  - **추천 후보**(`algs/candidates*.ts`): 상황마다 자료(대표·대안) 밖의 널리 쓰는 공식. 꼬리표는 코드로 센다(「짧음」 = 대표·대안·후보 중 HTM 최소, 「R·U만」「M·U만」「R·U·F만」「큐브 돌림」). F2L은 엔진으로 그 상황을 R·U(없으면 R·U·F)만으로 가장 짧게 맞추는 수를 찾아 「찾은 공식」으로 넣었다. 출처가 기억뿐인 공식도 `candidates.test.ts`가 모든 후보를 `checkAlg`로 확인하고(앞 윗면 돌리기까지 적어 시연이 바로 맞게), 실패한 것은 넣지 않았다. 2단계 OLL 꼭짓점은 같은 번호 OLL 후보를 함께 쓴다. 상황을 열면 후보마다 시연·「쓰기」(내 공식에 넣지 않고도 쓰는 공식이 됨)·「내 공식에 넣기」.
  - **버릇 상태**는 `cube.algs.v1`의 칸 `habit`(`learning`·`known`, 없으면 안 정함)이라 내보내기·가져오기로 함께 옮겨진다. 옛 저장값은 그대로 읽힌다. 연습 자취(내 공식 연속 성공·최근 시간·마지막 연습)는 이 기기 `cube.habit.v1`(`algs/habit.ts`, 겉모양 검사).
  - 공식 훈련에 **「내 목록」**(`/cube/train?pick=mine`): 버릇 들이는 중·익숙함 상황만 묶음과 상관없이 낸다. 비중 = 들이는 중 1·익숙함 0.25 × 1/(1+연속) × 오래될수록(하루마다 +1, 최대 3배), 안 해 본 상황은 3배. 맞추면 **친 수를 쓰는 공식과 견준다**(`algs/same-alg.ts`): 앞뒤 윗면 돌리기, 큐브 전체 돌리기(돌리기를 빼고 옮겨 적은 뒤 24방향으로 쥐어 견줌), R2·R2'·나눠 친 같은 층·같은 축 차례는 봐준다. 넓게 돌리기와 「바깥 층 + 돌리기」처럼 다른 수로 같은 일을 하면 다른 공식이다. 다른 공식이면 결과가 맞아도 「다른 공식으로 풀었어요」로 알리고 연속을 끊는다. 내 공식으로 5번 잇달아, 그 평균이 묶음 기준(PLL 6초·OLL·F2L 5초 등, 키보드 기준이라 넉넉히) 안이면 「익숙함으로 옮기기」를 제안한다(자동으로 옮기지 않는다).
  - **상황 알림**(설정 「혼자 맞추기 상황 알림(내 목록)」, 기본 꺼짐): 혼자 맞추기 3×3에서 F2L이 끝나고 큐브가 내 목록의 윗면 상황(OLL·PLL·2단계)에 이르면 큐브 그림 구석에 상황 이름과 쓰는 공식을 작게 보인다. 판정(`algs/spot.ts`)은 흰 면이 아래인 네 방향마다 그 상황의 대표 공식을 해 보고 검사기의 역할 목표가 되는지 본다(검사기 `solvesFrom`). 켰을 때만 수마다 판정하고, 기록에 그 판에서 만난 내 목록 상황(`SolveRecord.myCases`)을 남긴다.

- **학습 흐름 보충(2026-11-04, 처음 접하는 사람 기준 검토)**: 과정 마지막 단원 끝에 「다음에 할 것」(다음 과정·공식 훈련·혼자 맞추기·타이머)을 보인다. 다음 과정은 과정의 `requires`(먼저 배울 과정, 목록에 보이기만 하고 잠그지 않음, `learn/index.ts` 한 표)의 거꾸로다. 단원 `drill`은 끝에 「이 공식 훈련하기」(`/cube/train?set=`)로 잇는다. 3×3 초보자·2×2 둘·CFOP·4×4 축소법 끝에는 섞인 큐브를 처음부터 맞추는 마무리 단원(`learn/finale.ts`, 단원 자료는 고치지 않고 과정 정의에서 붙임)을 둔다. 단계 `sheet`는 단계 아래 표(블라인드 글자마다 준비 수). 내용: CFOP는 아래 십자 세 경우, F2L 진짜·가짜 짝 문제와 빼내기, 2단계 OLL 10·PLL 6을 하나씩 해 보기(F2L의 「붙은 짝 R U R'」 설명이 엔진 모양과 반대였던 것을 고침). 4×4는 조각 단원 뒤 표기(2R·Rw·Uw) → 막대 합치기→노랑→둘레 순서→마지막 두 면, 모서리는 한 쌍씩, 꼭짓점 둘만 바뀐 패리티. 5×5 모서리 단원 목표는 열 줄(`edges-ten`). 블라인드는 작은 섞기로 글자 줄 외우기 연습, 꼭짓점 글자 규칙(왼쪽 위 칸부터), 제자리에서 뒤집힌 모서리. 새 단계의 글과 고르기 답은 `learn/flow-advanced.test.ts`가(초보자 쪽은 8-5절, `flow-beginner.test.ts`) 엔진으로 확인한다.

| 첫 층 꼭짓점(`333-first-corners-up`) | `R' D' R D` | 흰 면 위. 꼭짓점을 넣을 칸 밑(앞-오른쪽 아래)으로 D, 칸을 앞-오른쪽으로 y. 흰색이 오른쪽 1번·아래 3번·앞 5번, 제 칸에서 돌아감은 오른쪽 2번·앞 4번. 위 칸에 박힌 것은 한 번으로 뺀다. 끝에 뒤집기(z2) 둘러보기 |
| 노란 십자(`333-ll-cross`) | `F R U R' U' F'` | 가로줄은 가로, ㄱ자는 노란 두 칸이 뒤·왼쪽. 점 → ㄱ자 → 가로줄 → 십자, 최대 세 번(점은 어느 방향에서 해도 ㄱ자). 사이에 U 하나 없이 ㄱ자(뒤·왼쪽) → 가로줄(가로)로 이어진다 |
| 옆면 맞추기(`333-ll-edges`) | `R U R' U R U2 R' U` | 끝의 U까지 한 묶음이면 뒤·오른쪽을 두고 앞·왼쪽을 바꾼다. U를 돌리면 늘 둘 이상 맞는 자리가 있고, 이웃한 둘(ㄱ자)이면 y로 뒤·오른쪽에 쥐고 한 번, 마주 보면(일자) 아무 쪽에서 한 번 → 이웃 둘이 생김 → 한 번. 많아야 두 번 |
| 꼭짓점 자리(`333-ll-corner-place`) | `U R U' L' U R' U' L` | 제자리(방향은 상관없이 세 색이 그 구석 세 가운데와 같음) 하나를 앞-오른쪽 위에 두고 1~2번. 나머지 셋은 위에서 볼 때 시계 반대로 돈다(거꾸로 `L' U R U' L U R' U'`는 시계 방향, 거울 `U' L' U R U' L U R'`는 앞-왼쪽 위를 둔다). 위 모서리가 맞은 뒤의 제자리 꼭짓점은 0·1·4개뿐이고, 0개면 아무 쪽에서 한 번 하면 꼭 하나가 생긴다 |
| 꼭짓점 방향(`333-ll-corner-twist`) | `R' D' R D`(첫 층과 같음) | 풀 꼭짓점을 앞-오른쪽 위에 두고 노랑이 오른쪽 2번·앞 4번. 다음 꼭짓점은 U만 돌려 가져온다. 중간에 아래 두 층이 흐트러지고 다 끝나면 돌아온다. 끝에 U로 옆색 맞추기 |

- 다른 방식은 고르기 문제 하나에만 얹는다: 꼭짓점 방향을 먼저 맞추면 자리는 방향을 지키는 A퍼뮤(`R' F R' B2 R F' R' B2 R2`)로 맞춘다(엔진: 방향·모서리를 지키고 앞-왼쪽 위를 둔 채 셋만 바꿈. `U R U' L' U R' U' L`은 방향을 바꾼다). 한국어 가이드처럼 큐브를 뒤집어 오른손 트위스트(`R U R' U'`)를 되풀이하는 방식도 한 줄로 알린다.
- 새 목표: `yellow-edges`(노란 십자 + 위 모서리 옆색, 윗면 돌리기 하나는 봐줌), `ll-corners-placed`(+ 위 꼭짓점 제자리, 방향은 안 봄), `2x2-corners-placed`. 새 섞기 규칙: `white-cross-up`(흰 면 위), `ll-cross-solved`, `ll-edges-solved`, `ll-corners-placed`·`2x2-corners-placed`(꼭짓점마다 `R' D' R D` 0·2·4번, 합이 6의 배수).
- 진도: 내용을 새로 짠 단원은 새 id로 두고 `progress.ts`의 `LESSON_RENAMES`가 옛 id의 「끝냄」만 같은 차례의 새 단원으로 옮긴다(해 보기 번호는 단계 차례가 달라 버린다). 「마지막으로 연 단원」도 옮긴다.
- 2×2 초보자 첫 층도 흰 면 위 `R' D' R D`로 바꿨다(`firstLayerUpSteps`, 끝에 뒤집기). 윗면·윗층 자리는 2×2 과정 그대로 수네·A퍼뮤.
- 컴퓨터(`solveBeginner3`)는 바꾸지 않았다(옛 순서: 노란 면 → 위 꼭짓점 자리 → 위 모서리 자리). 첫 화면 연출의 초보자 해법은 2026-11-04에 이 표의 순서로 맞췄다(0절, `{ taught: true }`).

#### 3×3을 아는 사람의 2×2(2026-11-04, `learn/lessons-222-from333.ts`, 과정 `222-from333`)

- 「2×2는 3×3의 꼭짓점이에요」 → 첫 층 → 꼭짓점 자리 → 꼭짓점 방향(2026-11-04 3×3 마지막 층 순서를 바꾸며 함께 바꿈). 뒤의 셋은 3×3 초보자의 「첫 층 꼭짓점」「꼭짓점 자리」「꼭짓점 방향」과 같은 이름·공식(`CORNER_TWIST`·`CORNER_CYCLE`을 `lessons-333.ts`에서 가져온다)이고 단원 첫머리에 「3×3에서 했던 ○○ 단계와 같아요」를 적는다. 판정은 2×2 목표(`2x2-first-layer`·`2x2-corners-placed`·`solved`).
- 2×2는 위 모서리가 없어 꼭짓점 자리에서 U를 돌려도 된다. 그래서 U를 돌려 제자리가 꼭 하나인 자리를 찾는다(둘인 자리는 건너뜀). 대각 바꿈(Y퍼뮤 상황)은 어느 U에서도 하나가 아니라(2·0·2·0), 0인 자리에서 한 번 쓰면 하나인 자리가 생긴다(`from333.test.ts`가 첫 층만 맞은 상황 24개로 확인).
- 첫 단원은 단계의 `beside`(곁 그림)로 꼭짓점만 보이는 3×3(가리기 `corners`)을 2×2와 함께 보여 주고, 「2×2에서도 그대로 쓰는 3×3 공식」(꼭짓점만 바꾸거나 모서리가 흐트러져도 되는 것)을 고르게 한다. 다른 점: 가운데가 없어 기준 꼭짓점 하나에 다른 꼭짓점을 맞추고(제자리는 아래층 꼭짓점끼리의 관계), 모서리 단계가 없다.
- 2×2만의 함정: 층이 어긋나 보이면 U·D 하나로 맞음(해 보기 `z2 D` → `D'`), 대각 바꿈은 위와 같이 한 번 더 쓴다.
- `Course.recommendAfter`: 3×3 초보자 과정 단원을 모두 끝냈고 이 과정이 남았으면 배우기 목록에서 「추천」으로 눈에 띄게 한다. 시험: `from333.test.ts`(3×3 공식이 2×2와 3×3의 꼭짓점을 똑같이 옮김), 해 보기는 기존 자료 시험.

#### 다른 해법(2026-11-04, 사용자 요청 「3×3·4×4 해법 중 유명한 다른 해법들도 학습 내용으로」)

배우기 목록은 크기별(3×3 → 2×2 → 4×4 → 5×5)로 나눠 보인다. 새 레슨 글은 해요체이고, 다른 과정처럼 글만 읽는 단계 없이 조각 찾기·고르기 문제·둘러보기·따라 하기로 설명한다(루 첫 블록은 블록 조각 찾기, ZZ 모서리 방향은 「좋은 모서리일까요?」 문제, 야우 가운데는 둘러보며 노랑 가운데 찾기). 그림을 보고 고르는 문제의 답은 `judge-methods.test.ts`가 엔진으로 센다.

| 해법 | 파일 | 단원 | 판정(`judge-methods.ts`) |
|---|---|---|---|
| 3×3 루(Roux, 질 루) | `learn/lessons-roux.ts` | 한눈에 → 첫 블록 → 둘째 블록(R·r·M·U) → CMLL(2단계: 윗면 7 + 자리 2, 전체 42개는 소개만) → LSE(EO → UL·UR → 가운데 줄 4c) | `roux-fb`·`roux-sb`·`cmll`·`lse-eo`·`lse-ulur` |
| 3×3 ZZ(즈비그녜프 즈보로프스키) | `learn/lessons-zz.ts` | 한눈에 → 모서리 방향(EO) → EO라인 → 블록(ZZF2L, R·U·L) → 마지막 층(꼭짓점 7 + PLL, COLL·ZBLL은 소개만) | `eo`·`eoline`·`zz-left`, 그 뒤는 기존 `f2l`·`oll`·`ll` |
| 3×3 페트루스(라르스 페트루스, 소개) | `learn/lessons-zz.ts` | 2×2×2 → 2×2×3 → 모서리 방향 | `petrus-222`·`petrus-223`·`eo` |
| 4×4 야우(로버트 야우) | `learn/lessons-yau.ts` | 흰·노랑 가운데 → 흰 십자 셋 → 옆 가운데 넷 → 모서리 묶기(3-2-3) → 3×3처럼 + 패리티 | `yau-ud-centers`·`yau-cross3`·`yau-centers`·`yau-cross`, 그 뒤는 `edges-paired`·`solved` |

- **판정은 지금 들고 있는 방향의 자리로 본다.** 루 블록 = 왼쪽(오른쪽) 면에 닿고 윗면에 닿지 않는 자리(옆 가운데 포함), 색은 큐브 전체 방향 24가지 중 하나라도 맞으면 된다(루는 M을 돌려 가운데가 움직이므로). CMLL 뒤 단계는 윗면 돌리기 하나를 봐준다. LSE의 EO는 「위·아래 가운데가 흰·노랑이고 모서리 여섯의 흰·노랑 칸이 위나 아래」. ZZ의 EO만 가운데 색 기준이고 앞·뒤 축(F·B를 4분의 1 돌릴 때만 바뀜, Kociemba 모서리 방향과 같은 정의)이다. 그래서 L·Uw처럼 블록·십자를 통째로 돌리는 수는 그 목표를 깨지 않는다.
- **시연·해 보기의 수는 풀이 함수가 실제로 푼 것**이다: 루·ZZ는 `@game/cube-ai`의 `solveRoux`·`solveZZ`가 대회 섞기(3×3 씨앗 21은 시연, 7은 해 보기)를 푼 단계별 수를 옮겨 적었다. 시험(`judge-methods.test.ts`)이 시연 뒤에 다음 해 보기의 목표가 되는지, 풀이 함수의 단계 경계마다 판정이 맞는지(두 쪽을 서로) 확인한다. 해 보기는 기존처럼 `judge.test.ts`가 「상황에서는 아직 목표가 아니고, 모범 답을 두면 목표」를 엔진으로 본다.
- **야우 공식**: 모서리 묶기 `Uw' R U R' F R' F' R Uw`(흰 면 아래에서 흰 십자·가운데를 지키고 모서리 두 줄만 바꿈), 옆 가운데 `2U R2 2U' R2`(흰·노랑 가운데와 흰 십자를 지킴). 둘 다 엔진 판정으로 확인했다. 패리티는 축소법 공식(`algs-big.ts`)을 그대로 쓴다.
- **컴퓨터(`@game/cube-ai`)**: `solveRoux`(첫 블록은 y 돌려 쥐기 넷 × 사각형 둘 중 가장 짧은 것, 둘째 블록은 R·r·M·U, CMLL 2단계, LSE는 M·U 탐색), `solveZZ`(EO라인은 돌려 쥐기 넷 중 가장 짧은 것, 블록은 R·U·L, 윗면 7 + PLL). 단계 이름 `fb`·`sb`·`cmll`·`lse-eo`·`lse-ulur`·`lse-ep`·`eoline`·`zz-left`·`zz-right`와 `STAGE_LABELS`. 가운데 층까지 다루는 조각 탐색은 `piece-search.ts`. 첫 화면 연출(`hero/methods.ts`)에도 3×3 「루」(`3-roux`)·「ZZ」(`3-zz`)로 나온다. 4×4 야우 풀이 함수(`solveYau`)는 아직 없어(가운데·모서리 묶기를 야우 차례로 하는 탐색이 필요) 첫 화면에도 없다.
- 공식 표기 기준: WCA 표기(Rw = 바깥 두 층, 2R = 둘째 층 하나, M은 L과 같은 쪽). 해법 이름과 단계 이름은 speedsolving.com 위키의 「Roux method」「ZZ method」「Petrus method」「Yau method」 쪽을 따랐다.

### 8-3. 핑거 트릭(실물)

- 공식을 수마다 손가락 표기(예: `R`=오른 손목, `U`=오른 검지 밀기, `U'`=왼 검지, `F`=오른 검지(R' 뒤), `F'`=왼 검지 등)와 함께 보여 주고, 가상 큐브가 그 속도로 시연.
- 연습: 정해 둔 반복 횟수를 실물로 돌리며 스페이스바로 한 번씩 표시 → 반복마다 시간·초당 수 그래프. 박자(메트로놈 소리) 켜기.
- 묶음: 기본 손목 돌리기, U·U′ 손가락 밀기, 섹시 무브(`R U R' U'`), 슬레지(`R' F R F'`), 자주 쓰는 PLL(T·U·J 등).

### 8-4. 조각 단원(2026-11-04)

공식은 모두 「어떤 조각을 어디로 옮기는가」라서, 공식보다 먼저 조각을 익힌다. 공식은 하나도 외우지 않고 모든 단계가 상호작용이다.

- **3×3 「큐브의 조각」(`333-pieces`, 초보자 과정 맨 앞)**: 가운데·모서리·꼭짓점 찾기(흰 가운데, 흰-초록 모서리, 흰-초록-빨강 꼭짓점, 노란 모서리 넷) → 개수·색 수 고르기(모서리 12·색 둘, 모두 26) → R U F'을 돌려 보고 흰 가운데가 위 그대로인지 → 맞은편 색 → 조각 따라가기(한 조각만 보이게 가리고 돌린 뒤, 가운데만 보이게 가린 큐브에서 그 조각 찾기: R, R U2, F R) → 모서리는 모서리 자리로만 → 제자리는 가운데 색이 정함(흰-빨강 고르기, 초록-주황·노랑-파랑-빨강 자리 누르기) → 뒤집힌 모서리·돌아간 꼭짓점(방향 2·3) → 한 조각만 보이게 가리고 제자리·바른 방향으로(꼭짓점 `U2 R'`, 모서리 `R' F'`) → 「앞으로 배울 공식은 모두 어떤 조각을 어디로 옮기는가」.
- 자료에 더한 것: 목표 `piece:UFR`·`piece:UF`(그 조각 하나가 가운데 색 기준 제자리·바른 방향, 큐브를 통째로 돌려도 같은 조각을 색으로 찾는다), 가리기 `centers`·`piece:UFR`·`piece:UF`, 찾기 `find.at`(조각이 아니라 자리: 그 면들에 닿은 자리, 틀리면 「그 자리는 ○·○ 가운데 사이」). 따라가기 정답과 고르기 답은 `pieces.test.ts`가 엔진과 시험용 시뮬레이터 두 쪽으로 확인한다.
- **2×2 「2×2의 조각」**: 꼭짓점 8개뿐, 가운데가 없어 기준 꼭짓점과 이웃 꼭짓점의 색 관계로 맞춘다. **4×4 「4×4의 조각」**: 가운데 칸이 넷이고 움직임(2R로 확인) → 가운데부터, 모서리는 날개 짝(2R로 떨어진 짝 둘 찾기). **5×5 「5×5의 조각」**: 한가운데 칸은 고정, 둘레는 움직임, 모서리는 세 칸 한 줄.
- 처음 안내(`/cube/intro`) 맨 앞 「조각」: 가운데·모서리·꼭짓점을 하나씩 눌러 찾고 「색이 아니라 조각을 옮겨요」. 끝의 「배우기 첫 단원」 링크는 3×3 초보자 과정의 첫 단원을 따라간다.
- 기존 흰 십자·첫 층 꼭짓점 단원의 첫 설명은 「앞에서 본 것처럼」으로 조각 단원에 이어 말한다.

#### 8-4 다시(2026-11-04, 사용자 「좀 더 자유롭게 상호작용할 수 있게」): 하이라이트·세기·놀이판·분해 조립

- **하이라이트**: 찾기 단계에서 누른 칸이 든 조각 전체(스티커 모두)를 3D와 펼친 그림에서 함께 밝힌다. 맞으면 초록, 틀리면 빨강으로 잠깐(가린 칸이면 색 이름은 말하지 않음). 3D 장면은 스티커 둘레 고리(`Sticker.mark`, 선택 기능)를 그리고 고리는 조각을 따라 돈다. 표시는 마스크처럼 스티커 정체마다(`StickerMarks`).
- **세기**: `count`가 둘 이상이면 누를 때마다 골랐다는 하늘색 표시(가린 큐브면 색이 드러남)와 「3 / 6」. 다시 누르면 풀리고, 틀린 조각은 세지 않는다(`pickPiece`). 3×3 「큐브와 만나기」의 까만 큐브 가운데 여섯 세기, 2×2 꼭짓점 여덟, 4×4 초록 가운데 넷, 5×5 모서리 셋, CFOP 흰 모서리 넷. 뒤쪽은 둘러보기(끌기)나 펼친 그림으로 고른다.
- **놀이판**(`play`): 보고 싶은 조각만 색을 넣고(가운데를 기준으로 더할 수 있음) 나머지는 까맣게 가린 큐브를 사용자 키 배치 전체·휴대폰 밀기·단추 줄로 마음대로 돌린다. 통과는 가볍게: 층 돌리기 N번 또는 그 조각이 자리를 N번 옮김(큐브 전체 돌리기는 세지 않음, `playCount`). 「다른 조각 보기」(가운데·모서리·꼭짓점 단추, 또는 큐브의 칸을 눌러 그 조각을 따라감), 「모두 보기」(나머지 색도 보이고 따라가는 조각에 노란 테), 「처음으로」. 3×3: 가운데 고정(가운데 층 M·E·S는 가운데를 함께 옮기지만 서로의 차례는 그대로), 꼭짓점 따라가기, 모서리 따라가기, 색은 함께 다닌다(모서리 + 꼭짓점). 2×2: 꼭짓점 따라가기. 4×4: 초록 가운데 넷(바깥 면이면 함께 돌고 안쪽 층이면 흩어짐). 5×5: 흰 면 가운데 아홉(한가운데 칸만 늘 제자리). 「R을 돌렸어요. 어디 있나요?」 찾기는 놀이판 뒤 확인 문제 하나만 남겼다.
- **스티커 vs 조각**(`parts`): 「스티커로 보기」(몸통 없이 54칸만 떠 있음) / 「조각으로 보기」(26조각이 살짝 벌어짐). 칸을 누르면 붙은 조각 전체가 함께 들린다.
- **분해·조립**(`build`, `learn/build.ts`): 맞춘 큐브를 가상으로 분해해 축만 남기고, 축 → 가운데 6(흰 위·초록 앞을 먼저 잡고 넷을 고름) → 모서리 12(둘을 고르고 나머지) → 꼭짓점 8(하나를 고르고 나머지) 차례로 빈자리를 눌러 끼운다. 지금 끼울 종류의 빈자리는 작은 자리 표시(하늘색 테)로 보인다. 가운데 규칙: 맞은편 짝(흰-노, 초-파, 빨-주)과 도는 차례. 빨강·주황을 바꿔 끼우면 「여기 끼우면 맞출 수 없는 큐브가 돼요」와 흰-초록-빨강 꼭짓점의 돌림 차례가 거꾸로라는 설명, 큐브의 수학 링크. 끝: 뒤집거나 돌려 끼우면 못 맞춘다(12번에 1번), 「흩었다 모으기」, 둘러보기. 「이것은 구조 보기예요. 실물 큐브의 분해·조립은 제품 설명서대로 하세요.」 3D 장면에 조각 놓임(`setLayout`: 벌리기·날아오기·몸통 숨기기)과 축(`setCore`)을 선택 기능으로 더했다.
- **평가 「다음 중 한 면을 맞춘 상태는?」**: 그림 둘(`quiz.pictures`). (가) 흰 면은 다 흰색이지만 윗층 조각의 자리가 모두 틀림(`FACE_ONLY`), (나) 흰 조각 여덟이 제자리(`LAYER_DONE`, 첫 층 다 맞음). 답은 (나), 「면이 아니라 조각이 제자리에 와야 해요」. 두 상태는 `pieces.test.ts`가 엔진으로 확인한다.
- 판정은 모두 순수 함수(`learn/interact.ts`의 `pickPiece`·`marksForSlots`·`focusPieces`·`focusMask`·`playCount`·`playPassed`, `learn/build.ts`)이고 단위 시험이 본다.

### 8-5. 처음 맞추는 사람의 흐름 보충(2026-11-04)

학습 흐름 검토(처음 큐브를 잡은 사람이 차례로 따라가 본 것)에서 나온 구멍을 메웠다. 원칙은 그대로: 색이 아니라 조각을 옮기고, 모든 단계는 상호작용, 해요체. 시연·고르기 답·자리는 `learn/flow-beginner.test.ts`가 엔진으로 확인한다(해 보기는 기존 `judge.test.ts`).

- **처음 안내**: 시간 규칙(살펴보기·+2·DNF·5번 평균)은 빼서 타이머 화면 「시간 규칙」 접기 칸으로 옮겼다. 표기는 「면을 돌리면 조각 아홉 개가 통째로 돈다」로 조각 단계에 잇고, 글자·'·2만 두고 R 한 수를 직접 쳐 본다(x·y·z와 큰 큐브 표기는 배우기에서). 차례: 조각 → 표기 → 키 → 배우러 가기.
- **3×3 표기**: 큐브 돌려 쥐기 y를 해 본다(빨강을 앞으로) + 「U와 y의 차이」 고르기. 초보자 과정에서 쓰지 않는 Rw·M 설명은 뺐다.
- **흰 십자**: 다섯 경우를 차례로 하나씩(시연 + 힌트 있는 해 보기) 다룬 뒤 무작위로 간다. ① 아래층 흰색 아래(D로 맞추고 반 바퀴) ② 가운데 줄(옆색이 붙은 면을 돌려 올림, 옆색이 다르면 「U로 비켜 놓고 → 올리고 → U로 되돌리기」로 이미 넣은 모서리를 지킴) ③ 아래층 흰색 옆(한 번 돌려 가운데 줄로) ④ 윗층 제자리 뒤집힘(한 번 돌려 가운데 줄로) ⑤ 윗층 흰색 위·엉뚱한 자리(반 바퀴로 아래로). 「어느 경우?」 고르기와 흰 꽃 실수를 무작위 해 보기 앞에 둔다. 경우별 풀이는 `lessons-333.ts`의 `CROSS_*`.
- **첫 층 꼭짓점**: 뒤집는 까닭(맞춘 층은 아래, 공식은 윗층만 흐트러뜨림)과 「뒤집은 뒤 오른쪽은 주황」 고르기. 두 옆색으로 넣을 칸 고르기(찾기 `at`, 두 번) → U'로 칸 위로 옮기기 → 횟수. 제 칸에서 돌아감(흰색 오른쪽 두 번·앞 네 번), 아래층 엉뚱한 칸에 박힌 꼭짓점 꺼내기(`STUCK_CORNER`: y'로 돌려 들고 R U R' U' 한 번 → y → 제 칸에 넣기, 시연 + 해 보기).
- **둘째 층**: ⊥(뒤집힌 T) 모양을 「앞면 가운데 세로줄 + 아래 줄」로 풀어 쓴다. 넣으면 안 되는 노란 모서리를 해 보기 앞에, 다른 칸 모서리가 박힌 해 보기(`RIGHT U' y' RIGHT y`)를 더했다. 공식이 무엇을 옮기는지 한 줄씩.
- (2026-11-04 뒤) 첫 층 꼭짓점과 마지막 층은 8-2 「3×3 초보자 마지막 층」으로 다시 짰다. 아래 두 줄은 그 전 모습이다.
- **노란 십자·노란 면·마지막 층**: 점·ㄱ자·가로줄 정의, 노란 모서리 1·3개면 앞 단계가 틀린 것, ㄱ자 쥐는 방향 고르기. 노란 면 0개·2개의 쥐는 법을 U·U' 한 수로 해 본다. 헤드라이트(같은 색 두 칸)·퍼뮤(자리 바꾸기 공식) 낱말 정의, 「A퍼뮤가 그대로 두는 꼭짓점(앞-왼쪽)」「U퍼뮤가 그대로 두는 모서리(뒤)」 고르기. 마지막 윗면 돌리기 한 수는 끝으로 옮겼다. 과정 끝 「다음에 할 것」은 공통 장치가 맡는다.
- **2×2**: 「2×2 살펴보기」 첫 찾기(조각 단원과 겹침)를 맞은편 색·둘레 색 차례 고르기 둘로 바꾸고, R 한 수 대신 「R로 함께 도는 꼭짓점 넷」 찾기. 첫 층은 「기준 꼭짓점 아무거나 고르기」 → 뒤집은 뒤 기준 옆에 올 꼭짓점 찾기 → 박힌 꼭짓점 해 보기(3×3과 같은 `STUCK_CORNER`, 「3×3을 아는 사람의 2×2」에도). 오르테가는 PBL을 풀어 쓰고 둘째 단계(윗면 노랗게, 목표 `2x2-both-faces`) 해 보기를 더했다.
- **조각 찾기에서 찾은 조각 드러내기**: 가린 큐브(예: 가운데만 보임)에서 조각을 찾으면 `revealFound`(순수 함수)가 그 조각의 스티커를 「보임」으로 바꾼 마스크를 만들어 3D와 펼친 그림 모두 색을 보인다.
- 핑거 트릭 Jb퍼뮤에 「이웃 꼭짓점 둘·모서리 둘을 바꾸는 PLL」 한 줄, 키 익히기 큐브 돌리기에 「U와 y의 차이」 한 줄.

### 8-6. 단계 지도(2026-11-04, 사용자 요청 「전체 몇 단계로 맞추게 되는지 흐름을 쭉 보여 주고 진행」, 「프리드리히도 마찬가지, 나머지 해법들도」)

- 자료는 `learn/stage-map.ts`의 `STAGE_SPECS` 한 표: 과정 id → 단계(이름·가르치는 단원·끝난 모습 목표), 지도 시연(섞기 + 단계마다 나눈 수), 더할 고르기 문제. `withStages`가 과정에 `stages`·`stageDemo`를 달고 첫 단계 단원 바로 앞(준비 단원 뒤)에 지도 단원 `<과정>-map`(「전체 흐름」)을 끼운다. 마무리 단원보다 먼저 붙인다.
- 지도 단원: 단계 시연(띠 칸마다 그 단계가 끝난 모습의 펼친 그림, 칸을 누르거나 「다음 단계」로 그 단계만 시연, 지금 칸이 밝아짐) → 「○ 다음에 할 단계는?」(자동) → 과정 고르기. 시연이 없는 과정은 띠와 고르기만. 글만 있는 단계는 없다.
- 단원 머리 띠(`StageHeader`): 「준비」·「전체 7단계」·「7단계 중 3단계」·「마무리」와 단계 칸(끝낸 단계는 ✓, 칸을 누르면 그 단계 첫 단원). 배우기 목록의 과정 카드에 「7단계」 꼬리표.
- 시연 수: 풀이 함수와 순서가 같은 과정은 그 함수가 대회 섞기(3×3 씨앗 21, 4×4·5×5 씨앗 3)를 푼 수를 단계 꼬리표로 묶어 옮겨 적었다. 초보자 과정(3×3·2×2 둘)은 컴퓨터 해법과 순서가 달라 단원 공식으로 짰고, 섞기는 그 거꾸로(풀이 속 큐브 돌리기를 앞에 두어 기본 방향으로 시작). `stage-map.test.ts`가 단계 끝마다 그 목표가 되고 시작 전에는 아닌지 본다.

| 과정 | 단계 | 시연 수(꼬리표 묶음) |
|---|---|---|
| 3×3 초보자 | 흰 십자 → 첫 층 꼭짓점 → 둘째 층 모서리 → 노란 십자 → 옆면 맞추기 → 꼭짓점 자리 → 꼭짓점 방향 | 단원 공식 |
| 2×2 초보자 | 첫 층 → 윗면 → 윗층 자리 | 단원 공식 |
| 3×3을 아는 사람의 2×2 | 첫 층 → 꼭짓점 자리 → 꼭짓점 방향 | 단원 공식 |
| CFOP | 십자 → F2L(짝 넷) → OLL → PLL | `solveCfop`: cross · f2l-1~4 · oll · pll |
| 루 | 첫 블록 → 둘째 블록 → CMLL → LSE | `solveRoux`: fb · sb · cmll · lse-eo·lse-ulur·lse-ep |
| ZZ | EO라인 → 블록(F2L) → 마지막 층 | `solveZZ`: eoline · zz-left·zz-right · oll·pll |
| 4×4 축소법 | 가운데 → 모서리 짝 → 3×3처럼(패리티) | `solveHuman(beginner, 4)`: centers-* · edges·last-edges · 나머지 |
| 5×5 축소법 | 가운데 → 모서리 셋 묶기 → 3×3처럼 | `solveHuman(beginner, 5)`: 같은 묶음 |
| 4×4 야우 | 흰·노랑 가운데 → 흰 십자 셋 → 옆 가운데 → 모서리 묶기 → 3×3처럼 | 없음(풀이 함수 없음) |
| 블라인드 | 외우기 → 모서리 → 꼭짓점 | 없음 |

- 페트루스는 소개 단원 하나라 지도를 달지 않았다. 오르테가는 2×2 초보자 과정 안의 단원이라 따로 지도가 없다.

## 9. 여럿이 하기

### 9-1. 판 모양

- 방장이 종목(크기)·판 수·살펴보기(15초/없음)를 정하고 2~8명이 들어온다. 빈자리는 컴퓨터로 채울 수 있다.
- **방식**: ① 한 판 대결(빠른 순 순위) ② 5판 평균(대회처럼 5판, 가장 좋은·나쁜 것 빼고 평균) ③ 먼저 N판 이기기(2명).
- 판마다: 모두 약속 후 공개로 섞기 씨앗 → 같은 섞기 → 살펴보기 → 풀림 → 각자 맞춤 → 모두 끝나거나 제한 시간(기본 3×3 3분) → 결과(시간, 수, 초당 수, 판정 하한 표시). 한 판 끝에 모두의 풀이를 나란히 다시 보기.
- 진행 표시: 진행 막대(맞은 조각 비율)와 단계 이름(3×3: 십자·F2L·OLL·PLL 자동 인식), 지금 순위. 2~3명이면 작은 큐브 켜기.
- 채팅·이모지 반응(기존 채팅).

### 9-2. 공정성(docs/46 3절)

- 섞기: 모두의 약속 후 공개(공개 안 하면 그 판 기권).
- 시간: 각자 기기 + 다른 사람이 잰 도착 하한(고정 여유 `cap` 200ms), n명이면 하한의 가운데 값.
- 맞춤 확인: 흘려보낸 수를 모두가 다시 적용.
- 의심 표시: 초당 수 순간 최대, 수 수가 너무 적음. 결과는 바꾸지 않는다.
- 대결 틀(`net/race`)은 게임을 모른다. 큐브는 "씨앗 → 시작 상태", "수 적용", "끝났나"만 넘긴다. 나중에 블록 대결 같은 각자 판 게임이 같은 틀을 쓴다.

## 10. 컴퓨터

docs/46 6절. 수 순서는 해법기, 속도는 단계별 초당 수와 멈춤(씨앗으로 결정적). 3×3: 입문(층별)·중수(층별+짧은 공식)·고수(CFOP)·초고수(2단계 해법). 2×2: 같은 방식 + 최적 해. 4×4·5×5: 축소법(나중 단계). 컴퓨터 세기 확인은 CI에서(로컬 bench 금지).

- C5 만든 것(`packages/cube-ai`): `solveHuman(level, size, state)` → 수(WCA 표기)와 단계 경계, `botPlan(level, size, state, seed, { inspectionMs })` → 수마다 둘 시각. 3×3·2×2만. 사람 흉내 해법은 흰 면을 아래로 쥐고(첫 수 `z2`) 시작하고, 입문·중수는 큐브 돌리기(y)를 섞어 쓴다.
- 남은 일: 4×4·5×5 컴퓨터(축소법), 컴퓨터와 대결 화면(apps/web), 고수 F2L에 y 돌리기·여러 해 중 손이 편한 것 고르기, 2×2 고수를 진짜 오르테가(PBL)로.
