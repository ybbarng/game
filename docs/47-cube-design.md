# 47. 큐브 맞추기 설계 (2026-11-03)

docs/46(인프라 적합성 검토)을 바탕으로, 사용자가 정한 범위(2026-11-03)를 한 게임으로 묶는 설계다. 구현은 이 문서의 단계(12절) 순서로 작은 PR을 이어 올린다.

## 0. 사용자가 정한 것(2026-11-03)

- 진행한다. docs/46 갈림길 K1~K8은 **추천대로**(같은 섞기 경주, 진행 막대+순위, 고정 여유 cap, 기기 표시, 3×3·2×2 먼저, 이름 「큐브 맞추기」, three.js, 실시간 판정 장치보다 먼저).
- **색 배치**: 대회 표준 색(위 흰색·앞 초록·오른쪽 빨강, 맞은편은 노랑·파랑·주황). 설정에서 바꿀 수 있게.
- **배우기**: 초보자 해법을 처음부터 끝까지 순서대로 따라 할 수 있게. 고급 해법(프리드리히, CFOP)도 소개하고 훈련. 훈련 때 필요한 부분 말고는 **까맣게 가리기 / 보통 큐브** 중에 고를 수 있게. 2×2·4×4·5×5도 마찬가지.
- **핑거 트릭**: 실물 큐브를 들고 하는 훈련으로 따로.
- **타이머 모드**: 실물 큐브 시간 재기. 섞는 공식은 대회 규칙에 맞게 만들고, 15초 살펴보기 시간.
- **블라인드**: 보고 외운 뒤 안 보고 맞추기.
- **여럿이 하기**를 알맞게 구성.
- **조작은 키보드만**(마우스와는 상대가 안 된다). 회전 종류가 크기마다 크게 달라지는 것을 넓힐 수 있게. 양손 키보드 대 한 손 마우스는 적당한 안을 제시(4절). **모든 조작을 설정에서 바꿀 수 있게.**
- **그래픽은 실물에 가깝게**, 회전은 부드럽게.
- 나중: 표면에 그림을 넣어 가운데 방향까지 맞추기(그림 큐브), 아주 나중: 큐브가 아닌 퍼즐(스퀘어-1, 피라밍크스 등).
- 분리할 수 있는 것은 서브에이전트로 나눠 만들고, game에 잘 인계한다.

### 2-1. 퍼즐 공통 계약(`puzzle-core`)

큐브가 아닌 퍼즐까지 받으려고, **"스티커 자리의 순열 + 스티커 방향"** 을 공통 상태로 둔다.

```ts
interface PuzzleDef<Move> {
  id: string;                     // "cube3", "cube4", 나중에 "pyraminx", "sq1"
  stickerCount: number;
  faces: FaceDef[];               // 면 이름·기본 색 자리
  solved(): PuzzleState;
  parse(text: string): Move[];    // 표기 → 수
  format(moves: Move[]): string;
  apply(state: PuzzleState, move: Move): PuzzleState;   // 둘 수 없는 수(스퀘어-1 모양)면 오류
  canApply?(state: PuzzleState, move: Move): boolean;
  isSolved(state: PuzzleState, opts?: { orientCenters?: boolean }): boolean;
  geometry: PuzzleGeometry;       // 그리기용: 조각 모양, 스티커 위치, 수마다 회전축·각도·움직이는 조각
}
interface PuzzleState { perm: Uint16Array; twist: Uint8Array }  // 자리 i에 있는 스티커 번호, 그 스티커의 돌아간 정도
```

- **수 = 순열 + 회전 정보.** 수마다 "어느 스티커가 어디로 가나"와 "어느 축으로 몇 도, 어떤 조각이 움직이나"를 함께 둔다. 엔진은 앞의 것만, 3D는 뒤의 것만 쓴다. 피라밍크스(꼭짓점 축 120°)·메가밍크스(72°)도 같은 모양이다.
- **스티커 방향(`twist`)** 을 처음부터 들고 다닌다. 보통 큐브에서는 판정에 안 쓰지만, 그림 큐브(가운데 방향까지 맞추기)에서 `orientCenters`로 쓴다. 나중에 상태 모양을 바꾸지 않아도 된다.
- 스퀘어-1처럼 모양이 바뀌어 둘 수 없는 수가 생기는 퍼즐은 `canApply`로 막는다.
- 표기는 퍼즐마다 다르므로 `parse`·`format`이 퍼즐 안에 있다.

### 2-2. n×n 큐브의 수 모델(`cube-engine`)

크기마다 회전 종류가 크게 달라지는 것을 **하나의 일반 수**로 표현하고, 표기는 그 위의 이름일 뿐으로 둔다.

```ts
interface CubeMove {
  axis: "x" | "y" | "z";          // 회전축
  from: number; to: number;       // 축을 따라 몇 번째 층부터 몇 번째 층까지(1부터 n까지)
  turns: 1 | 2 | 3;               // 시계 방향 90°의 몇 배
}
```

- `R` = x축 바깥 1층, `Rw`·`r` = 바깥 1~2층, `3Rw` = 1~3층, `2R` = 2층만, `3R` = 3층만, `M`(3×3) = 가운데 층, `x` = 1~n층 전체(큐브 돌리기), 큰 큐브 가운데 층(`M`은 홀수 크기의 정가운데, 짝수는 정의 없음).
- 표기 읽기는 WCA 표기(`R U2 F' Rw 3Rw2 x`)와 흔히 쓰는 소문자(`r u`)·가운데 층(`M E S`)을 받는다. 쓰기는 WCA 표기로.
- 새 회전(예: 6×6의 `3Rw`)이 필요해도 수 모델은 그대로고, 조작키 배치에 "동작"만 하나 더하면 된다(4절).

### 2-3. 무작위 상태·가리기·상황 만들기

- **무작위 상태**: 조각별(꼭짓점·모서리·가운데·큰 큐브의 날개 모서리·가운데 조각)로 섞고 맞출 수 있는 조건(홀짝, 방향 합)만 맞춘다. 해법기가 필요 없다.
- **일부만 섞기**: "F2L은 맞고 윗층만 무작위", "십자만 맞음" 같은 상황을 조각 묶음 단위로 만든다(맞아 있어야 할 조각은 고정, 나머지만 무작위). 훈련의 "보통 큐브" 모드가 이것을 쓴다.
- **가리기(마스크)**: 스티커마다 「보임 / 까맣게 / 회색」. 단계마다 정해 둔 마스크(십자만, F2L만, OLL은 윗면 색만, PLL은 윗층 옆면만 등)를 훈련의 "가리기" 모드가 쓴다. 블라인드는 모두 까맣게.
- **공식으로 상황 만들기**: 공식의 거꾸로를 맞춘 큐브에 적용 + 무작위 윗면 돌리기(AUF)로 OLL·PLL 상황을 만든다.

## 3. 대회 규칙 섞기(`cube-scramble`)

WCA 규정과 공식 섞기 프로그램(TNoodle) 방식을 따른다.

| 종목 | 방식 | 필요한 것 |
|---|---|---|
| 2×2 | 무작위 상태, 최적 해가 4수 미만이면 다시(4b3b). 섞기 글은 TNoodle처럼 U·R·F만으로 **딱 11수** | 2×2 최적 해(상태 367만, 표) |
| 3×3(블라인드 포함) | 무작위 상태 → 2단계 해법으로 푼 해의 거꾸로를 섞는 공식으로(21수 이하). 1수 이하로 풀리는 상태만 다시(4b3: 2수 이상 필요한 상태) | 3×3 2단계 해법(Kociemba류, 웹 워커) |
| 4×4 | 공식은 무작위 상태(3단계 해법). **1차는 무작위 수 40수**로 하고 화면에 "대회 공식과 다름"을 밝힌 뒤 나중에 바꾼다 | (나중) 4×4 해법 |
| 5×5 | 무작위 수 60수(4b3e, 대회 방식과 같음) | 이어지는 같은 축 묶음 안에서 같은 면·두께는 한 번만(TNoodle `isRedundant`를 줄여 옮김) |
| 6×6·7×7 | 무작위 수 80·100수 | 같음 |

- 섞기는 씨앗에서 결정적으로 나온다(온라인 경주·컴퓨터·복기에서 같은 섞기를 다시 만든다).
- 블라인드 3×3(4b3a): 섞기 뒤 무작위 방향 돌리기를 붙인다. 첫 수 {없음, Rw, Rw2, Rw', Fw, Fw'} × 둘째 수 {없음, Uw, Uw2, Uw'}, 24가지 같은 확률. 섞기 마지막 수는 방향 돌리기 첫 수의 축과 같지 않게 해를 찾는다(TNoodle `firstAxisRestriction`).
- 2단계 해법은 표를 처음 만드는 시간이 든다. 웹 워커에서 만들고, 그동안 화면은 "섞기 준비 중"을 보인다. 크기·시간은 CI에서 잰다(로컬 성능 측정은 하지 않는다, 2026-11-03 사용자).

## 4. 조작: 키보드

### 4-1. 동작과 키를 나눈다

- **동작(action)** 은 "무엇을 하는가": `move(R)`, `move(R')`, `move(Rw)`, `move(2R)`, `rotate(x)`, `layer+1`, `undo`, `reset`, `inspectionSkip` 등. 크기마다 쓸 수 있는 동작 목록이 다르다(`M`은 홀수만, 깊이 고르기는 4×4 이상).
- **키 배치(keymap)** 는 "어느 키가 어느 동작인가". 배치는 이름 있는 묶음(「두 손」「표기」「사용자」)이고, 설정 화면에서 아무 동작이나 아무 키(Shift·Alt 조합 포함)로 바꾼다. 겹치는 키는 저장 전에 알린다. `event.code`(자판 위치) 기준이라 한글 입력 상태에서도 같은 자리로 동작한다.
- 저장은 기기 `localStorage`(내 설정), 내보내기·가져오기(JSON).

### 4-2. 양손 키보드 대 한 손 + 마우스 — 제안

| 안 | 장점 | 단점 |
|---|---|---|
| **A. 양손 키보드(큐브 돌리기 x·y·z도 키)** | 가장 빠르다. 손이 홈 줄을 떠나지 않는다. 시뮬레이션 큐브에서 오래 써 온 방식이라 옮겨 오는 사람이 많다. 온라인 경주에서 모두 같은 조건 | 처음엔 외울 것이 많다 |
| B. 왼손 키보드 + 오른손 마우스(끌어서 x·y·z) | 큐브를 "손으로 돌려 보는" 느낌, 외울 키가 적다 | 마우스로 90° 맞춰 돌리기는 키 한 번보다 느리고 손이 오간다. 오른손 담당 면(R 등)을 왼손으로 쳐야 해 공식 손맛이 실물과 달라진다. 경주에서 A보다 늘 느리다 |

**제안: A를 기본으로 하고, 배우기용으로 「표기 배치」를 함께 둔다. B는 "보기 돌리기"로만 연다.**

- **「두 손 배치」(기본, 빠르기)**: 실물 큐브에서 그 면을 돌리는 손이 같은 손으로 치도록 둔다. 오른손 = R·U(오른 검지)·F, 왼손 = L·U′(왼 검지)·D, 그리고 같은 면의 시계·반시계는 대칭 자리. 큐브 돌리기 x·y·z는 가운데 줄(T·Y·G·H 근처, 두 검지가 닿는 곳)과 ;·A 등 새끼손가락. 정확한 표는 구현 때 기존 웹 큐브 프로그램과 최대한 같은 자리로 맞춰 옮겨 오는 사람이 편하게 한다.
- **「표기 배치」(처음, 직관)**: R·L·U·D·F·B 키 = 그 면 시계, Shift = 반대, M·E·S, X·Y·Z = 큐브 돌리기, 숫자 2~7 = 다음 수의 층 깊이, Alt = 넓게(w). 튜토리얼 공식을 글자 그대로 친다.
- **마우스(선택)**: 끌면 **보기만** 돈다(카메라, 수로 세지 않음, 놓으면 제자리로 천천히 돌아옴). 큐브 돌리기(x·y·z)를 마우스로 하는 설정은 「사용자 배치」에서 켤 수 있게 열어 두되 기본은 끔. 경주에서 B를 고른 사람은 결과에 표시한다.
- **큰 큐브**: 「표기 배치」는 숫자로 깊이, 「두 손 배치」는 넓게 돌리기(`Rw` `Lw` `Uw` `Dw` `Fw` `Bw`)와 안쪽 한 층(`2R` 등)을 몇 키 더 둔다. 5×5 넘어가면 "층 고르기 키 + 면 키".
- 키 그림(지금 배치)을 큐브 아래에 늘 보이게(접기 가능). 키를 누르면 그 키가 잠깐 빛난다.
- 휴대폰은 1차로 **혼자 하기·배우기·타이머**만(밀어서 돌리기 + 표기 단추 줄). 온라인 경주는 키보드 기기만 들어오게 하고 나중에 다시 본다(사용자: 키보드만).

### 4-3. 빠른 입력과 부드러운 회전

- 키를 누른 순간 엔진 상태가 바뀐다(시간·판정 기준). 화면은 애니메이션 줄을 따라간다.
- 다음 키가 오면 지금 돌던 회전을 즉시 끝내고 다음으로. 줄이 길면 회전 시간을 줄인다(기본 한 수 90ms, 설정 0~200ms).
- 키 반복(autorepeat)은 무시한다.

### 4-4. 키 익히기·단축키 표(2026-11-04)

사용자 요청(「키가 익숙해질 수 있도록 조작 훈련이나 튜토리얼」, 「키보드 레이아웃에 단축키 표」)으로 `/cube/keys` 세 화면을 두었다(첫 화면 「키 익히기」, 처음 오셨나요·설정 키 배치·혼자 맞추기 아래에서 이어짐). **단축키 표**(`/cube/keys`)는 지금 배치를 실제 키보드 비례(숫자 줄·QWERTY 세 줄·스페이스·화살표)로 그려 키마다 그냥·Shift·Alt(·Alt+Shift) 층 동작을 적고, 면 돌리기는 큐브 표준 색(R 빨강·L 주황·U 흰·D 노랑·F 초록·B 파랑), 넓게·안쪽·가운데 층·큐브 돌리기·명령은 따로 색, 왼손·오른손 영역은 옅게 나눈다. 크기 2~7을 고르면 없는 동작은 흐리게, 인쇄는 흰 바탕, 휴대폰은 칸이 줄어 가로로 넘치지 않는다. 아래 동작 → 키 표는 `R'`·`Ri`·`Shift+I`·「되돌리기」로 찾는다. **키 익히기**(`/cube/keys/learn`)는 손 자리(F·J) → R·R'·U → L·L'·U' → F·D·B → x·y·z → M·Rw → 되돌리기·섞기·맞춘 상태로 → 섹시 무브·수네 8단계로, 칠 키가 그림에서 빛나고 3D 큐브가 친 대로 돌며 틀리면 친 키의 동작을 알린다. 문구의 키는 배치에서 읽어(「두 손」·「표기」·「사용자」 같은 단계) 배치에 없는 수는 건너뛰고 알린다. **조작 훈련**(`/cube/keys/drill`)은 수 보고 치기(30초 또는 30수, 단계 면만 → 반대 → 큐브 돌리기 → 넓게·가운데 → 4×4 이상 안쪽 층, 큐브 숨기기), 키 보고 맞히기(빛나는 키의 동작을 보기 넷에서), 공식 따라 치기(핑거 트릭 공식, 반복마다 초당 수). `R2`는 같은 층을 두 번, `2R`은 깊이 키 뒤 면 키로 친 것도 맞다. 키(동작)별 맞힘률·평균 반응 시간과 튜토리얼 진도를 이 기기에 남기고, 틀린 비율·느린 만큼 무게를 더해 약한 키를 더 자주 낸다. 로직은 `apps/web/src/cube/keys/`(화면 모름, 시계·난수 주입).

## 5. 그래픽

three.js(이미 의존성, 큐브 화면에서만 늦게 불러오기).

- **조각**: 모서리가 둥근 상자(검은 플라스틱, 약간 거친 반사). 스티커는 조금 들어간 둥근 사각형, 매끈한 광택(clearcoat). 「스티커 없는(stickerless)」 모양을 고를 수 있게.
- **빛**: 실내 반사맵(three.js가 코드로 만드는 방 환경, 파일 없음) + 부드러운 그림자 한 장(바닥 접촉 그림자). 과하면 휴대폰은 낮은 품질로.
- **회전**: 부드러운 가감속(끝에 아주 살짝 넘쳤다 돌아오기는 설정). 움직이는 동안만 그리고 멈추면 그리기를 멈춘다(배터리).
- **색**: 표준(흰·노랑·초록·파랑·빨강·주황), 설정에서 면마다 바꾸기와 색 묶음(높은 대비, 색약 친화). 가린 스티커는 검정(또는 회색).
- **그림 큐브(나중)**: 스티커에 그림 조각을 붙이고 `twist`로 방향을 그린다. 상태 모양은 이미 준비(2-1).
- **보기**: 기본은 앞·위·오른쪽이 보이는 각도. 뒤·아래 살짝 보기(키 하나로 잠깐), 펼친 그림(전개도) 작은 창.
- 그리기 품질 단계(높음/보통/낮음)를 설정에 둔다. 성능 숫자는 실기기·CI에서 잰다.

## 6. 타이머 모드(실물)

- 종목 고르기(2×2~7×7, 3×3 블라인드). 대회 규칙 섞는 공식 + 섞인 모습 펼친 그림.
- 시작: 스페이스바를 0.3초 넘게 누르고 있으면 준비(초록), 떼면 시작, 아무 키로 멈춤. 휴대폰은 화면 누르기로 같게.
- **살펴보기 15초**(WCA A3a1·A3b3·A3b4·A4d): 켜면 섞기 뒤 첫 누름으로 살펴보기 시작, 8초·12초 알림 소리, 딱 15.00초부터 +2, 딱 17.00초부터 DNF(A4d1+·A4d2+). 끌 수 있다. 블라인드는 살펴보기가 없다(B1a).
- 기록: 종목·세션별 목록, 5번 평균(가장 좋은·나쁜 것 빼고 셋 평균), 12번 평균(관례), 최고 기록, +2·DNF 고치기, 메모. 내 기록(`/profile`)에 묶는다. 이 기기 저장 + 내보내기.
- 버림·반올림(9f1·9f2): 한 번 기록은 원래 값을 1/100초로 버린 뒤 +2를 더하고, 10분 이상이면 초로 버린다. 평균은 그 기록으로 낸 뒤 1/100초(10분 이상은 초)로 반올림.
- 블라인드: 외우기 끝 표시(키 한 번)로 외우기·맞추기 시간 나눔. 3×3 블라인드는 5번 중 최고(9b3a)와 따로 인정하는 5번 평균(9b3b)을 보인다(4×4·5×5 블라인드는 3번 중 최고·세 번 평균, 9b6).

## 7. 블라인드(가상)

- 섞기 → 외우기(보이는 상태, 큐브 돌리기 x·y·z와 보기 돌리기만 허용, 면 돌리기 막음) → 「시작」 키 → 모든 스티커 까맣게, 맞추기 → 「끝」 → 공개. 맞았으면 시간, 아니면 DNF와 틀린 조각 표시.
- 배우기에 블라인드 해법(올드 포흐만: 모서리·꼭짓점 하나씩 바꾸기 공식, 글자 붙이기)을 단원으로 둔다(3단계 뒤).

## 8. 배우기와 훈련

### 8-1. 공통 틀

- **단원(lesson)**: 설명 글 → 시연(엔진이 공식을 천천히 돌림, 한 수씩 앞뒤) → 직접 해보기(정해진 상황에서 목표 모양을 만들면 통과). 목표는 "이 조각들이 맞아 있음"으로 확인(일부 칸만 보는 판정).
- **훈련(drill)**: 상황 묶음(예: PLL 21개)에서 무작위로 내고, 맞춘 시간·실수·쓴 공식 기록. 약한 것 다시 내기. 고른 상황만 연습.
- **가리기/보통**: 단원·훈련마다 마스크(2-3)를 정해 두고, 사용자가 「가리기」(필요한 스티커만 색, 나머지 검정)와 「보통 큐브」(나머지도 무작위로 섞인 실제 모양) 중 고른다.
- 공식은 여러 개를 허용하고 **결과 모양으로 채점**한다(사람마다 쓰는 공식이 다르다). 대표 공식과 대안을 보여 준다.
- 자료는 데이터 파일(`apps/web/src/cube/learn/*.ts`)로 둔다. 상황 이름, 마스크, 만드는 공식, 대표 공식, 손가락 표기.

### 8-2. 크기별 내용

| 크기 | 초보자(순서대로 전부) | 고급 훈련 |
|---|---|---|
| 3×3 | 표기 → 흰 십자 → 첫 층 꼭짓점 → 둘째 층 모서리 → 노란 십자 → 노란 면 → 위 꼭짓점 자리 → 위 모서리 자리 (층별 맞추기) | 프리드리히(CFOP): 십자(8수 안), F2L 41 상황, 2단계 OLL(10)·PLL(6) → OLL 57·PLL 21 |
| 2×2 | 첫 층 → 윗면(3×3 공식 재사용) → 윗층 자리 | 오르테가, CLL(나중) |
| 4×4 | 축소법: 가운데 맞추기 → 모서리 짝 → 3×3처럼 → 홀짝(OLL 패리티·PLL 패리티) | 요(Yau) 소개(나중) |
| 5×5 | 축소법: 가운데(가운데 줄 포함) → 모서리 셋 묶기 → 3×3처럼 → 마지막 두 모서리 | — |
| 블라인드 | 올드 포흐만 | — |

### 8-3. 핑거 트릭(실물)

- 공식을 수마다 손가락 표기(예: `R`=오른 손목, `U`=오른 검지 밀기, `U'`=왼 검지, `F`=오른 검지(R' 뒤), `F'`=왼 검지 등)와 함께 보여 주고, 가상 큐브가 그 속도로 시연.
- 연습: 정해 둔 반복 횟수를 실물로 돌리며 스페이스바로 한 번씩 표시 → 반복마다 시간·초당 수 그래프. 박자(메트로놈 소리) 켜기.
- 묶음: 기본 손목 돌리기, U·U′ 손가락 밀기, 섹시 무브(`R U R' U'`), 슬레지(`R' F R F'`), 자주 쓰는 PLL(T·U·J 등).

## 9. 여럿이 하기

### 9-1. 판 모양

- 방장이 종목(크기)·판 수·살펴보기(15초/없음)를 정하고 2~8명이 들어온다. 빈자리는 컴퓨터로 채울 수 있다.
- **방식**: ① 한 판 경주(빠른 순 순위) ② 5판 평균(대회처럼 5판, 가장 좋은·나쁜 것 빼고 평균) ③ 먼저 N판 이기기(2명).
- 판마다: 모두 약속 후 공개로 섞기 씨앗 → 같은 섞기 → 살펴보기 → 풀림 → 각자 맞춤 → 모두 끝나거나 제한 시간(기본 3×3 3분) → 결과(시간, 수, 초당 수, 판정 하한 표시). 한 판 끝에 모두의 풀이를 나란히 다시 보기.
- 진행 표시: 진행 막대(맞은 조각 비율)와 단계 이름(3×3: 십자·F2L·OLL·PLL 자동 인식), 지금 순위. 2~3명이면 작은 큐브 켜기.
- 채팅·이모지 반응(기존 채팅).

### 9-2. 공정성(docs/46 3절)

- 섞기: 모두의 약속 후 공개(공개 안 하면 그 판 기권).
- 시간: 각자 기기 + 다른 사람이 잰 도착 하한(고정 여유 `cap` 200ms), n명이면 하한의 가운데 값.
- 맞춤 확인: 흘려보낸 수를 모두가 다시 적용.
- 의심 표시: 초당 수 순간 최대, 수 수가 너무 적음. 결과는 바꾸지 않는다.
- 경주 틀(`net/race`)은 게임을 모른다. 큐브는 "씨앗 → 시작 상태", "수 적용", "끝났나"만 넘긴다. 나중에 블록 대결 같은 각자 판 게임이 같은 틀을 쓴다.
