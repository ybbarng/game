# 21. 새 게임 체크리스트 (2026-10-28)

새 게임을 넣을 때 이 목록을 **처음부터 끝까지** 따른다. 마이티·하트·오목을 만들며 쌓인 구성요소를 모은 것이다.
사용자가 정한 기본 요건은 넷이다. **PC·휴대폰 화면, 여러 단계 컴퓨터, 효과음, 온라인 대전**이다. 같은 날 **튜토리얼**도 더해졌다. 다섯 가운데 하나라도 빠지면 그 게임은 끝난 것이 아니다.

단계를 나눠 올려도 된다. 다만 올릴 때마다 아래 "게임별 상태" 표에 남은 칸을 적어, 실제 상태와 기록이 어긋나지 않게 한다.
새 구성요소가 생기면 이 문서에 더한다. 그 기능을 이미 있는 게임에도 넣는다(CLAUDE.md "작업 규칙").

- [ ] `docs/NN-<게임>.md`에 다음을 적는다.

  - 화면 배치
  - 컴퓨터 단계
  - 시간 규칙
  - 숨길 정보

- [ ] 데이터 계약을 정하기 전에 다섯 질문을 본다. 계약은 규칙 문자열, 기록 형식, 온라인 메시지다.
  - 뜻
  - 지킬 규칙
  - 찾아 쓰기
  - 바뀔 때 고칠 범위
  - 대안
- [ ] 숨길 정보가 있는지 본다. 남의 패나 섞은 더미가 있으면 멘탈 포커(`packages/fair-play`)를 쓴다. 판 게임처럼 숨길 것이 없으면 쓰지 않는다(docs/18 3-2).
- [ ] 처음에 정해 숨기는 값(숫자야구 비밀 수)은 **약속 후 공개**로 한다(docs/34 3절): 엔진에는 약속(SHA-256 + 소금)만, 답은 비밀 가진 기기가 자동으로 내고, 판 끝 공개에서 약속과 모든 답을 다시 계산한다. 컴퓨터는 사람이 정한 비밀을 모르니 `botCanAct`로 답하기를 막는다

  - 힌트(혼자 하기, 넣는 게임만)는 공통 `HintButton`·`useHint`(components)를 쓴다. 혼자 하기·미션 아님·내 차례일 때만 보이고 수가 오가면 지운다. 고수 수 고르기와 판 위 표시(출발 점선·도착 초록 고리 #059669)는 게임이 맡는다
- [ ] 온라인 화면
  - 판 게임은 공통 `BoardOnlineScreen`을 쓴다. 게임마다 다른 것(킷, 이름, 공유 제목, 세션, 저장소, 컴퓨터, 규칙 요약)만 `<게임>/online.ts`의 `BoardOnlineGame` 설정 객체로 넘긴다. 아래 항목은 이 화면이 모두 맡는다
  - 방장은 `HostRoom`, 참가자는 `GuestRoom`
  - 초대 링크(`?room=`)로 들어온다. 방장이 새로고침하면 `hostedRoom(<id>)`로 다시 연다
  - 끊긴 사람 대신 컴퓨터가 둔다(`standInDelayMs`)
  - 연결 끊김 띠와 `ChatBox`
  - 참가자는 판 끝 검증(audit)을 통과하면 `saveGuestArchive`로 기록을 받는다
- [ ] 방장·다른 참가자가 남의 행동을 꾸밀 수 없는지 공격 시험으로 확인한다(2026-11-04, 원카드 #67·은하 한 바퀴 #69·큐브 #56에서 모두 같은 구멍이 나왔다)
  - 판 끝 다시 계산이 건너뛰는 기록(시계·방장이 넣은 꼬리표 행동, `timing.strip`이 null, `hostAction`)마다 `GameKit.verifyUnsigned`로 「그 자리·그 차례·정해진 대신 두기와 같은가」를 본다. 꼬리표만 달면 아무 행동이나 넣을 수 있는 구멍을 막는다
  - 방장 발표(청구 판정 등)와 엔진 기록이 같은지 참가자가 맞춰 본다. 발표만 맞춰 보면 기록을 따로 꾸밀 수 있다
  - 그물 연결(손님끼리 직접 보냄)이면 방 상태·누가 어느 자리를 맡는지는 처음 방장 것으로 고정하고, 사람 자리 메시지는 그 사람 기기에서 온 것만 받는다
  - 시험은 「고치기 전에는 판 끝 검증이 통과하던 위조가, 고친 뒤 실패한다」로 남긴다: 남의 자리에 행동 지어 넣기, 발표와 다른 기록, 발표한 것 빼기

## 10. 시험과 확인

- [ ] 제한 시간이 있는 코드는 `Clock`을 받는다(기본 `realClock`). 시험은 `ManualClock`을 넣고 `advance`로 시간을 옮긴다. 시험에서 실제 시간을 기다려 결과를 얻지 않는다(CLAUDE.md "flaky 시험은 두지 않는다")
- [ ] 기다림은 조건으로 한다. 기록 저장처럼 비동기인 것도 "쓰였는지"를 확인한 뒤 넘어간다(예: `omok.spec`의 `finishedOmokGames`)
- [ ] 화면 시험 `e2e/<게임>.spec.ts`(여럿이면 `<게임>-<무엇>.spec.ts`). CI는 이 이름과 `src/<게임>/`·`src/app/<게임>/`·`packages/<게임>-*` 경로로 그 게임이 바뀌었을 때만 돌린다(`scripts/affected-e2e.mjs`, docs/38 16절). 화면으로만 확인할 수 있는 것만 본다(규칙·진행은 단위 시험이 본다). **빠르고 결정적으로**(CLAUDE.md 2026-10-30):
  - `import { expect, test } from "./test"`(이동·새로고침 뒤 화면 준비 끝을 기다린다). 움직임 줄이기는 설정 기본이고, 연출이 있는 길은 시험 하나만 켠다. 컴퓨터 대기는 `useTestSpeed(context)`(카드 게임은 `prepareFast`)로 줄인다. `expect.poll`은 `intervals: [50]`
  - 세 화면 크기(desktop, phone-portrait, phone-landscape): 배치가 크기마다 다른 것만. 목록에서 들어가 두다가 **판 끝 화면까지 가장 짧은 길**(기권, 작은 판·말 수, 정해진 시드)로 간다. 판 끝 화면이 정산처럼 자연스럽게 끝나야만 보이는 게임만 끝까지 둔다
  - 가로로 넘치지 않는다
  - 데스크톱 하나만: 새로고침 뒤 이어하기, 끝낸 판이 내 기록과 복기에 보인다, 온라인 두 탭(`?net=local`)으로 두다가 판을 끝내고(기권 가능) 판 끝 검증을 확인한다
  - 배우기: 단원을 끝내고, 미션은 실패한 뒤 다시 해서 성공한다

원카드는 2026-11-03에 PC·휴대폰 화면, 혼자 하기, 효과음을 올렸다. 2026-11-04에 튜토리얼 5단원(docs/42 15절)과 컴퓨터 세 단계(docs/42 13·14절)를 올렸다. 같은 날 친구와 하기(일반방·암호화방, docs/42 16절)를 올렸다. 같은 날 「원카드!」 외침을 반응 속도 겨루기(규칙 o2, docs/42 17절)로 바꿨다: 미리 외침을 없애고 한 장이 되면 겨루기 창 하나에서 각자 잰 반응 시간으로 가린다.

새 구성요소(2026-11-03, 원카드): 수가 오가도 그대로 흐르는 시간 창이 여럿이면 `GameKit.timers`, 대국 기기가 바로 넣는 행동(다시 섞기)은 `GameKit.autoAction`, 컴퓨터의 차례 밖 반응(외침·잡기)은 `KitBot.react`(울릴 때 그 순간 화면으로 다시 보려면 `recheck`). LocalMatch가 Clock으로 잰다.

새 구성요소(2026-11-04, 원카드 o2): 같은 판을 두고 반응 속도로 겨루는 게임은 `KitClaims.race`(공통 판정 2층, docs/43 7-2)를 채운다(본인 판별·하한·공정 창·보냄 지연). 청구에 `rtMs`를 싣고, 방장 발표의 `race.rt`와 순서를 참가자가 `net/claim-race.ts`의 같은 식으로 맞춰 본다. 혼자 하기에서 누름을 모으려면 엔진이 모으는 시계를 `GameKit.timers`로 내놓는다.

새 구성요소(2026-11-04, 원카드 온라인): 실시간 청구는 `GameKit.claims`(공정한 동시 판정 1층, docs/43 7-1) — 화면은 `room.claims.claim(body, {seen})`, 방장 발표는 엔진 행동으로 기록에 남아 판 끝 다시 계산이 판정까지 다시 한다. 방장 기기가 넣은 행동(창 시간 끝·다시 섞기·청구 묶음)은 `GameKit.hostAction`으로 판 끝 검증의 "내 행동"·"컴퓨터 수" 맞춰 보기에서 뺀다. 기억을 쓰는 컴퓨터는 `KitBot.observe`로 판 끝 검증 때 같은 사건을 듣는다. 판 도중 뽑기·다시 섞기가 있는 카드 게임의 멘탈 포커는 `GameKit.cardTable`에 `kind: "onecard"` 모양(fair-play `OnecardTableSpec`)으로 넣는다.
새 구성요소(2026-11-04, 은하 한 바퀴 배우기): 주사위 게임 미션은 굴림 눈을 장면에 적어 두고 `LocalMatch`의 `step`을 바꿔 그 눈으로 굴린다(`galaxy/practice.ts` `scriptedDiceStep`, 엔진 `stepWithDice`). 배우기 첫 화면의 단원 아래 칸(`TutorialHome` `extra`)에 아이콘(`icon`)을 줄 수 있다.

새 구성요소(2026-11-04, 은하 한 바퀴):
- `GameHome`의 `together`(친구와 하기)는 빼도 된다(혼자 하기만 먼저 올릴 때). 아래 `footer` 칸에는 출처 접는 칸 같은 것을 둔다.
- 엔진 자료가 크면 기본 하나만 묶고 나머지는 `loadSky`처럼 쓸 때 불러온다. 루트 layout이 부르는 설정 저장소는 엔진 값을 가져오지 않는 파일에 둔다(`galaxy/settings-store.ts`, 엔진 package.json `sideEffects: false`).
- `KitTimer.later(state)`: 시간 창이 끝난 순간의 상태로 넣을 자리·행동을 정한다(컴퓨터가 대신 정하기처럼). 온라인 방 결정 시계(은하 한 바퀴 `galaxy/online.ts`)가 쓴다. 대신 정한 행동은 꼬리표를 달고 `timing.strip`이 null을 돌려 판 끝 검증의 「내가 보낸 것」에서 뺀다.
- `GameKit.verifyUnsigned({before, seat, action, index, context})`: 사람이 보낸 것이 아닌 기록(`timing.strip`이 null)이 규칙대로인지 참가자 판 끝 다시 계산이 확인한다. 방장이 넣는 꼬리표 행동이 있는 게임은 반드시 채운다(꼬리표만 달면 내 행동·컴퓨터 수 대조를 건너뛰므로).
- `BoardOnlineScreen`: 참가자 기기가 받은 규칙 문자열을 읽지 못하면 방에 들어가지 않고 오류를 보인다.

공통 정리: 오목·장기·체스·바둑·숫자야구의 온라인 화면은 공통 `BoardOnlineScreen` 하나로 묶었다(2026-10-29). 화투 세 게임의 온라인 화면도 거의 같은 코드라, 멘탈 포커로 옮긴 뒤 같은 식으로 묶을 수 있다.
